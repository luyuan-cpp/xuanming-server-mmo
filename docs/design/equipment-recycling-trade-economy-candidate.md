# 回收、玩家变现与当面交易：首发经济系统候选及 UI 交接

更新：2026-11-17。状态：**可评估候选，不是新增规则已获确认，也不是真钱上线验收。**

本轮只做策划、源码核对及实现交接；不改正式表、协议、客户端或服务器业务代码，不启动支付、结算或提现。UI 由负责人另一台电脑制作，本文第十节可以单独复制过去，不需要对方读取仓库。没有向其他聊天或外部人员派发任务。

## 0. 先给推荐

**让普通玩家能自养、能卖旧物，让经营者靠归集、加工和承担库存风险赚钱；人民币成交由官方聚宝斋托管订单完成。**

推荐首发组合：

1. 核心材料仍是每日既有的 20 份自选额度；从中划小部分为可流通来源，候选为 **16 份绑定 + 4 份可流通**，不是额外再掉 4 份。比例待定，现代码还没有这种绑定分配。
2. 纯可流通材料造出的装备可以流通，穿戴本身不改变其性质；出售时先卸下。任何绑定投入使产物绑定。这样确实存在能出售的旧装备，同时不能将免费绑定投入洗成货。
3. 旧装备自己拆或卖给玩家收购者。拆解先产“旧器砂”，加工成“调灵符”，用于**自愿换词条、换流派**；首发不兑换回核心打造材料或百炼石，不返强化投入，也不设官方人民币回收价。符合条件的流通产物仍可卖给真实买家。
4. 游戏币收购复用现有材料市场与托管合同；唯一旧装备采用实例寄售或当面交易。人民币沿现有聚宝斋固定价订单，先少量标准材料和逐件核准的装备，不再做人民币实时盘口。
5. 保留当面交易，补“双方各自编辑 → 锁定 → 最终清单 → 双方确认相同版本 → 统一交割决定 → 可恢复交付”。人民币付款只进官方订单。
6. 工作室可正常收购、加工、囤货和转售；不提供专属掉落、保底利润或自动刷号特权。没有真实买家，就可能卖不出。

前两项的比例与绑定规则、第三项的配方及改配费用是**本稿新增候选**，不覆盖装备文档中已确认的强化、数值、技能和排位规则。原聚宝斋的宠物、游戏币和角色交易目标继续保留在既有路线中；本文只是建议降低第一个开放切片的品类数量。

## 2. 回收玩法：先有真实用途，再有经营空间

### 2.1 旧物从哪里来

首发来源是玩家真实持有的过渡装、换流派留下的旧装、重复打造或买入后不需要的装备，以及允许加工的余料。**不为了供货额外增加无限掉落旧装备的刷怪点。**

新手赠送、任务、活动和 GM 发放需要保留来源限制；不能把“系统免费发的可重复装备 → 拆解 → 出售”做成新号套利。原有资产缺少新来源标记时，按明确转换名单核对，不一律放成可流通，也不批量销毁；本轮不执行转换。

| 对象 | 首发建议 | 处理选择 |
|---|---|---|
| 白名单内 V1 基础旧装 | 自己拆；纯流通品可卖或转售 | 好属性先提示查看实例，不将稀有好装默认批选 |
| 两类核心材料 | 支持流通批次的收购/出售 | 绑定批次自用；不把核心材料“回收”成系统保底金币 |
| 旧器砂、调灵符 | 第二个小切片开放标准化加工与买卖 | 砂不直接恢复核心材料；符仅用于可选改配 |
| 首饰、法宝、镶嵌宝石、旧版装备 | 先允许已验收的原件转售，拆解按独立白名单逐项开放 | 未定义返还规则前拒绝拆解；有宝石先摘除，摘除能力没做好就不可拆 |
| 宠物、角色、任务物 | 不进入这个回收切片 | 依旧由原玩法及聚宝斋路线维护，不借“回收”处理 |
| 已穿戴、手动保护、战斗预留、交易锁定资产 | 不可直接拆解、托管或出售 | 显示具体原因，先完成解除保护的正式步骤 |

“手动保护”是防误操作；“绑定”是流通限制；“交易占用”是并发控制。三者不能共用一个布尔锁。

### 2.2 推荐的小配方组

以下名称与数字都是**演示候选，不是已写正式表**：

| 操作 | 消耗 | 产出/作用 |
|---|---|---|
| 拆一件白名单 V1 基础装 | 完整销毁该实例 | 4 份旧器砂；核心打造材料、百炼石、已装词条与强化投入均不返还 |
| 加工 | 5 份旧器砂 + 20 游戏币 | 1 张调灵符；确定产出，无成功率赌博 |
| 可选改配 | 1 张调灵符 + 一件符合条件的装备 | 将指定一条改为合法的另一个固定词条；保留其余合法属性及强化，不提高词条槽数和战力上限 |

基础装本体当前要 20 打造材料；首发不因词条和强化更高就增加砂产量。不同单位的“20 材料”和“4 砂”不是固定兑换价值，砂只能按上述用途消费。

装备文档中“5 打造材料换一条”仍是未确认建议。本稿提出用调灵符代替的候选；**两条费用路线不能未经决定同时上线**。若保留旧建议，应重新衡量谁会买符、有没有重复支付；不得把无用途产物上架后假装有需求。新手免费调整若采用，作为独立一次性权限，不产生可卖符，不可拆成可交易补贴。

玩家不需要职业执照才能加工；收购者优势来自愿意找货、归集、持有库存、研究实际需求和提供便捷成品。不给指定工作室隐藏配方或额外收益系数。

### 2.3 完整例子：五名普通玩家 → 收购加工者 → 换流派玩家

这是**有真实买卖意愿时的算例**，价格不是系统报价。游戏币阶段假设这些成交适用 5% 卖方税并向上取整；摆摊已有该默认规则，其他入口必须明确接入相同规则后才能使用此数字，不能把它当当前所有合同自动扣税。

1. 五名普通玩家各有一件不用的纯流通旧基础装。收购者乙愿意每件出 100 游戏币；每位卖家税后得到 95，共 475。玩家也可以自己拆和加工，无人被强制卖给乙。
2. 乙实际支付 500，取得五件原件；拆为 20 份流通旧器砂。
3. 乙消耗 20 砂与 80 游戏币，加工出 4 张流通调灵符。
4. 换流派的玩家丙愿意以每张 180 买 4 张，支付 720，用于自己选择的四次改配。税 36，乙收到 684。
5. 乙差价为 684−500−80=**104 游戏币**，尚未计工时与滞销。若只能以每张 120 卖出，税后 456，差价就是 **−124**。没有丙下单时，符只是乙的库存。

此链金币来源是丙原先持有的金币：475 给原卖家、104 留给乙、80 加工费与 61 两端成交税被销毁，合计 720。系统没有给商人铸币。五件装备离开后只留下四次可选改配机会，没有返出 100 核心材料让玩家重造五件。

人民币可以发生在同一类真实买卖中，但必须分别走官方订单。例如乙在官方订单各以 ¥1.00 买入五件旧装，总支出 ¥5.00；再将四张符作为一个同质批次标 ¥8.00。真实买家付款并交付后，乙净收益账为 ¥7.60，人民币购销差 ¥2.60，另有 80 游戏币、时间、库存及可能的税费成本，**这些成本不能擅自按固定汇率折成人民币利润**。此变体只有白名单、同质批次交付及实际支付/出款条件全部具备时才可开放；48 小时公示使其也不是即时套利。

### 2.4 长期需求的实际上限

养满后仍可能有新玩家买过渡装、老玩家自愿换流派或准备副套，以及偏好便捷成品的玩家买调灵符。以后若真的做外观、染色、收藏，可以另立用途并验证需求；**尚未实现的外观不算本轮成交来源**。

固定词条、固定上限的装备迟早会饱和。新玩家少、大家配置稳定时，旧装与符的成交量会下降。接受加工商减少、库存降价和利润变薄；不以强制装备损坏、赛季清空强化、持续抬战力上限或强制每日改配维持工作室收入。

## 3. 资源、游戏币、人民币分别闭环

### 3.1 物品与首套预算

| 账 | 进入 | 消耗/退出 | 不允许的回流 |
|---|---|---|---|
| 核心打造材料、百炼石 | 既有每日 20 自选额度；其他来源逐项登记 | V1 本体、首次词条、强化，仍按两类各 300 | 砂/符兑换回核心材料；同一奖励多入口领取 |
| 装备 | 真实材料打造或已登记发放 | 持有、转让或拆毁；转让只是换所有者 | 凭模板补造第二件原件、同一实例拆两次 |
| 旧器砂 | 符合条件的旧件销毁 | 5 砂/符 | 拆解结果未知时换键重复发砂 |
| 调灵符 | 明确配方扣料及金币 | 一次合法可选改配 | 改配退回旧符、用免费改配权限铸可卖符 |

16+4 候选下，玩家将全部 20 自用时仍是 600/20=30 的材料预算；若每天净卖出 4 且不买回，则留存只有 16，600/16=37.5，约 **38 个有效游玩日**。交易是处理时间与现金/游戏币的选择，不能同时承诺“全部卖掉又照样 30 天满装”。30 分钟领取 20 份仍需实测。

目前每日额度按**玩家角色**存储在 material_reward 中，不是账号共享额度。把可流通份额放在这 20 内也只是角色限产，挡不住同账号多角色和多账号。首发必须统计账号关联的总流通产出；若要改为账号硬额度，需另做持久配额与发放幂等协调，不能改前端计数冒充已完成。没有既有授权就不改其他角色的核心自养额度。

本稿砂和符不补首套材料，改配是首套之外的自愿消费；投入旧件的最初材料已计过产出，拆解不再给核心材料。若将来开放核心返料、继承返还、困难加料或额外装备掉落，必须改算：

**可用净资源 = 正常领取 + 额外掉落折算 + 净买入 + 核心返还 − 卖出 − 改配等额外消耗。**

额外旧装能拆成核心材料时，不论是直接给还是先经符兑换，都要计入额外产出。不能仍把 600/20 当实际完成天数；存量旧装也要单列一次性供给冲击。当前困难额外 5 份没有采用，本稿不自动加上。新百炼石与旧强化材料不自动互换。

### 3.2 游戏币

游戏币只采用当前允许的 kCurrencyGold，界面货币中文名跟随现有配置，不新增“商人币”。绑定货币不能代付流通订单。

游戏币来源是现有战斗/任务等经批准发放；本稿只新增可选加工费用候选。V1 当前打造、强化没有额外金币费，本稿不暗加首套金币门槛。交易款从买家转卖家、费用按冻结条款销毁；撤单只退未成交预留，不额外奖金币。

对买单、卖单、寄售、当面交换和赠送逐项确定收费政策。建议标准材料收购/出售统一明确费用，首发当面交换不额外收税、不用象征性税假装杜绝站外成交；不得因换入口就绕过物品限制。游戏币交易税不会进入运营银行账户，也不能单靠抽税消除材料库存过剩。

### 3.3 人民币与运营收入

买家付款来自真实购买意愿；运营方不按固定人民币价格无限回收材料，不承诺物品保值、人人赚钱或卖家收益。玩家出售游戏币若按既有聚宝斋路线开放，也由买家自愿报价，**不产生官方金币兑人民币汇率**。

示例，买家实付 1234 分，5% 手续费向上取整为 62 分，卖家净额 1172 分：

**买家实付 1234 = 平台手续费 62 + 卖家收入 1172。**

手续费是平台毛收入的一部分，GMV 是交易总额。月度演示：GMV ¥10,000，按 5% 得 ¥500；假设支付成本 ¥60、出款成本 ¥20、退款/拒付预期损失 ¥50、服务器 ¥120、客服 ¥100，则只余 **¥150 税前经营结余**。这些成本与费率均为可改算例，不是渠道报价，也未计个人全部工时；税务另按运营主体与地区确定。GMV 为零时，抽成收入为零，固定成本仍在。

商城直售核心材料会替代玩家供货，并影响价格预期。**推荐冷启动不同时推出无限量、低价的同款核心材料直售**；先以非战力外观等有实际产品的项目获得收入，相关商品也不能凭空记成已存在。若最终选商城卖材料提速，应给购买来源明确绑定规则，实测对玩家成交的替代，并重新计算成长；充值材料→自由卖出→收益提现的自买/套现路径必须评审。

替代路线可以是“商城限定量绑定材料 + 玩家流通材料”，但额度、定价、是否影响首套时长都仍待评估。旧 0.1 元试算不自动落地。运营不能既无限低价供应同货，又承诺收购者稳定差价。

## 4. 绑定、加工、返还与循环检查

### 4.1 候选采用两种来源，先保持简单

- B：角色绑定，只可本人使用和允许的自处理；不是不能拆。
- T：来源允许流通，仍须满足模板白名单、当前占用与交易条件；T 不是一定卖得掉。
- 穿戴不自动绑定纯 T 装备；卸下后可流通。这样原件才有真实旧装市场。
- 流通限制放在物品实例的数据层，不写入背包槽位；运行时锁定、好友标签与界面选中态不写进物品持久属性。

| 操作 | 限制继承 |
|---|---|
| T 原料单独打造/合成/加工 | 产物 T，仍受模板限制 |
| 任意 B 原料混入 | 本次产物 B，不按占比生成一部分 T |
| T 装备消耗 B 强化材料、B 词条材料或 B 调灵符 | 装备变 B；确认前明确提醒 |
| B 装备改用 T 材料 | 仍 B，不反向洗白 |
| 拆解 B / T 装备 | 砂继承原件 B / T；强化、词条限制同样已影响原件 |
| 合堆、拆堆 | 不同限制不能合堆；同批拆分保留限制与数量，不能只按模板汇总 |
| 分开加工 B 与 T | 必须明确拆成独立批次，各自扣料产出；不能用总量混扣后推测哪件 T |
| 退货/退款返还 | 还原同一托管原件及限制，不按当前规则重新铸造、解除绑定或换号 |
| 转移养成/继承（后续） | 目标采用两边更严限制；来源移走的养成清除，原件不能再次返同份投入 |

副作用前展示“用了这份绑定材料，装备会绑定”；服务端提交仍须原子重验。玩家可以留 T 材料给 T 装备，但不能要求客户端“优先扣绑定”后又承诺装备始终可卖。

### 4.2 首发与未来组合循环

| 组合 | 要证明的结果 |
|---|---|
| 打造 → 拆 → 加工 | 20 核心材料造一基础装，拆仅 4 砂；5 砂再付金币才有一符，符不还核心材料。不能无投入回到原装备 |
| 强化 → 拆 | 不返百炼石、不按强化提高出砂；强化不是可重复领返料的凭证 |
| 改配 → 拆 | 不返符或旧词条材料，也不因多次改配提高砂产出 |
| 继承 → 拆（后续） | 首发不开放继承；将来完整转移的强化不再返料，不能“目标保留强化 + 源件完整退石” |
| 重铸返还（后续） | 不给“消费符 → 旧词条退足材料 → 再铸符”的正循环；费用路线只能有一个权威定义 |
| 免费装备/免费改配 → 出售 | 免费来源限制向下继承；重复奖励、退回、补发不产生新的流通资格 |
| 交易 → 退回 → 再交易 | 只是原件所有权恢复，不算新掉落或新日额度，不触发成交补贴/奖励 |

首发不做“成交返活跃奖励”“亏损补贴”“回收积分兑奖金”，避免对敲产生系统补贴。任何新增配方必须列投入、直接/间接产出、返还和继承的组合；不能只检查单条配方净损耗。

## 5. 聚宝斋：下单、交付、收益、提现是一条可查链

| 阶段 | 资产/资金与玩家可见状态 |
|---|---|
| 上架预览 | 展示实际原件或同质数量、人民币分、冻结费率/预计净额/期限；预览不是托管完成 |
| 托管与登记 | scene 真正扣出并取得持久结局，trade 保管完整快照；商城登记原合同引用，不能凭用户声明生成货 |
| 公示与在售 | 默认公示 48 小时、随后寄售 7 天；公示可看不可买，价格由卖家决定 |
| 买家下单 | 商城同事务确定唯一买家、金额、占用及 OMS；同请求返回原单，同账号角色自买拒绝 |
| 付款 | 只认可信渠道证明，核订单、商户、币种、金额和唯一流水；买家截图和客户端“我付了”不算 |
| 交付 | trade 发原件；结果未知查原命令，背包满、离线等保持交付中；按真实 SQL 持久结局推进 |
| 卖家待结算 | 商城在可信 DELIVERED 回执事务中记毛额、费用、净额；不是上架就有收入 |
| 可提现 | 冷静期默认 3 天，另满足实际渠道、身份与未决争议条件；不凭客户端倒计时发钱 |
| 提现申请 | 同一商城收益账按账号预留具体收入，写原申请号及分配；并发不能花同一笔 |
| 出款结果 | 可信成功只结一次；确定失败原路释放；结果未知只查原出款，不能当失败解冻再申请 |
| 争议/人工 | 分别展示订单、原件、收入与出款的实际状态及理由；不把 MANUAL 伪装成已取消 |

未付撤单与付款争同一权威裁决；已付款卖家不能随意撤货。mock 到期关单不能代替真钱渠道查单/关单。到期、退款或取消未拿到确定结果，资产与资金继续有清楚的托管归属和待办。

只在未交付且可确定安全退回时自动补偿；货已到买家后，投诉、支付拒付和商品退回是不同事实。真实渠道若可能强制拒付，须先完成交付后追偿、再流通/消耗处理及损失承担规则；不能假设平台“禁止退款”就能挡住渠道动作，也不能让卖家先出货再自行讨款。冷静期不是自动追回的保证。

### 5.1 实际收款与结算条件

运营地区、主体、发行平台、支付渠道及个人卖家准入尚未核实，不因代码存在就假设可以替玩家收付款。上线前确认实名认证与年龄限制、未成年人保护、税务与订单凭证、适用的交易服务条件，以及支付机构是否接受本场景和卖家类型。可以先做 UI 与游戏内交易，不必等这些事项才画图。

2026-11-17 只核对官方公开资料所得：

- [微信支付平台收付通](https://pay.wechatpay.cn/doc/v3/partner/4012086891)描述的是平台与二级商户的支付、结算及佣金能力；[普通商户分账](https://pay.wechatpay.cn/doc/v3/merchant/4012067962)也有独立产品规则。**存在这些产品不证明本游戏或普通个人玩家获准接入**，需按实际场景核准，不能用普通收款接口冒充卖家结算方案。
- [Apple 审核指南 3.1.1、3.1.1(a)、3.1.3](https://developer.apple.com/app-store/review/guidelines/#payments)对数字商品付款及外链有平台、商店地区与授权条件；“两个玩家交易”不能自行当作实时个人服务豁免。不能为中国区 iOS 先画一个必然可用的站外支付按钮。

本稿不作合法性结论、不承诺指定渠道可开通；这些是正式接入需确认的条件。当前设计页可以展示完整官方订单和“真钱通道未开放”，不跳过玩家变现目标。

## 6. 工作室边界与普通玩家保障

### 6.1 按行为处理

| 可以参与 | 不允许 |
|---|---|
| 正常游玩、公开报价、真实收购、加工、承担库存和自主转售 | 脚本批量刷号/刷战果、利用漏洞复制、盗号搬货、伪造付款、洗资产、对敲操纵成交或刷奖励 |
| 家庭共网、网吧、长时间在线，经证据核实的正常交易 | 仅凭同 IP、上线时间长或“赚得多”就直接判作弊 |
| 对规则提出异议和申诉 | 指定经营者获得特殊掉落、优先撮合、保证价或免审核 |

普通玩家不必卖货或买货也能取得核心材料；PVE 是低人数时期的自养路径，20 份目标的用时与实际完成率单独验证。本稿不改排位数值、胜负奖励或引入付费专属战斗上限。副套和改配不应变成领取日常奖励的强制要求。

### 6.2 适合个人开发的分阶段措施

1. **先把资产账做准。** 小白名单、确定配方、原件追踪、持久防重、统一锁物和原单恢复；功能开关按品类关闭新单，已有单继续交付/退回。先不做需要全天团队维护的复杂竞价、多市场或大量可现金化随机物。
2. **做低成本观察。** 定期报产出、库存、销毁、真实成交、集中转移和长期未决单；实名与出款资格按渠道方案接入，不能把注册一个账号当真人唯一证明。
3. **积累关联证据再限制。** 结合战果重复/异常行为、跨号供货关系、循环转移、价量异常和共同控制证据复核；同账号自买直接拒绝，对不同账号关联不只看 IP。公开行为规则，精确判定阈值不写入玩家提示或此公开交接稿。
4. **有限人工处理。** 优先临时限制可疑资产的新交易/出款并保存证据，不能随意扣清全部资产。给案件号、受限范围、补证和申诉入口；错判按审计解限。紧急复制漏洞可暂停受影响品类的新单，并处理已收款未交付订单。

单角色额度、单账号额度和实名资格都不是防多账号的万能措施。16+4 仅控制每角色来源强度，工作室仍可能靠规模压价；需要用实际集中度与普通玩家体验判断是否调小流通份额或改账号配额，而非声称影响已被消除。

### 6.3 观察与调整

| 指标 | 含义及对应动作 |
|---|---|
| 分材料 B/T 产出、消耗、净库存与库存天数 | 库存持续增加先核来源和真实消费；削减未来多余来源或流通份额，不用凭空收税假装材料消失 |
| 活跃买家/卖家、实际成交量、未售率、成交等待 | 区分挂牌与成交；无人买时缩小品类、改善找货与批次，不发系统保底订单 |
| 分位成交价、价差、挂价偏离 | 防止把高价自挂当市场估值；小样本显示不足，不画虚假行情趋势 |
| 前列账号及关联群体的产出、库存、成交/净流入份额 | 观察集中度，不把大卖家自动定罪；结合关系图和资产来源复核对敲/搬货 |
| 新手、普通玩家完成首套的 p50/p90 有效日与每日用时 | 同时看“全自用”和“净卖出”群体，验证自给路线，不能拿商人买料速度代表免费普通玩家 |
| 退款、投诉、误点、版本变化、未知结果与人工积压年龄 | 判断防骗和恢复效果；有超时案件需责任人处理，不能永远挂处理中 |
| RMB 成交额、实收手续费、各成本、未结算/未出款负债 | 判断运营能否覆盖成本，不用充值流水替代利润 |

金额、账号关系仅在受控账务/风控分析中使用。Prometheus 只放低基数的品类、阶段、结果等标签，不加 player_id、订单号或账号号。调整只作用未来规则与新单，既有订单按冻结条款结算，并公告实际变更。

## 7. 当面交易：技术防骗与统一交割

### 7.1 对玩家的流程

~~~mermaid
stateDiagram-v2
    [*] --> 邀请
    邀请 --> 编辑: 对方接受
    编辑 --> 双方锁定: 分别锁定自己的报价与资产
    双方锁定 --> 最终核对: 完整快照已固定
    最终核对 --> 交割决定已提交: 双方确认同一修订和摘要
    交割决定已提交 --> 交付中
    交付中 --> 完成: 双方均已持久到账
    最终核对 --> 编辑: 修改使双方锁定和确认失效
    双方锁定 --> 编辑: 修改使双方锁定和确认失效
    编辑 --> 退回中: 取消或会话到期
    最终核对 --> 退回中: 交割提交前取消胜出
    退回中 --> 已取消: 占用释放或托管退回已确认
    交付中 --> 人工处理: 已部分到账或不能安全自动补偿
~~~

断线不是一个自动终态：从原交易号查询权威阶段。编辑期可按明确截止取消并退回；提交后由服务器继续交付，重连恢复原单。后端返回当前允许动作，客户端倒计时只展示。

### 7.2 最终页必须能看懂

- 固定对方公开角色编号、名字、头像和**系统查得的好友关系**。好友不等于官方担保；不能让对方备注伪装系统好友。公开编号沿现有身份来源确定，不擅自再编码一套身份。
- 两列固定为“**我付出 / 我得到**”，列完整数量与币种。最终页和凭证不使用“1.2 万”等缩写；1,000 与 10,000 需一眼区分。
- 原件显示唯一实例标识、模板、强化、完整关键属性及词条、数量、流通限制；同名装备不能只用相同图标与名字掩盖差异。
- 显示双方锁定/确认的条款修订。商品或金额任何修改都增加条款修订，撤销**双方**锁定和确认，保留可读差异：“100,000 → 10,000 游戏币”“原实例 +5 → 另一实例 +0”。
- 最终清单固定后不可悄悄刷新成新条款。数据失效返回编辑，不能沿用旧确认；单纯多弹一次确认不代替这些约束。

双方各编辑自己一侧，不能代对方提交新报价。报价修订与后台数据库 version 分开：后者可能因推进变化，不能拿它表达“玩家看过哪一份东西”。服务端生成规范清单及摘要，不信客户端自己算的条款。

### 7.3 后端必须兑现的语义

锁定必须是权威资产预留或实际托管；只在 UI 画锁不算。该实例/数量不能再交易、上架、拆解、打造消耗、邮寄、赠送或重复战斗预留；退回中也不能提前恢复可用。

修改已锁定报价时，旧版本占用与资产命令继续关联旧条款修订。首发优先采用简单策略：撤销双方锁/确认，先按旧版本释放预留或原样退回已托管资产，再允许新版本锁定；退回未确认时显示处理中，不让同一资产重新提交。旧版本迟到的持久回执只能推进原释放/退回，不能给新版本解锁或作为新版本成交资格。新报价必须取得自己对应的权威快照与托管结局。

同一条款的双方最终确认、双方托管持久结果满足后，trade 在同一合同行事务中记录**唯一交割决定及交付待办**。取消与最后确认争同一裁决；提交后不能接受普通撤单。原件归属和双方应收权益明确，即使一人离线也不会变成私下欠款。

两个玩家的存档分开提交，**不宣称一次 SQL 同时写两个人背包**。统一的是交割决定、托管与可恢复交付；双方真实持久到账后才显示完成。首发限制包形状，并对单次资产应用全包校验，避免正常请求部分到账。

临时失败继续原单，未知查原 seq；确定性拒绝时，只有证明尚未发出/应用对方所得的阶段才可原样退回。已部分到账不整单重发或双边全退，应保留原收据、剩余托管/应收、补齐任务、案件责任与告警。个人运营做不到处理的包类型先不开放。

同一交易号和原请求键支持重放。客户端发送前持久保存完整原意图，未知时不换键、不另开一单；查询暂时失败也不能变成“交易失败，点此重新支付”。gate 保序只解决同会话发送顺序，不代替合同并发裁决与跨会话防重。

## 8. 赠送、站外付款与投诉

一方零对价时明确进入“赠送”模式。赠送方最终页写“我付出：具体资产 / 我得到：无”，按钮写“确认赠送”；受赠方写“我付出：无 / 我得到：具体资产”，按钮写“确认接收”，双方仍确认同一条款修订。按价值、陌生关系及近期变更给更显著的核对，不能靠误导倒计时催确认。新赠送模式仍复用托管、修订、交割和凭证，不直接调用扣款发物绕过交易记录。

1 游戏币换高价物仍可能是站外人民币交易，不因对价非零就标“安全”。不得宣传“禁零价已杜绝绕费”。站外转账、对方给的二维码和截图、聊天中的借物/回赠承诺不在系统交换清单内；借物承诺也不自动创建可追回租约。

每笔完成、退回及人工交易有不可变凭证：原交易号、双方公开身份、清单、条款修订、费用、时间、交割与到账结果。举报从原单进入，附类型、描述和受控证据；系统保存可核对的版本变化及资产去向，敏感账号/支付信息不向对方公开。

投诉受理、资产追踪、证据复核、限制有争议资产、补齐或按规则追回分别记录，不因买家投诉自动退款，不先扣无关善意买家的资产。已消耗、继续流转或无足够证据的情况，能否追回需个案判断；不能承诺任何被骗物都能自动恢复。

技术可预防清单被偷换、金额缩写误导、双花、重复发货与伪造付款；玩家在准确清单外自愿相信“先送给我以后返还”，系统能提示、留证和处理举报，无法保证不会发生。负责人当年具体受骗方式未知，本稿不编造经历。

### 9.4 后续验收场景

1. **守恒与循环**：正常/边界数量、整数溢出、混合 B/T、拆堆合堆、加工绑定继承；打造拆解、改配拆解、未来继承返还组合均无复制和洗白；回收不增加核心额度。
2. **同一资产竞争**：拆解、加工、上架、当面、邮寄与战斗预留争同一实例/数量，至多一种占用成功；穿戴/保护变化在提交点复核。背包不足全包不应用，不留下半个本地配方。
3. **预览与防重**：预览后表/实例/配方变化拒绝；同键同参返回原结果、异参拒绝；回执淘汰后的旧键不重复执行；重启/换场景仍可恢复原操作。
4. **当面防骗**：同名不同实例、不同强化词条、完整大金额、0 与 1 游戏币；任意改动清除双方锁/确认，过期版本不能成交；确认与修改、撤单与最后确认并发只有一个裁决。
5. **故障恢复**：分别在第一方托管持久、第二方托管持久、交割决定提交、第一方交付、第二方交付后崩溃；超时、重连、换 gate/scene 与 owner 换代不双花、不双退、不丢失应收；原交易号恢复。
6. **失败与人工**：离线/背包满为在途；终局拒绝、部分到账、未知分别处理；有可查询原收据与剩余资产、处理责任和结案凭据，不停在无人负责半单。
7. **市场**：未完成托管不进盘口；部分成交与撤剩余竞争只退实际剩余；冻结税率、成交价量与到账一致，无人买时不伪造成交。
8. **人民币**：库存竞争、自买、回调重放、金额币种/商户不符、取消后迟到付款、下架与付款竞争；同一 DELIVERED 只记一份收入；未知付款不误放库存。
9. **提现**：冷静期/争议限制、并发分配、同申请重放、同键异参、确定失败解冻与未知出款不解冻；真实渠道成功须有可核的对应证明。
10. **UI 与运营**：手机横屏安全区、长名/大数/放大字、触摸误点、动态文字分层、读写失败、原请求恢复、案件补证/申诉；客户端真正交互与发布画面分别验收。

未来实际执行者按受影响模块运行构建、单测、真实 TiDB/跨玩家故障与 UI 验收；C++ MSBuild 串行 /m:1。没有本轮业务代码改动，**本轮不运行编译、游戏测试、压测、支付或提现**。

独立 Java 版：只读 PARITY 的 2026-10-21 后续条目已记录 kind6、mock OMS/退款/提现源码，不能沿用早期“完全没做”。后续若干人工处置、盘口与交付修正仍标待做。本轮未改该仓、未登记功能完成版本；新回收、限制继承与双边锁单在两版均为待实现，客户端可见契约后续同批对齐。

## 11. 仅保留三项关键待定

1. **可流通来源比例**：推荐每日既有 20 内 16B+4T；也可更保守地减少 T，或全部 T。全 T 交易最自由，也最容易被规模账号压价；全 B 则旧装经营来源明显不足，不符合长期流通目标。角色/账号额度区别必须公开说明。
2. **回收用途与成本**：推荐先用“旧件 → 旧器砂 → 调灵符 → 自愿改配”，不返核心材料；4砂、5砂+20币与1符/次均可调。若选择核心返料，必须重算首套预算和继承组合，不能同时维持原预算宣传。
3. **供货与售卖切片**：推荐先玩家小品类供货、同款核心材料商城直售暂不同时开放；人民币材料批次/旧装待相应交付与渠道条件通过后开放。若选择商城绑定材料提速，需要另定限量、售价与替代影响，原 0.1 元不是已定价格。

已确认的人民币方向、面对面交易、八部位/强化骨架及聚宝斋默认费率期限不列为重新审批事项。上述待定不阻止另一台电脑先按演示参数制作 UI，本轮不以候选稿代替业务实现。
