# 瑞兽迎春：轻量活动首发 V1

更新：2026-11-22。用途：活动线的玩法事实源。代码逻辑交给 Gemini，UI、布局、美术与交互表现交给另一台电脑的 Codex。本轮只交付设计，不修改游戏代码、协议、配表或玩家数据。

先读本页；随后程序读[逻辑交接](battle-festival-beast-logic-handoff.md)，UI 制作者读[界面交接](battle-festival-beast-ui-handoff.md)。三份文档是一套交付，玩法规则只在本页维护。

## 1. 需求与设计决定

用户已确认：春节神兽既是可挑战的首领，也可获得为宝宝；玩法简单好玩、不肝、允许小额消费；完成设计后由 Gemini 实现逻辑，另一台电脑 Codex 制作 UI。全游戏主要免费养成按每天约 30 分钟规划。

以下是本次受托收敛的 **V1 制作默认值**，不是用户逐项指定的数值，也不是已经实现或验证的平衡结论。它取代本聊天此前的“两档难度、六胜、三档领奖”建议；不修改常驻[首领试炼](boss-trial-planning-ui.md)的方案。

| 项目 | V1 规则 |
|---|---|
| 活动名 | 瑞兽迎春；奖励宝宝工作名“春禧兽”，文案名可换，内容身份不可复用 |
| 内容 | 一只首领、一个难度、一个战场；没有护卫、排行榜、随机路线和活动币 |
| 人数 | 一位真人及其一只合法出战宝宝；首发不做组队活动与 NPC 助战 |
| 开放 | 一期 14 个完整的 24 小时，全时段开放；正式起止日期由运营配置 |
| 主目标 | 本期累计胜利 3 场，免费领取 1 只确定种类的神兽宝宝 |
| 时间目标 | 一场含准备结算 4～6 分钟，三胜约 12～18 分钟；失败余量另测，不靠强制等待凑时长 |
| 进度 | 可一天打完，也可分 14 天完成；不要求连胜、连续登录、每日接交任务 |
| 入场与重试 | 免费、无门票、无体力扣费、无每日挑战次数上限 |
| 材料 | 有效胜局沿全游戏既有材料账新增最多 10 份额度，当日所有来源合计最多 20 份 |
| 额外掉落 | 首领经验、银两、普通掉落和捕捉全部关闭，避免反复练习产生另一条无限收益线 |
| 小额消费 | 沿用现有 10 元人物易容卡；活动不新建收费商品或支付链 |

活动模块对玩家提供开放状态、挑战入口、胜场进度与领取资格。它只改变本期挑战的规则和奖励条件；技能、装备、宝宝养成继续由各自系统负责。

### 为什么这样取舍

三场让玩家有机会经历“看懂、尝试配合、熟练完成”，同一机制刷六场增加的主要是重复。只调一档单人难度，个人开发者才能把低速辅助、普通宝宝和控制失败后的恢复调好。首领只需一个明确的危险动作，玩家的选择来自谁防御、谁输出、是否提前保护，而非记多套机制。

本版不加重击后的百分比扣血“破绽”、伤害竞速奖励或额外战斗按钮。普通行动轮已经提供恢复与输出时间；是否有趣以实际试玩为准，不把“最好玩”当作已验证结果。

## 2. 一次体验

1. 从“活动”打开瑞兽迎春。直接看到“累计通关 3 次获得春禧兽”、自己的 0/3 进度、开放时间和本日材料剩余额度。
2. 页面展示本人的出战宝宝。满足活动开放、基础回合战斗与宝宝功能可用、存在合法出战宝宝、没有其他对局或待确认结算后，可点击“开始挑战”。具体等级复用基础功能准入，不新增活动等级养成。
3. 开局使用本人的真实装备、技能、四维与宝宝。局内血蓝补满，禁止背包道具与捕捉；没有标准化竞技预设或临时授招。
4. 神兽普攻，并提前一整轮预告下一次重击会打人物还是宝宝。被点名者可以防御，另一方继续输出；也能提前恢复、上盾或尝试控制。
5. 胜利并完成权威结算后，进度变为 1/3。第二场变为 2/3；第三场取得永久待领取资格。失败、放弃和作废保留旧进度。
6. 点击“领取神兽”，得到正常宠物实例，再从既有宝宝界面管理、加点与出战。活动不自动顶替当前出战宝宝。

无宝宝时给“选择宝宝”入口；没有拥有宝宝时引导现有普通宝宝获取功能，不新增付费准入。已在社交队伍中可以参加本人的单人活动，但先走既有暂离/忙碌规则，不能把队友自动拉入或绕过队伍已承诺的开局。

合法出战宝宝须属于本人、已出战且仍存活；低血存活可以入场，局内补满。局外已倒地者先走既有恢复或换宠流程，活动不替其永久复活。开局锁定确认的宝宝身份，生成战斗快照时再次核验；预检后换宠、取消出战或资格变化则取消本次建房并返回明确原因，不能无宠开局或悄悄换成另一只。

## 3. 战斗规则

### 3.1 三回合节奏

| 回合 | 神兽计划 | 提示与选择 |
|---|---|---|
| 1、4、7、10 | 普通单体物理攻击 | 补充血蓝、保护或输出；目标由正常合法目标规则选取 |
| 2、5、8、11 | 普通单体物理攻击；本轮操作窗口开始前预告下一轮重击 | 指明被点名的人物或宝宝。可提前治疗、护盾、减攻或调整下轮速度 |
| 3、6、9、12 | 对已预告目标尝试一次物理重击 | 被点名者可以本轮防御，另一方输出；也可凭血量、保护继续进攻 |

- 预告目标由服务端在合法存活的人物和宝宝中用该局确定性随机源等概率选择，只有一个合法目标则选择它。一次预告只选择一次，重连、重播不重抽。
- **本活动的重击是慢蓄力动作**：占神兽当轮唯一正常行动，排在本轮人物与宝宝的正常行动之后、回合末状态清理之前。只改变该怪物动作的执行优先级，不修改全游戏的防御或速度规则。
- 防御仍需角色本轮正常执行成功；角色被控、已倒地等不能保证防御生效。上一轮防御不会延续到重击轮。治疗和护盾各消耗自己的行动。
- 神兽被合法控制阻止出招时，本次重击取消，不补普通攻击，也不在解控后追补；下一次按原回合节奏重新预告。睡眠被伤害打醒后能否出手按公共时序判定。
- 预告对象倒地、逃离或退场等失去目标资格时取消该次攻击，不改打另一方。冰冻等免伤按公共规则处理，不绕过不可受伤语义。
- 加减速下一轮生效。它可影响普通行动及保护时机，不让慢蓄力重击插回人物行动之前。
- 通过击杀首领取胜；第 12 回合全部正常动作和回合末效果处理后仍未取胜，按公共胜负优先级判定挑战失败。正常技能、持续伤害、反击与复活时序沿用公共引擎。

### 3.2 首测参数与平衡验收

普通攻击沿现有怪物物理公式；重击以同一基础伤害的 **180%** 为首测试值，零法力，单目标。首领表中的额外暴击、连击、反震、吸血先设为零，避免已读懂预告仍被随机额外连击击倒。首领不是宠物，不能被“劝退宝宝”当作合法对象，也不能捕捉。

生命、防御、物攻和速度按固定等级档配表，以开局角色的生效等级匹配唯一配置区间并锁定；区间不得重叠，须覆盖全部准入等级。宝宝等级、装备强弱不参与选档，不跟随玩家换更好装备而自动抬高。表 ID、具体各等级档数值由正式配表生成与试玩校准，不在客户端写公式。

开放前必须验证：

- 普通装备、普通输出宝宝搭配辅助/护盾人物能在 12 回合内通关；物攻和法攻各有可行搭配。
- 同档合理满血单位未成功应对一次重击仍有恢复机会；本轮防御成功应能明显降低压力。低速单位也能执行防御。
- 控制抵抗一次不等于必败，首领不统一绝对免控；免疫与抗性只使用现有公共规则。
- 全程双防不会获胜；提前保护后双输出、点名者防御且另一方输出，两种策略均有可观察作用。
- 双辅助低输出组合可以更慢或无法在上限内完成，页面只建议“至少一方承担输出”，不承诺任意搭配都同速通关。

这里没有增加人物或宝宝技能。引用[最新技能规则](skill-planning/combat-rules.md)、[正式技能目录](skill-planning/README.md)和[人物治疗与护盾](skill-planning/character-support-ui.md)：人物独立主动护盾为 A40，旧 P11 过量治疗转盾已撤回；宝宝三个分类入口合计每回合一招。当前正式目录是 61 项，不能恢复旧 69 项或已退役单体技能。

## 4. 不肝与失败处理

活动使用“仅局内补满”的专用结算策略：保留本人真实属性、技能与宝宝配置，局内起始血蓝为各自上限；局外不因本活动结算修改人物/宝宝血蓝、技能学习、四维、条目、装备和永久状态。原有局外冷却/状态的自然计时不被回滚或重置，局内初始冷却和状态仍按现行 PVE 快照规则生成。

本活动禁用背包消耗品和捕捉，不能预留或扣取战斗道具。退出后局外仍残血的角色不会因进活动获得免费补血。本规则是待实现能力，不得仅在客户端把血条画满。

失败后等结算确认即可免费再试，无复活费用或付费继续。玩家显式使用既有逃跑动作时，按公共逃跑结果判定；成功即本人与宝宝一同离场，不计进度。关闭活动页、断网和退出应用不等于逃跑。服务器不确定是否仍在战斗时保持“正在确认”，不能立即另开一局。

断线后沿用现有合法托管/超时行动，重连恢复原局。客户端已提交的动作不能重做。服务端确认作废后才释放战斗占用；作废不增加胜场、材料或神兽资格。

## 5. 进度、神兽与复刻

### 5.1 一根进度条与一次领取

- 每个角色、每一期只有 `0..3` 的累计胜场；第一、二胜点亮进度，不再各放一个领取按钮。
- 合法胜利每场加一，最多显示 3/3；同场重投、同请求重复、旧 UI 回包都不能加二次。
- 达成 3/3 即永久获得本主题神兽的待领取资格，资格不因档期结束、满栏、离线、改名或跨区而丢失。
- 领取不要求付费、完成困难或当日仍有材料额度。宝宝由服务端生成固定种类，资质采用该活动种类的固定首发模板，不做重复开箱刷资质。
- 每角色对同一神兽奖励身份终身只能取得一只。返场沿用同一奖励身份；已取得者显示“已拥有”，不因出售、删除、换期或换客户端重新发放。角色删除重建是新角色，不承诺账号级限领。

### 5.2 正常宠物实例与容量

春禧兽是独立活动种类，复用已确认可用的现有宠物模型/动作；正式资源绑定由 UI 制作者核对后填写。不把既有普通种类全体改成神兽。其 `acquisition_tier=2` 与 `cultivation_tier=4` 分别来自获取类和五阶表，不能用展示品质推算。

宠物等级、成长、技能资格和条目点沿[宠物系统](player-pet.md)与[宝宝条目首测配置](skill-planning/pet-entries-first-test.md)。活动不增加额外点池、不复制 Boss 重击为宝宝技能、不授予所有技能、不扩大出战名额。正式模板须提供可用初始技能及四维数据，最低携带等级不得高于本活动准入；未完成正式配置时不得开放领取。

**为这一个独占活动种类保留额外 1 只赠送容量**，与普通携带容量分别计数，使用同一宠物列表和同一 `PetInstance`。普通商店/捕捉不得占用这份容量；这也不是第二只同时出战的槽。普通栏满仍能领到这一只；异常已有重复实例时拒绝再创建并保留可恢复记录。

首发该种类只有活动授权发放渠道，绑定领取角色，服务端禁止将它单独交易、赠送、上架、寄售或作为合成/分解材料。通过种类的转移策略统一校验，不靠 UI 隐藏按钮，也不往实例里塞位置字段。跨服迁移和存档恢复属于原角色的正常搬运。若既有角色交易允许整个角色转让，神兽与该角色原有领取记录一起保留，角色 ID 不变、资格不重置；本版不新增整角色交易权限或禁售规则。当前没有放生功能，不在此新增；以后允许释放时必须保留终身已领回执，不能释放后重刷。

这是保护免费神兽与轻量领取所需的新增容量/转移策略，不能宣称现有宠物系统已经具备。后续若同一种类增加可交易来源，必须另行设计实例来源绑定，不能复用本版“整种类禁转移”的前提。

### 5.3 复刻与错过

本主题后续复刻使用相同神兽奖励身份，首次取得路径不变。未参加者可在下一期重新取得资格；已达成但未领者可随时补领。未达成的 1/3、2/3 不跨期累计，档期结束前明确说明；三胜集中完成不受每日次数限制。

不承诺永久绝版战力或某个固定复刻日期。已领者可重打参与并走正常材料额度，但不另外发可卖碎片或补偿货币。

## 6. 材料与小额消费

[装备材料现行方案](equipment-eight-slot-implementation.md)已规定：scene 首次应用有效 PVE 胜局时产生每场 10 份自选材料额度，全角色当日所有来源共享 20 份，UTC+8 每日 05:00 换日。额度是待领余额，不等于材料已经入包；仍走既有材料选择/领取流程。

活动接同一规则：当日已得 20 份，活动胜利仍推进神兽进度但材料新增为零；首次两场活动胜利也可以完成当天 20 份。三场同日完成最多产生 20 份，不额外发阶段材料。迟到材料按既有“首次应用结算时的游戏日”记账，活动胜场按“开局锁定的活动期次”归属，二者不得混淆。

不新增困难额外 5 份、材料单价、礼包或活动币。通关后的练习仍可获得当日剩余公共额度，额度满后没有材料；普通经验/银两/掉落始终为零。若共享材料路径不可用，正式活动不开启，不能静默改成独立日额度。

小氪只复用[现有 10 元人物易容卡](character-appearance-switch.md)：用于更换人物形象，非神兽皮肤、非永久衣柜解锁。活动主页面可有一个低优先级“人物外观”入口，价格和可售状态由既有商城/外观页展示。没有付费重试、神兽抽奖、购买通关次数、材料翻倍或活动通行证；失败页和神兽领取页不插入促销。

本主题免费定向取得规则覆盖旧文档中对本主题可套用“神兽充值抽奖”的未落地预留；不删除其他未来神兽渠道。三次通关与小额外观消费互不依赖。

## 7. 时间、收尾与异常

- 存储 UTC 毫秒，活动时间统一显示北京时间 UTC+8，附服务器校准倒计时；手机改时区/时间不能开活动。使用 `[starts_at_ms, ends_at_ms)`，终点不再准入。
- 活动开始到结束为 14×24 小时；结束后 7×24 小时为集中领奖展示期，然后进入历史。此 7 天只是展示期，**不是已达成资格的失效期**。
- match 成功持久化准入时冻结期次/规则版及准入时刻。到期前仅点按钮但尚未取得准入不算；合法准入后正常在途局可在截止后结束并记原期进度，不能据此无限重开。
- 新建房使用既有有界开局截止时间；未在该期限成功建房则作废。活动对局 12 回合上限不能在结束后被配置更新拉长。
- 结束后重放迟到的真实结算，仍按原准入和终局验证，能补足三胜资格；重复原件不能重复入账。不能用当前活动表已下架为由丢弃已准入局。
- 活动列表在任何日期均保留“待领奖”入口，只有全部领取完成且没有待处理结算才可折叠进历史。满普通栏不阻碍额外赠送容量；号源/存档失败则保留“待领取/正在确认”。
- 已领奖重试返回同一宝宝身份，不创建第二只。看不到回包不是失败证明；客户端保留原请求身份恢复查询。
- 资格冻结达成时的奖励定义和版本，换期/改表不改变这份已赚取权益；新设备从权威详情取回原资格和在途操作，不要求用户找回旧设备的 UUID。
- 维护顺延首版采用人工调整生效截止时间并留审计，复用[时间设计](activity_maintenance_auto_shift.md)的基线/生效分离；不宣称已有自动顺延。延期不复用期次或清空进度。

## 8. 可复用范围与首发边界

配置可替换活动名称/说明/美术引用、排期、固定等级档、首领与宝宝表引用、重击回合参数、累计胜场门槛。程序只支持这一种已验证的“预告单体重击＋累计胜场”模板；不会因为表里换了文字就自动获得召唤、护卫、组队、排行等新机制。

非节日可用同模板办“灵兽来访”或短期主题试炼。首发只开放一个实例，仍按期次存档；神兽返场共用奖励身份。新增另一种神兽、额外赠送容量、跨期累计或独立付费时，属于后续明确扩展，不提前开发通用活动 DSL 或新活动微服务。

## 9. 实现前提与完成标准

玩法及交互可按本文直接制作。正式开放仍需具备真实起止日期、春禧兽正式表行及模型引用、各等级档战斗数值、两版执行能力与试玩数据。这些是制作输入和运行验收，不由 UI 编造成功。

Gemini 先实现免费主线和幂等领取，外观入口只连接既有页面。UI Codex 可先做清楚标记的演示数据，契约确定后接真实状态。按逻辑交接中的分批验收完成；静态文档审查不能替代战斗、资产与 UI 联机测试。

本轮完成标准：三份交接规则一致、文件链接有效、更新索引与追加进度。C++/Go、独立 Java 版、客户端的新活动能力均待实现；本轮没有运行游戏编译、战斗或支付测试。
