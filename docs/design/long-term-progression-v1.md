# 《五行奇谈》长期养成首发规格 · 试炼手记

2026-11-22。**首套装备有终点，养满后还有打法可试。** 想稳一点，可以把已有法宝换成护心珠；想省一回合，可以让人物先压回春护卫，把输出机会留给宝宝。玩家有四个可以独自完成的通关印记，还能在相同条件下挑战自己的最好成绩。喜欢约战可玩论剑，想收集角色可翻人物志，想歇几天也不会掉印或扣成绩。

首发新增 **一页「试炼手记」、两张页签、四枚印记、一种成绩**。长期线只负责手记。八件法宝的定向获取、人物收藏和赛季荣誉分别属于装备、人物志和论剑。本稿交 Gemini 做逻辑，交另一台电脑的 Codex 做 Unity UI。四格、单人纪录和以下界面均为本次选定的首测制作基线。已有装备与技能代码沿各自计划验收，手记、试炼专用结算及其联机效果尚待实现与验证。[项目设定](project-vision.md) · [装备首发规格](equipment-v1-affixes-artifacts.md) · [人物志](character-background-collection-design.md) · [论剑规格](ranked-play-season-ui-candidate.md)

## 一、玩家怎样玩一局

**相同的回春护卫，上次用了 8 回合。** 玩家点「首领试炼 → 试炼手记 → 单人纪录」，选「普通·回春」查看旧成绩，点「前往试炼」回到选好普通、回春的试炼入口。在准备页调整自己已有的技能、法宝或出战宝宝。人物和宝宝各用自己的正常行动，操作和技能资格沿用战斗规则。

1. 单人立即准备。若已在队伍中，队长按当前 1～5 位真人准备，成员各管自己的人物和宝宝。普通随试炼的基础战斗与宝宝准入开放；本人普通首次通关后才可选困难，组队困难须全员符合。按钮读取试炼资格，不增加手记等级、门票或接任务步骤。[首领试炼](boss-trial-planning-ui.md)
2. 第一回先压护卫。看到护卫准备给首领回血，玩家可以抢先击倒它，也可用已学且合法的控制争取一次输出机会。普通难度的危险动作错开。在另一回合看到重劈点名自己的宝宝时，可以提前保护宝宝，暂缓输出。胜负由战斗裁决，手记只读结局。
3. 这次若 **6 回合胜出**，同一角色的「普通·回春」从 8 改为 6。若是首次通过，这一格也自动盖印。多人一起过，同格可盖印，每人原有单人成绩照旧。若失败，这一局只保留原战果，关掉结果页就能离开，不欠一次重打。
4. 结果页沿用胜负、返回和再战。已确认的本人试炼战果带有本局对应格时，次要按钮「看手记」打开该格。旧战果没有标记时省略这个按钮，仍可从试炼入口看总览。手记没有领取、补签、周清、伤害榜、弹窗追领奖励或强制红点。

### 三个阶段的选择

| 玩家阶段 | 一次实际可做的事 |
|---|---|
| 第一周 | 首次过普通·回春盖一枚印，下次换护势，观察什么时候该改打首领。七个有效日每天拿足 20 份，共 140 份，可先花 40 打造一件带两条目标词条的基础装，再用 40 换一件指定法宝，余下 60 自选。本周只玩三天则是 60 份，下次接着攒。 |
| 搭配成形 | 和朋友打困难·护势也能盖自己的印。改天独自用输出宝宝、人物处理防护，再试该格的单人回合数。同一只宝宝在战外可免费全量重分配共享的 20 条目点，各阶同预算。五阶是独立种类/实例身份，现有品质与获取分类另有其义。手记不消耗宝宝材料或修改技能。[宝宝条目首测](skill-planning/pet-entries-first-test.md) |
| 首套养满 | 想试第二种打法，可用两天常规额度换一件不同的法宝，再去同一格比回合。已经集齐四印，可以只玩自己喜欢的那一场，休息数周后仍可接着挑战。满印没有额外战力、称号、兑换物或下一圈重复任务。 |

## 二、什么算一枚印、一条纪录

| 永久印记格 | 点亮条件 | 单人纪录页 |
|---|---|---|
| 普通·回春 | 本人首次有效通关普通、回春版本 | 本格、当前可比规则的最少完成回合 |
| 普通·护势 | 本人首次有效通关普通、护势版本 | 同上 |
| 困难·回春 | 本人首次有效通关困难、回春版本 | 同上 |
| 困难·护势 | 本人首次有效通关困难、护势版本 | 同上 |

- **有效通关**。服务端冻结的正式首领试炼，入场 1～5 名真人，本人是入场者、属于终局胜方、未成功逃跑、完成回合数大于零。终局倒地、断线托管但仍满足以上条件的成员可盖印。按每个角色单独判定。成员中途退出，留下的人胜出仍按入场人数归类；观众、宝宝、非参战队员不计真人数。首次通关自动生效，材料额度用完后仍有效。
- **比较边界**。仅入场恰好一名真人的有效通关参与回合纪录，一人队亦同，带宠数量和操作速度不作比较维度。只在相同角色、正式试炼、难度、护卫及可比规则版本内取最小正整数。过程切手动/自动均可。首次成绩直接立项，平手或更慢保留原值。只展示回合，不打星，不按用时、伤害、队伍输出或是否充费排名。多人不建回合榜。
- **规则变更**。试炼方对影响可比性的敌方配置、回合口径或显著战斗平衡变化显式换代，改文案、换图不换代。权威版本在开局冻结，迟到的旧版终局只更新相应旧版成绩。旧成绩保留，首发页固定展示当前规则四格；首次换代出现「本版暂无纪录，通关印记已保留」。印记表身份跨可比版本不变。普通任一格点亮可作为困难解锁依据，沿用试炼方已有的权威资格，双方共用同一通关事实。
- **中断与来源**。失败、平局、作废、零回合和本人逃跑成功均不改手记。逃跑失败后继续打赢照常判定。关面板、切后台和断线不等于逃跑。不确定结局时显示「结果确认中」，重连查本人已确认状态。退出者不能回来补印，其他成员的实际资格独立计算。普通旧 PVE、PVP、小游戏、自有规则的活动和观看回放不记手记。若活动页仅跳转同一正式首领试炼，仍按那一份试炼原件认局。

## 三、半小时的养成账

**负责人已确认首套预算和每日目标。** 从零开始、同一装备档的一套八件含十二条目标词条与两件指定法宝，成本为 **300 打造材料＋300 强化石**。四基础装各到 +10，强化必成。两首饰和两法宝允许同类双件，同名法宝可各占一个槽。全游戏免费主养成目标为约 30 分钟合计 20 份。下表按首次应用结算时的游戏日计算，UTC+8 每天 05:00 切日。下列份额仅指装备自选额度，战斗内其他真实消耗、掉落另按原系统。[装备预算](equipment-eight-slot-planning.md) · [材料账本接入](equipment-eight-slot-implementation.md)

| 来源或用途 | 每次净增/支出 | 限制与有效日换算 |
|---|---:|---|
| 正常匹配 PVE 胜利或匹配 PVP 有效完赛 | +10 份待选额度；PVP 胜、负、平均可 | 共享每日 +20。两场 PVE、两场 PVP 或各一场都只够两份 10。零回合、成功逃跑、作废、切磋 +0。困难首测同额，额外 5 份仍是候选。 |
| 宝宝翻牌小游戏 | +0 份，扣 0 份 | 翻牌首发只作休闲，可替换一段游玩时间，完成或本机纪录均不占用材料次数。[翻牌规格](pet-memory-minigame-v1.md) |
| 活动入口及活动战斗 | 复用既有战斗时按原件记一次，入口额外 +0 | 按核心循环的 20 份方案，接入统一账本的独立活动合格结算可抵一次 10，与 PVE/PVP 共两个机会。未接入的活动不展示材料收益，满额后 +0。 |
| 选择材料 | 已赚余额 −n，背包内两类物品合计 +n | 余额大于零时在已有装备材料页自选，单批 n = min(20, 已赚未领余额)，两类之和须等于 n。以服务端持久确认显示成功。余额跨日保留，这一步的新增养成收益为 0。手记不经手。 |
| 四基础装、两首饰、两法宝 | −300 打造材料 | 四基础装各 40、两首饰各 30、两法宝各 40，合计 300，用足普通额度需 15 个有效日。 |
| 四基础装强化 | −300 强化石 | 每件累计 75，四件合计再 15 个有效日。打造与强化可交错，稳定拿足 20 的玩家，首套共 **30 个有效日**。 |
| 首套后可选的新法宝 | −40 打造材料/件 | 两个有效日一件；若首套选了两种不同法宝，再收齐余下六种需 240，约 12 个有效日，同时可佩戴仍为两件。每件完整生效，全收藏无套装奖。 |
| 手记的首通、改纪录、满印或重复打 | +0 材料，0 消耗 | 最多四个盖印格。每天、每周可额外投入的必做时间均为 0，上述 30 天已包含首套的全部 600 份。 |

有效日指拿足 20 份的一天，无需连续登录。半额日也保留实际所得。上述天数假设材料全自用，按两类实际缺口选取，多余强化石不能抵打造材料。装备流通稿每 10 份中 9 份仅自用、1 份可交易，两类合计仍是 10。若每天把 2 份卖出，首套按净留 18 份需 34 个有效日。以每场普通试炼 5～8 分钟的试玩目标估算，两场约 10～16 分钟，30 分钟中有约 14～20 分钟留给换装、重试、领取或其他活动。单场估算已含准备与结算。实际是否在半小时内拿足 20，按从玩法入口到拿足可领额度的真实耗时验收。[核心玩法循环](core-gameplay-loop.md) · [试炼时长目标](boss-trial-planning-ui.md) · [装备流通首测](equipment-recycling-trade-economy-v1.md)

**综合经济发布前需合并一处分歧。** 核心循环和现有材料账按两场合计最多 20，赛季稿提出当日前两场中每个真人 PVP 胜局再加 5，日合计可能为 20、25 或 30。这两套属于互斥口径。手记沿已有 20 做预算、在所有额度下新增 0，不在 UI 或服务端激活胜局加成。综合发布由核心循环与赛季线统一唯一奖励策略后，再复算装备天数。手记原型、结算与纪录独立实施。[核心玩法循环](core-gameplay-loop.md) · [赛季材料规格](battle-season-one-simple-design.md)

**小额付费只承接既有装备提速方向**。将来若装备线开放补材料，用同一种材料、相同打造及 +10 上限；例如同档首套还差 80 份，等价于四个足额免费日。付费不改回合、不卖印、不提高免费每日额度。首测不新增货币、订阅、付费强度、商城入口或生产支付。材料单价未定，本稿不为 80 份标价。

## 四、Gemini 的逻辑实现与契约

1. **用一份可信来源认局。** 成局权威确认玩法身份、难度/护卫对应的稳定格 ID、入场真人数与可比规则版本，冻结在当局并随可恢复的终局个人原件传到 scene。本人胜负用终局胜方与本人队伍比对，已完成回合直接取 `BattleSettlementData.total_rounds`（含终局回合），退出用本人 `fled`。既有 `battle_config_id`、`match_mode` 与结算传输协议版本均不足以识别四格。成局前校验试炼目录映射和入场数据。普通旧局或旧版无试炼标记照常结算、略过手记。已明确为新试炼、却缺少必填身份的异常原件保留，进入既有结算恢复。试炼方接通可信开局和终局前，正式手记入口关闭，独立 UI 演示可先交付。[个人结算源](../../proto/battle/battle_data.proto) · [冻结原件](../../cpp/libs/services/battle/system/result_commit.h) · [终局提交](../../go/match/internal/authority/completion.go)
2. **只在玩家自己的结算链写一次。** 复用 player_inbox 战斗域永久消费水位、`ApplyInboxSettlement` / `ApplySettlementToEntity`。候选中给本人的合格格位置位，对单人旧值取更小的回合数，与该笔效果及消费水位同一玩家快照、同一次围栏提交。沿 `CompleteInboxSettlement` / `PublishBattleResult` 的已提交时机公开。存档前只回上次已确认快照或「确认中」；重投与重连可恢复相同结果。相同局的冲突原件走既有裁决，不信客户端的身份、回合或通关上报。不依赖最近战果去重，不另开服务、线程、发奖账本或任务系统。[scene 结算](../../cpp/libs/services/scene/battle/system/player_battle.cpp) · [近期战果契约](../../proto/scene/player_battle_result.proto)
3. **持久数据保持小而有归属。** 永久布尔状态按手记四个稳定业务行 ID 走导表器 `cfg_bit_index` 映射、紧凑位图落盘；不拿行 ID/界面顺序当位序，也不绑定公共 Reward。最好成绩单独按对应格及可比版本存最少回合，无成绩用缺项。每种规则最多四个成绩，不保存全局流水、完整配装、通关次数或聊天内容。停用/删行保留老位，未知高位和未知旧记录原样透传，已收集数只遍历当前目录。老角色缺字段初始空，与新角同样从正式接入后的首场计起，读空页不初始化或改档。旧战报不足以历史回填，原试炼方若已有困难准入仍遵守其已有权威结果。[位图和业务 ID](../rules/bit-storage-and-table-ids.md)
4. **前端只新增一个只读查询。** 会话解析本人，返回可用性、已确认修订标识、当前可比规则版本/展示名，以及当前有效目录各行的稳定格 ID、难度、护卫名称与图标引用、已盖印、该版可选的单人最少回合数、可前往状态/原因、目标试炼选择。资格取试炼权威，实际进场再校验。目录与进度一次取齐，两页签本地切换。首发有效目录恰好四行。两页渲染的行和分母均从当前有效目录读取，锁住的困难行仍在目录内。退役行及其位不计数，目录缺失或无有效行时整页暂不可用。对现有已公开的本人 `PlayerBattleResult` 补一个可选的试炼标记（携带稳定格 ID，语义名 `trial_entry_id`），与该条自己的 `battle_id` 同源同次确认；现码尚无此标记。「看手记」只据已确认的这条结果选格，缺标记或格已退役即省略定向按钮，无需另查逐局档案。旧响应不得覆盖同角色较新快照。手记不提供写请求，组队、换装、领取材料沿用各自页面。[本人近期战果结构](../../proto/common/component/player_battle_result_comp.proto)
5. **已有代码与交付顺序。** `MissionListComp` 虽声明成就 scope，当前 `player_mission.cpp` 只接受普通 `kPlayerMission`。`GetRecentBattleResults` 最多 10 局，`AckBattleResults` 只标已看。材料资格的实码已支持未逃跑的 PVE 胜方，包括倒地者。普通掉落另有规则，实际获得物品与盖印分别判定。先与首领实现方接同一个冻结上下文，再做玩家写入和只读查询，最后把语义、缺省、错误、能力可用状态和一份真实样本交给 UI。按仓规改源协议/表再生成。C++/Go 与独立 Java 分别按玩家契约验收。本交付未核验 Java 手记逻辑；宝宝首测文档记载 Java 战斗只接入 21 个条目方向中的两项直伤，带宝宝试打时使用该服实际可用能力。[普通任务入口](../../cpp/libs/services/scene/player/system/player_mission.cpp) · [近期战果上限](../../cpp/libs/services/scene/battle/system/battle_result_history.h) · [材料资格](../../cpp/libs/services/scene/player/system/player_equipment_material_reward.cpp) · [生成与客户端同步规范](../rules/proto-and-tables.md) · [宝宝两版能力](skill-planning/pet-entries-first-test.md)

## 五、另一台电脑的 Codex 可离线制作的 UI

**在既有首领试炼入口加「试炼手记」，结果页加次要按钮「看手记」。** 做一张沿用项目手机方向、安全区和返回栈的手记面板。道家 Q 版，米白纸底、玉绿页签、古金印边。沿用现有两种护卫图标，普通/困难用明文区分；未盖印留空印框和「未通关」，已盖印用实框和「已通关」。不要求新增立绘、战斗场景、佩戴徽章或新主页。

| 位置 | 画什么 | 点了做什么 |
|---|---|---|
| 顶栏 | 返回、标题「试炼手记」、页签「通关印记」「单人纪录」 | 首进默认印记，切页不发新请求，返回原页面。结果页只凭已确认的本人战果内与该局关联的目标格选中该格。旧结果缺试炼标记或格已退役时省略定向按钮，可从试炼入口看总览。 |
| 通关印记 | 盖印数/当前有效格数。首发普通/困难各一排、两列为回春/护势，小屏可纵向滚动 | 点任一格只选中它，下方显示「1～5 人通关均可盖印」、该格已/未通关与准入说明。默认选第一格。 |
| 单人纪录 | 按相同有效目录列出成绩，首发四行。逐项显示难度、护卫和「最好 6 回合」或「本版暂无单人纪录」，显示当前规则名 | 点行显示说明「独自上阵，挑战同一护卫的更少回合」。多人通关的格可已盖印但单人纪录为空。 |
| 底部 | 唯一主按钮「前往试炼」；不可前往时就地显示原因 | 跳到已有试炼选择/准备入口，预选本格。不会直接进战、花费、拆队或申请开局。已组队成员按已有界面看队长/队伍状态；当前占用、未开放或困难未解锁则禁用，保留返回。 |

**一份可直接绘制的样例**（UI 演示数据）：角色当前规则「首测规则」，普通·回春「已通关，单人最好 8 回合」，普通·护势「已通关，本版暂无单人纪录」（双人通关），困难·回春与困难·护势「未通关，本版暂无单人纪录」。页头为 **2/4**。在演示菜单切到「回春再战 6 回合」时，只把第一格的 8 换为 6，计数仍是 2/4；切到「困难·护势首次组队通过」时变 3/4，单人值仍空。切换演示场景不连真实网络，不写玩家缓存、装备或背包。

| 状态 | 页面与允许操作 |
|---|---|
| 首次加载/刷新 | 首次显示「正在翻开手记」，暂不显示 0/4。已有上次确认内容时保留并标「更新中」，允许返回。 |
| 真空档/部分/满印 | 首发四个有效格的空档显示 0/4 和各格条件，部分按样例，4/4 显示「印记已齐」，仍可前往试炼。行与分母始终取有效目录，未解锁行保留，退役行移出。 |
| 未解锁/未开放 | 条件由权威提供，例如「本人普通通关一次后开启困难」。若整项能力未开放，常规入口隐藏。已开页面遇目录缺失或无有效行显示「手记暂不可用」，不显示 0/0。图标引用缺失可用通用印框，显示真实文字。 |
| 查询失败/断线/归属切换 | 有本人旧快照显示「上次同步」并禁用前往，无旧快照显示「手记暂未同步」。按钮「重试」「返回」；重试只读，恢复后重查。切角色清空旧视图及在途回包。 |
| 胜负已定但手记待确认 | 结果页显示「记录确认中」，已确认的旧成绩仍可保留；新局按钮按源玩法占用决定。重连后读取已确认本人战果/手记。不从结束动画、客户端计数、掉落或查看回放推算新纪录。 |
| 只能看到旧战报/服务器不支持 | 最近十局找不到请求局，只说明该列表无此项。可单独看已确认的手记总览，不报失败、不凭本地操作盖印。正式未接的能力保持未开放，独立演示始终标「UI 演示数据」。 |

UI 制作顺序为面板与切页 → 上述样例及空、满、错误、断线状态 → 既有试炼入口和结果页导航 → 接入 Gemini 提供的只读响应与能力开关。交付提供真机或编辑器的空档、部分、满印、不同人数和异常状态截图，以及演示/真实接入清单。UI 可单独按本节施工，无需先获取另一台电脑的仓库；最终联机需双方使用同一契约版本。

## 六、首测验收

| 输入或操作 | 玩家应看到/服务器应保持 |
|---|---|
| 新角色单人普通·回春依次 8、8、9、6 回合通关 | 印记始终 1/4；最好值依次为 8、8、8、6。最后一回合已算入；一次新纪录不发物品。 |
| A、B 双人打普通·护势，A 倒地，B 连线或托管，队伍胜出 | 未逃离者各自盖本格印，均不写单人成绩；入场两人即使后来只剩一人也不改档。A 成功逃跑的变例中，仅留下的 B 盖印。 |
| 一人队、单人无其他玩家在线，普通先打一种，再分别打困难 | 只要满足源玩法准入就能盖印、记单人回合；结算和后续跳转无排队等陌生人的要求。 |
| 同格当前规则最佳 6，另一护卫、另一难度或新版打出 4；旧版结果延迟重放 | 各格、各规则独立，当前规则不被旧版迟到结果覆盖。印记跨版本已有一次即可。 |
| 失败、平、主动逃离、作废、无入场身份、非试炼 PVE 或只看回放 | 相应本人手记不增加。断线后仍获有效胜利的可正常记录；关闭结果页不影响最终状态。 |
| 收件箱重复/乱序补投、提交前断线/换节点、提交后应答丢失、超过十场后重登 | 提交前绝不显示新印。恢复同一原件得同一结果。已确认的手记与最好值可跨设备取回，确认已读及重试均无额外经济效果。旧档缺新增字段且有有效目录显示空档。 |
| 当前目录退役一格、目录缺失、战果缺试炼标记 | 退役后按三行渲染并以 3 为分母，旧位照常保存。缺目录时整页不可用。缺标记的旧战果无定向按钮，入口仍可查询有效总览。 |
| 日内 PVE 胜一场＋匹配 PVP 有效负一场，再胜试炼；跨日领；额外活动包同一局 | 前两场共赚 20 待选，试炼仍能盖印或破纪录，领取只把原 20 入包。跨日清当日已赚、保留未领；多来源不能把 20 算成 30，困难额外默认 0。 |
| 免费体验节奏 | 首测找一位新手、一位熟练玩家各走两场普通，计入准备、操作、重试、结算与等候，记录能否在约 30 分钟拿足 20。另走 PVE＋PVP；匹配等候过长时可回单人 PVE。用实测调整主玩法节奏，不往手记再塞奖励。 |

制作联通的顺序是试炼方提供有效原件、Gemini 持久化并公开本人手记、Codex 绑定同版查询。UI 样机可与前两步并行。这里的时长、金额等价日和示例成绩均为设计或预算，联机结果由两端分别提供运行证据。
