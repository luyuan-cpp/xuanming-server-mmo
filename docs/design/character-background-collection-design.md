# 《五行奇谈》人物志与角色收藏设计

2026-11-23 当前分工。本机 Codex 负责玩法设计与委派协调，另一台电脑的 Codex 负责人物志界面、布局、美术素材及交互表现。负责人已授权 Gemini 实现人物相关业务逻辑，Gemini 自主核对现状、设计技术框架、实施并验证。四个人名、留灯院和下文故事均为原创候选。文中的人物名可以改，既有资源身份、玩家昵称和玩家存档各有自己的用途。

## 1. 玩家要收集什么

玩家从一个人物起步，可以通过游玩、达成条件或购买取得更多人物。每一位都应有玩家能记住的生活、脾气和牵挂。即使两位玩家选择相同人物，仍能以不同的技能、装备和宝宝打回合制战斗。收藏多一个人物的回报，是能以他的样子在城里行走、上场战斗，知道他为什么这样说话，还能回头读某件东西的来历。

**本稿推荐的身份口径**是一份玩家养成存档、数位可选择的独立人物。玩家扮演当前选中的人，图鉴记述这个人的生平。档案上的“陆照禾”和头顶的玩家昵称可以同时存在。换到祝停云时沿用同一玩家 ID、等级、装备、宝宝、任务进度和技能方案，不重新建号。四人可以在同一则往事里出现，无需以共魂、转世或多人同时出战争取解释空间。另一种口径是同一主角穿不同装束、档案记述衣装原主；若选择后者，需要重写人物口吻与出场文案。现有代码能支持外观身份，尚不能据此断言负责人已经选定世界观口径。

物攻、法攻、障碍、辅助均属于共通修习。赤枪、毛笔、竹弓和水葫芦是人物的辨识物，人物图鉴不授招、不加属性、不提高出战名额。宝宝保有各自既有养成与出战规则。个人开发首批只写四位，原目录中的其他形象继续正常展示和使用。

## 2. 留灯院的四个人

归元城的留灯院候选设在一条离面铺不远的巷子。院里有一口存雨水的缺沿缸，一张不得不垫纸的长桌，门外有一盏给夜客认路的灯。几个人住的住、来吃面的来吃面，故事可以发生在一顿饭的工夫里。留灯院只作人物文字和插画场所。后续节气小事可以写成“没加油的旧灯自己亮了，灯芯偏向月汐湾”，到此为止也成立，不依赖新地图、房屋经营或主线任务。

### 陆照禾 · 灯下留一碗

**给玩家看的档案全文。** 陆照禾在归元城面铺后院长大。母亲擀面，祖母从前替人照看留灯院。祖母膝盖疼，搬回家歇下，院门钥匙就穿到了阿禾的金葫芦绳上。葫芦里一直装水。夏天从井里灌满，过两条巷子，还有一点凉。

他记得谁吃面不放葱、谁上台阶得扶一把。偏偏到了自己的账上，瓦匠上次少收的钱、邻居帮忙背的木料，一概写作“算清了”。母亲翻开账本，让他指给她看，哪一笔算清了。他挠着发带想了半天，往空白处画了一只碗。

有一年上灯，他答应送灯、接夜客，又跑去替米铺搬粮。回来时天黑透了，客人抱着包，坐在黑门外。阿禾准备了许多解释，客人只说：“你来不了，告诉我一声也行。我还能先去吃碗面。”第二天，他在门边钉了块写去向的小木牌。轮到自己出门问路，他仍会在路口多绕一圈，装作看人下棋。眼下他正攒钱换漏雨的瓦；等屋顶补好，也想当一回提着包到别人门前的客人。

**写作与演出。** 少年感约十五至十七岁。圆脸短身、短棕刺发、金发带、玉绿外袍、米白内衫、太极扣与金葫芦沿用既有主角。热心、嘴快，怕自己拒绝了别人就没人接手。他的成长落在一次能说出口的求助上。日常的动作是摇葫芦听水声，把最干的一只凳子推给来客。

**可跳过的片段《第四只碗》。** 暮雨从第四片瓦缝落下来。三只碗接得准，第四只总差半寸。阿禾一手举碗，一手执笔，要写“出门片刻”。停云推门，将一根撑篙靠在墙边。“你还要走？”阿禾看看漏雨，又看看要送去巷口的热面。“你能替我看一会儿院子吗？”停云把第四只碗往左挪了半寸。“成。回来带葱。”这次他翻过木牌，认认真真写下“祝姑娘在，想吃面等我”。

### 祝停云 · 败局册

月汐湾的摆渡人家靠潮水吃饭。父亲掌舵，母亲修船，停云拆下旧船绳的一股编在枪穗里，遇雨也舍不得换。约十八至二十岁，惯于第一个跳下船系缆。她想整修那条旧渡船，也想在论剑场堂堂正正赢一场。她最讨厌别人说“已经很好了”，总听成对方没把她当成对手。

她输过一回，脱口说是地滑。父亲等她说完，才道：“输一场，别把自己说的话也赔进去。”她回去道了歉，偏没好意思问对手那一步怎么走。此后开始记败局，每页都有对方的长处；给自己留的问题字特别小。收摊后常替母亲剔掉船板缝里的碎贝。她肯为了别人出头，最难的一步是承认自己也需要人教。

**可跳过的片段《纸也赢过一回》。** 她连输三场回来，枪穗上的雨滴进闻砚生的墨里。闻砚生写“惜败”。她把纸转过来：“去掉惜字吧。”自己的败局册先写了“对手拖”，再划掉，改成“我又急了”。面端上来，她用筷子尖在桌面上点出两个人的脚步。“要等他先动，到底等到什么时候？”闻砚生看她：“昨天谁说我纸上谈兵？”她扒了口面：“今天纸赢了。你讲。”

### 闻砚生 · 白纸夹页

归元城印铺子弟，约二十至二十三岁。家里印账本和渡船时刻，砚生从小校字，发现刻错了总要一刀一刀补回来。他想编一本亲身核实、封面能署自己名字的奇谈集。越想署名，就越怕当众承认自己拿不准。旁人说见过古怪东西，他常先回一句“不可能”。

街坊曾说纸人半夜搬书。老人说到一半，他认定是鼠患，把传闻删成两行小字。书印出来，次日纸上多出一行：“不是老鼠，书也没偷。”他拿着那张纸去找老人，头一回坐下听完全段。册首的“所录皆实”没舍得刮掉，只夹入一张“暂未查明，也记于此”。他替阿禾对账、和停云论步法，唯独对听雨的远行见闻格外认真，也格外容易冒犯她。

**可跳过的片段《借还栏》。** 印铺老人领他看书架最底层，那里有只腿短的纸人，正踮脚把昨天的书送回。砚生的笔停在“被搬走”后面。老人从旧账簿上撕下一张窄纸：“我们这里管这个叫借。”砚生在夹页两头分别写上“借”和“还”，中间空了一行。他把纸递到最底层：“还缺名字。这一行，你来？”

### 桑听雨 · 竹筒里的旧船票

约十六至十九岁，生在月汐湾的竹器人家。父亲编筐制弓，母亲沿岸卖竹器；海风里哪种绳结会松，她摸一下就知道。她想去八景岛画潮汐鸟谱。家里早给她备好了行李，她却拖了一年：怕一个人坐船，也怕回来发觉大家没有她一样过得很好。问得紧了，她就讲个半真半假的海上笑话。

去年买了票，临登船让给别人，对家里说赶上急事。父亲没拆穿，只把她落在门边的竹筒重新挂好。筒里有笔、卷成细管的纸和一张过期船票。她擅长等——一只鸟能等一下午，自己的第一步也能等一年。阿禾信她见多识广，砚生发现她把近岸的鸟鸣记进了远岛，停云一句“我替你买明天的票”能让她整天躲着渡口。

**可跳过的片段《没有画的那一页》。** 阿禾问：“八景岛的鸟脚也是青的吗？”听雨本想说“当然”，看见他已经摊开纸。“岸边这只青。岛上的……你替我空一页吧。”饭后她去了渡口，先问一个人带行李该坐哪一边。船还在系缆，她就坐在靠岸的一侧，听了半刻钟水声。图里第一笔是一根缆绳。

## 3. 从翻人物志到永久收藏

**首版人物志。** 主城既有“易容形象”入口保留。在已有形象详情上增加“人物志”阅读入口；对应四人时显示档案名、原形象名、同一稳定 ID 的预览、人物小传和一则片段。名单其余形象不虚构人物故事。选行只更新详情，读片段可“返回”或“跳过”，稍后可以重读。切换到阅读页应解除之前待确认的扣卡动作，阅读区没有购买和扣卡热区。关闭、返回、点下一人、断线重开均不派发修改外观 RPC。既有面板可按原设计请求只读形象信息。预览缺失时显示该人物的姓名和“形象资源暂不可用”，不冒用另一个人物的图。文章可独立打包，当前只需复用同 ID 现有预览与 PNG，避免为读一段话加载整套动画。

首批公开全部四份基本档案和上述四个片段，候选名作为可替换的展示文本。选定人物、页码/本次已读提示如有需要只在当前角色的界面会话内保留，退出角色清掉；不做跨设备承诺。“继续阅读”只定位文字，跳过与看完都不发道具，也不给玩家打永久“已拥有”标签。

**永久收藏目标。** 角色拥有权是服务端存档。可预览（内容和画面）、已拥有（允许装备）、当前永久使用（基础形象）与正在试用（临时覆盖展示）是四个不同事实。正式启用新规则后，在列表显示“未获得”“已获得”“使用中”，试用另标到期时间。未获得可看公开档案和获取说明，有权者可点“使用”；目标已使用时不再提交。服务端不可用时标“状态待同步”，停用资产操作。

**三类内容各归其主。** 永久人物档案可随时重读，包含姓名、家庭、愿望、物件与公开小传。未来若加需解锁的故事片段，可在获得人物或达成玩法条件时开放，片段开放、读到哪一页、奖励是否已结算各自独立；只有确需跨端保存时才为稳定片段 ID 建存档。活动期、排名与当期奖励由活动/排位按期持有，活动结束不收回已经取得的人物，复刻复用人物 ID 与取得幂等规则。好感度、主线分支、专属数值天赋、属性羁绊及付费强技能均不在本设计范围。

### 为什么首批保留旧形象卡

现有形象卡每次消耗一张，将一位永久形象覆盖为另一位；商城规则价 1000 分。有卡与有某个人物是两回事。从历史的当前形象和试用位不能还原玩家过去用卡换过哪些人。把“使用”直接连到旧切换 RPC 会扣卡，把所有试用过的形象点亮又会误发权益。首批只读以避开这两个错误。

**后续推荐的权益衔接，待负责人决定。** 新取得的人物永久登记，已登记者可免费切换；如继续使用旧卡，推荐让一张卡只在玩家明确选择一个允许用卡解锁、且尚未拥有的目标时消耗，解锁与扣卡同一权威提交。排位、PVE 等专属渠道可各自禁用形象卡兑换。已有卡保留原道具身份，旧卡未来可换哪些人、未发订单、已持卡和历史购买的处理必须随经济规则定案。也可保留旧易容、先只让玩法收集公开故事与纪念图，此方案没有“获得后免费扮演”权益。两套合同不可在同一按钮上混用。项目尚未上线，本节约束已有开发存档及新规则的启用，不预设存在生产服和真实历史订单。未决定前只开放首批阅读功能，勿调整 SKU、消费、余卡、历史外观或试用。

### 2026-11-22 全版收藏讨论记录

以下记录当时考虑过的数据风险与技术做法。Gemini 自主选择实现；玩家权益与需负责人决定的玩法问题见上一节，当前交接见第 6 节。

1. **归属、旧号与装载。** 以玩家永久 ID 持有收藏。建议在既有 profile 中加独立的拥有位图，按 `CharacterAppearance.id` 经已有永久映射取位，原试用位图只表试用。当前角色只呈现一个人物，沿用 `appearance_id` 现有身份投影；不新增并行“当前人物”字段。新号在权威建角/初始化的同一提交授初始形象。旧号有合法永久外观时优先承认该项，已持有的下架形象仍能显示。历史空 ID 保留旧职业/性别回退，未知 ID 原样保留并记录；不全服改成阿禾，不根据头像替代映射、试用记录或现有卡数追认购买史。旧号是否额外送阿禾、历史已付订单如何补录另由明确政策处理。资格初始化须有明确的数据版本或可重入规则，避免每次读档催生新资产。
2. **发放与失败。** 授权发放只接已验证的建角、任务、活动或订单结算。服务端核验玩家、目标、来源、有效条件，以来源实例和稳定业务幂等键去重；相同事件重放返回既有结果，操作键换参拒绝。另一合法渠道取得已有人物返回“已拥有”，不重复发替代币、不自动换上。消耗类请求先检查已拥有、可兑换和可用余额，在同一次资产提交中完成扣除、置位和对应来源回执；并发两笔至多扣一次。涉及跨服务以现有可靠消息、事务外通知与持久回执重试，避免先记“已领”后丢发放。不得用客户端“读完故事”触发发放。
3. **装备与身份。** 全版明确区分经批准的解锁和免费装备操作。scene 校验当前玩家可变、拥有、目标可用及幂等键；战斗准备/进行、换节点和退出过程拒绝新切换。重复同参得同一结论；普通失败保持永久形象、试用和背包，未知提交状态先按原键查证。成功只改永久展示选择、清理临时覆盖、递增已有切换序列、沿存盘与目录回调传播。战斗开局采用同一时点生效外观，已开局的重连/观战读原战斗快照，试用中途到期的城内表现按现有时钟恢复；不得因打开档案或重连改写战斗快照。装备不同人物不重算战力、不改宝宝。
4. **兼容、展示与验证。** 配表禁用/缺行允许安全读历史，禁止新的非法授予；保留未知高位，按当前可展示行过滤统计。旧客户端缺少拥有字段，继续走与其协议语义匹配的受控入口；若收费合同变更，正式切换前须停用或版本隔离旧消费入口，避免新规则客户端免费、旧端却还扣卡。冻结、存盘失败、目录延迟、同一奖励重投、角色转移、禁用资源、断线回放、未知高位、空档案都纳入两服相同契约用例。新增 tip 走 `Tip.xlsx`；协议和表从权威源生成，双服与客户端按各仓规范对齐。
