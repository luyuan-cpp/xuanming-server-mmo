# 瑞兽迎春：另一台电脑 Codex 的 UI 交接

更新：2026-11-22。先读[玩法 V1](battle-festival-beast-v1.md)，接入看[逻辑契约](battle-festival-beast-logic-handoff.md)。本文件是界面制作规格，不代表真实接口已完成。本轮没有访问或修改客户端。

## 1. 工作范围与顺序

你负责 UI 页面、布局、美术资源、交互表现及视图绑定；Gemini 负责服务端逻辑、源契约、测试和客户端非视觉数据适配。先读客户端仓 AGENTS，确认共同编辑边界。

先用独立演示数据实现全部状态；服务端契约完成后，把同一视图接到真实适配层。演示模式必须在开发环境明显标记，不能向真实服务发写请求，也不能显示为真实获得神兽。缺少新契约时保持“功能未开放/数据未同步”，不要复用旧接任务接口冒充挑战。

首发新增一张活动主面板和一个规则弹窗，扩展既有战斗/结算界面。宝宝管理、材料选择、人物外观和商城仍使用已有页面。不要制作活动商店、通行证、困难页、三层奖励树或NPC跑腿导航。

## 2. 视觉方向与资源

沿客户端现有道家 Q 版、玉绿/米白金边，春节用朱红、灯笼和梅枝作少量装饰。复用现有按钮、字体、弹窗、战场、怪物/宝宝模型及骨骼动画；先核对实际资产，不凭服务端资源名假定文件存在。

首领与宝宝共用同一只瑞兽的形象，差异用缩放、镜头和名签表现。工作名“春禧兽”，最终资源绑定由制作时确认。首版新增资源预算限于一张活动横幅/裁切图、一个活动入口图标、一种点名标记，可复用已有重击特效。禁止仅为此活动制作新地图或整套新动作。

普通宝宝、神兽五阶徽章、展示品质各是独立信息。不能把红金皮肤画成一个未提供的更高品质或付费皮肤。

## 3. 入口与活动主面板

活动列表卡片显示名称、缩略图、阶段、统一时区的起止时间、个人通关进度，以及“前往”按钮。红点只表示确实有可领取神兽，不因每天上线或入口未点击重复亮红点。

主面板信息顺序：

```text
瑞兽迎春                         规则  关闭
北京时间：开始日期 — 结束日期    剩余时间

        瑞兽预览          累计通关3次，免费获得春禧兽
                         已完成  ● ● ○  2/3
                         奖励详情／已拥有状态

当前出战宝宝：[实际名字]  查看宝宝
重击前一回合会点名，人物和宝宝都可能被选中。

今日还能赚取材料额度：实际值 / 20
已有待领取材料余额：实际值（可跨日保留）
本次胜利预计新增：实际值；材料需到既有入口领取。

       [开始挑战] 或 [领取神兽] 或 [继续挑战]
材料领取入口                  人物外观（低优先级）
```

- 以开始挑战或领取为单一主按钮，不让玩家同时面对两排大按钮。按服务端永久资格优先：领取处理中→“正在确认领取”；有未领资格→“领取神兽”（新一期0/3也适用）；已领且本期开放→“继续挑战”，明确不再发第二只；其他满足准入者→“开始挑战”。历史期没有开战按钮。
- 3/3未领仍可通过次级“继续挑战”进入战斗，但正在领取/结算时禁用；不会因重打丢失资格。
- 不画难度选择、体力、碎片、每日签到、剩余收费次数。三个圆点是一个累计进度，不是三个领取箱。
- 开始挑战发请求后原位显示“正在开战”，禁止连点。成功后沿既有战斗分配与票据进入；未知时显示“正在确认”，查询恢复原请求。
- 已在社交队伍中显示“本次为个人挑战”，沿既有暂离/忙碌行为；不得在客户端直接解散队伍。
- 服务端提示出战宝宝已倒地时，提供现有恢复/换宠入口；开局途中宝宝身份变化时显示“出战宝宝已变化，请确认后重试”，刷新真实宝宝信息，不能沿用旧预览假装进入成功。
- 非活动期且有待领取资格，卡片显示“待领奖”，主按钮可继续领取；没有未领奖则归历史。

## 4. 按钮与状态

| 元素 | 动作 | 不可用/失败时 |
|---|---|---|
| 开始挑战 | 提交原请求身份、活动实例及当前配置版 | 未开放显示起止；无合法宝宝给宝宝入口；在战斗/结算中显示真实原因 |
| 查看宝宝 | 打开既有宝宝管理，返回保留本面板 | 战斗内按已有规则只读，不替玩家换宠 |
| 领取神兽 | 提交稳定奖励身份与原请求身份 | 未达成显示差几胜；处理中保留原请求；服务错误可刷新/原请求重试 |
| 查看已领取宝宝 | 打开真实 pet_id 的详情 | 实例未同步时显示同步中，不临时构造一只假宝宝 |
| 材料领取入口 | 打开既有额度分配页，依据已赚未领余额启用 | 待领余额为0才显示暂无可领取材料；今日赚取额度满但历史余额非0仍可领，不灰掉活动挑战 |
| 人物外观 | 打开既有易容页面 | 无对应功能则隐藏；价格和售卖状态在原页面读取 |
| 规则 | 打开本页第5节弹窗 | 始终可关闭，不强制逐页阅读 |
| 关闭 | 收起当前面板 | 不取消已经成立的战斗、不代替逃跑、不清除在途请求 |

加载中显示骨架/占位，数据缺失不得显示为“0/3”。首次加载失败用“暂时无法读取活动信息”和“重试”；旧快照刷新失败可继续看，但标记未同步，禁用需要新资格的写操作。

领取成功动画只在服务端持久确认后播放。显示“已获得春禧兽”及“查看宝宝”，不自动购买、换宠或继续开局。普通栏满也能走本活动专属赠送容量；服务端拒绝异常容量时显示返回原因并保留资格，不提示购买扩容。

## 5. 可直接使用的规则文案

> 活动期间累计通关3次，可免费获得一只春禧兽。三次可以在同一天完成，失败不会清空进度；未满三胜的进度不跨期累计。
>
> 每局在12回合内击败神兽。它会提前一回合点名，下一回合向目标发动重击。被点名者可在重击回合防御，也可以提前保护；另一方继续进攻。
>
> 每次挑战仅在局内补满血蓝，不改变局外血蓝。活动内不能使用背包道具或捕捉。
>
> 胜利材料与全游戏共用每日20份额度，额度用完仍可推进活动进度。已达成的神兽领取资格不会随活动结束失效。
>
> 春禧兽每名角色终身最多获得一只，绑定角色、不可单独交易或赠送，不增加同时出战数量。整角色转让沿既有规则，领取记录随原角色保留。

开始/结束时间与北京时间标注由数据填充。小额外观消费单独留在原外观页，不混入活动规则或领取条件。

## 6. 战斗界面扩展

复用既有回合指令和人宠切换，回合显示“第N/12回合”，不新增“躲避/打断/爆竹”按钮。

第2/5/8/11回合开始操作前，显示：

> 下回合：春禧兽将重击【人物名/宝宝名】

目标上显示带形状的标记与文本。第3/6/9/12回合显示：

> 本回合重击【名字】；在本轮人宠正常行动后发动。

同时给一条可关闭提示“目标可本轮防御，另一方可输出；控制可能被抵抗”。不要写“点防御必定安全”，被控而未能正常行动时防御不能生效。

预告有效、取消、已执行三种状态来自服务端。看到控制图标不能本地判定取消；目标倒地/退场后也等权威结果。重连直接恢复当前预告与提交状态，不重抽目标，不强播从第1回合开始的动画。

不能把第2回合的防御画成跨回合抵挡第3回合。人物治疗与A40独立护盾是两个正常行动，宝宝三个分类共用一回合一招。冰冻期间不显示“冻住后集火”的建议。

## 7. 结算界面扩展

| 结果 | 必显内容 | 按钮 |
|---|---|---|
| 胜利，未到3胜 | 已确认进度1/3或2/3；本局实际新增材料额度 | 再试一次、返回活动 |
| 本局首次取得资格 | 3/3、神兽已可领取；材料与神兽分开列 | 领取神兽、返回活动 |
| 之前已取得资格但未领，再次胜利 | 神兽待领取，不重复演出新解锁 | 领取神兽、返回活动 |
| 已拥有后胜利 | 已拥有；本局实际材料额度或日额度已满 | 再试一次、返回活动 |
| 失败/成功逃跑 | 原进度不变；没有本局通关材料；可免费再试 | 结算确认后开放再试、返回活动 |
| 作废 | 服务器确认的原因，进度未增加 | 状态清理完成后重新挑战 |
| 结果/存盘未确认 | 结算处理中，奖励待确认 | 返回查看状态；禁重复开局/领取 |

再试生成新局前重新读取准入和出战宝宝，先回活动准备状态，不在玩家确认结算时自动连刷。材料用“本局新增可领取额度 +10”而非“获得10个道具”；实际入包仍以原材料领取回执为准。

不把关闭结算当成放弃神兽资格。领取在途可收起面板，但重新打开必须恢复原请求状态。

## 8. 必备演示数据与验收截图

演示数据字段形状须与 Gemini 确认后的契约一致；未定字段只留在隔离演示适配层，不生成第二份正式协议。至少覆盖：

1. 未排期、预告、开放0/3、开放2/3、3/3可领取、已领取、集中领奖、历史待领奖。
2. 初次加载、首次失败、旧快照未同步、未出战宝宝、其他对局占用、正在结算。
3. 开局超时原请求恢复、领取超时原请求恢复、号源失败保留资格、正常栏满成功领神兽。
4. 人物被点名与宝宝被点名；下一回合/本回合；权威取消；重连后保留预告。
5. 今日已赚0/10/20时本场分别新增+10/+10/+0；日额度已满但历史待领余额仍非0；首次达到神兽资格但材料+0。
6. 领取成功、已拥有继续挑战、复刻0/3但有旧资格可领、复刻0/3已拥有、3/3未领又胜利、历史已领不能挑战。
7. 新设备无本机请求UUID，从详情恢复原在途开局/领奖；不能创建第二笔来替代恢复。

按客户端规范验证至少两种屏幕尺寸/安全区和长名字；时间、主按钮、预告不得被遮挡。中文状态不要只靠颜色区分，主按钮点击区域沿用项目可用尺寸。正式验收再逐项接真实状态和断线重连；截图与演示不替代联机结果。

## 9. 可直接交给 UI Codex

> 按服务端仓 `docs/design/battle-festival-beast-v1.md` 和本文件制作瑞兽迎春 UI。只做一张活动主面板、规则弹窗及既有战斗/结算界面的预告和进度扩展；一只神兽、一个难度、14天内累计三胜免费领取，不做每日任务或活动商城。复用现有道家Q版界面和现有宠物/场景资源。宝宝、材料、人物外观均跳现有页面；10元卡是人物易容，不能画成神兽皮肤。Gemini负责业务逻辑、源协议和非视觉适配，你负责布局、美术、状态表现和视图绑定。先完成第8节独立演示状态，再接正式契约；权威数据没到不得画成功、发奖或自行计次。核对预告在慢速人宠行动后兑现、本轮防御不跨轮、结束仍可领、未知请求恢复与普通栏满的专属赠送容量。不要修改服务端、正式配表或并发编辑Gemini负责的数据层；交付截图和真实/演示边界，不部署、不提交、不推送。
