# 首领试炼：轻量玩法 V1、UI 规格与双机交接

更新：2026-11-22。交付对象：Gemini 负责代码逻辑、协议和验证；另一台电脑的 Codex 负责 Unity UI、美术和交互表现。

**这是可据以开工的首发设计。本轮只更新文档，没有实现首领试炼，没有修改代码、协议、配置或客户端。下面的首测参数是设计起点，时长与平衡仍须实测。**

## 1. 首发定稿与阅读入口

用户方向：简单、好玩、不肝、小小氪金。核心体验是“看懂一次预告，安排自己和宝宝的两次行动”，让同一个首领因护卫不同产生不同打法。

| 项目 | V1 决定 |
|---|---|
| 一局内容 | 一场首领战，直接准备、开打、结算；不跑长地图、不清前置小怪 |
| 人数 | 1～5 人；单人带自己的宝宝即可体验，已有队伍按实际人数进入；无 NPC 助战、无专门匹配大厅 |
| 内容量 | 一个首领、回春／护势两种可选护卫版本、普通／困难两档；两种护卫是二选一 |
| 策略 | 选目标、看预告、防御或控制、安排人物与宝宝分工；不增加新操作资源 |
| 时长目标 | 普通每局 5～8 分钟、困难 8～10 分钟；这是从准备到结算的目标，不是倒计时或已测结论 |
| 日常收益 | 普通、困难均为胜利每人 10 份自选材料额度；全游戏 PVE/PVP 共用每天 20 份，不另开试炼上限 |
| 失败成本 | 无门票、无体力；试炼临时战斗状态满血满蓝开局，禁用真实背包消耗；失败可免费重试 |
| 小额消费 | 沿用既有易容等外观消费；默认形象可体验全部首领、护卫和难度；试炼不新增收费点 |
| UI | 挑战页、战斗页、结算页三个主界面，附机制说明、退出确认、既有材料自选弹窗 |

本版明确替代 11 月 17 日旧稿中的三项设想：① 困难首发不提高材料收益；② 不把试炼内血蓝损耗和倒地带回场景；③ 七个 UI 阶段合并为三个主界面内的状态，不另做七套整页。保留原稿的一首领、两护卫、人物与宝宝协作方向。

阅读顺序：玩法看第 2～6 节；UI 看第 7～12 节；现有能力与缺口看第 13 节；两台电脑分别复制第 14、15 节交接；验收看第 16 节。本文的 UI／机制编号只是策划标识，不是正式表 ID、错误码或 RPC 名。

## 2. 进入、组队与难度

### 2.1 准入

普通在基础战斗与宝宝功能开放后可见；复用已有功能解锁事实，不另设等级、战力、付费或每日任务门槛。首次正常通关任意护卫版本的普通后，本人解锁困难；没有额外首通材料礼包。资格记录须随结算可靠保存。

无宝宝可进入，显示“建议带上出战宝宝，与人物配合更轻松”，提供宝宝界面入口；不弹强制购买、不要求稀有宝宝。平衡基准是同档正常养成人物加一只普通出战宝宝，不承诺任意无输出组合都能过关。

开局由服务端检查在线、存档可写、未占用其他战斗、上局已释放占用、队伍与出战配置有效。场景中已倒地或处于其他禁止战斗状态时，先按场景规则解除；本玩法不能用于免费复活场景角色。

### 2.2 队伍与准备

- 单人选择难度和护卫后，一次点击“开始挑战”；不再点一次“准备”。
- 组队沿用当前社交队伍，队长选择难度和护卫，每人确认自己的准备，全部准备后队长开局；无需凑满五人。
- 困难要求每个成员都已解锁。每人的材料余额独立，拿满额度的成员仍能陪朋友打。
- 修改难度、护卫、成员名单、队长或任一成员的有效战斗配置时，撤销本次全队准备，提示变化原因。准备确认绑定同一版本的房间信息。
- 战中不补人、不换宠、不换装备或技能配置；断线、逃跑、倒地不重算怪物人数和数值。返回挑战页不解散原社交队伍。
- 从准备页离开仅取消本人准备、退出本次准备；离开社交队伍仍走既有队伍按钮与确认。

### 2.3 敌人数量

| 入场真人数 | 首领 | 所选特殊护卫 | 普通护卫 | 敌方总数 |
|---|---|---|---|---|
| 1 | 1 | 1 | 0 | 2 |
| 2 | 1 | 1 | 1 | 3 |
| 3 | 1 | 1 | 2 | 4 |
| 4 | 1 | 1 | 3 | 5 |
| 5 | 1 | 1 | 4 | 6 |

普通护卫只使用基础攻击，无治疗、召唤或独立预告机制，复用同类外观。始终只有一个特殊护卫，避免多人局叠成治疗墙。按入场人数和难度选固定数值档，不根据玩家装备自动追涨；玩家养成强了就应打得更轻松。

首发不加多波刷怪、随机词缀、排行榜、赛季通行证、专用货币、扫荡、连续自动开局或专属商店。

## 3. 一局节奏与胜负

```text
挑战页：选择普通／困难、回春／护势，查看今日额度
  → 单人直接开局／队伍全部准备后由队长开局
  → 开局确认中（仍在挑战页）→ 战斗页
  → 本方胜利／失败／本人退出／作废 → 结算页
  → 自选材料，或再来一局回挑战页，或返回原场景
```

开局请求结果未知时保留原请求并查询，不能重新创建另一局。返回原场景可以先收起结果页；新的挑战必须等上局权威终态和占用释放，不因关窗而假定结算完成。

正常胜负在回合末效果（包含合法复生）处理后，按双方仍存活且未退出的单位判定：敌方已全灭且己方仍有存活单位为胜利；己方全灭且敌方仍存活为失败；双方同时全灭按既有平局结算，不通关、无材料。全员暂时被控制、不能行动不等于全灭。只击倒首领时，余下护卫仍需处理；人物倒地但自己的宝宝尚在，仍可操作该宝宝，队友可以按既有技能规则救人。

指令窗口首测上限 25 秒，所有需要手动指令的单位提交完可提前推进，不强制等待满时长。首测回合上限为 20，先执行第 20 回合，再判断正常胜负；仍未结束则“回合耗尽”，无胜利额度。首版不加入残血狂暴、限秒秒杀或强制第三机制。

普通·回春版示例：第 1 回合看到首领点名，人物和宝宝可先压回春护卫；第 2 回合被点名者防御，另一单位继续输出或保护；第 3 回合可打断护卫治疗，也可接受一次回血、先恢复自己。护卫倒下后集中处理首领。决策有余地，不要求每一轮都选唯一正确答案。

## 4. 三种机制：能看懂，也有免费解法

### 4.1 M1 预告重劈

| 项目 | 首发规则 |
|---|---|
| 预告 | 第 1／4／7…回合指令开始前，公开下一回合的目标；第 2／5／8…回合兑现 |
| 目标 | 每次只点名一个合法敌方单位，人物和宝宝均可能被选；多人也不增加点名数量 |
| 伤害 | 单次物理攻击；受现有物攻削弱、物理减伤、护盾、防御等合法效果影响 |
| 行动预算 | 占首领本回合唯一正常行动；没有额外普攻；非重劈回合首领普通攻击 |
| 出手顺序 | **重劈是慢动作，在本回合普通行动序列结束后、回合末效果结算前执行。** 首领本轮从普通行动序列中移出，不重复行动 |
| 免费应对 | 被点名单位在兑现回合选择防御即可先建立防御；另一个自有单位可输出、治疗或提供保护 |
| 控制 | 按技能标签检查封物、封灵及无法行动状态；有效时取消本次重劈，不解控追补；不因首领身份统一免控 |
| 目标失效 | 目标倒地、逃跑或其他不再合法时取消，不秘密换打另一单位；预告轮被击倒即取消，即使稍后复活也不恢复本次点名 |

此处只给本试炼重劈定义慢动作，不修改全局防御优先级、加减速公式或其他玩法的排速。当前引擎的防御在动作执行时生效、回合末移除；上回合防御不能挡下回合重劈。慢动作是**待实现并验证的能力**，不能仅在 UI 中把图标排在最后。

控制有命中与抵抗，首领也可能在行动前被唤醒，因此“看到控制图标”不等于重劈已取消。UI 只消费服务端预告状态；重劈取消、目标失效、正常命中分别给出短提示。

### 4.2 M2 回春护卫

每三个回合有一次主动治疗，只给首领回血；其他回合普通攻击。普通在第 2／5／8…回合开始预告、第 3／6／9…回合执行，与重劈错开；困难改为第 1／4／7…回合预告、第 2／5／8…回合执行，与重劈重叠。

治疗占护卫本回合唯一行动，按正常速度出手。首测治疗量为首领最大气血的普通 8%、困难 10%，实际恢复量受减疗和缺失气血限制。首领已满血时恢复 0，已经倒地时取消，不改为复活或治疗其他护卫。

提前击杀、封灵、无法行动类控制可以阻止；封法仅限制法术攻击，不能当作治疗打断。接受一次回血也应有继续获胜的余地。一次治疗被取消后不追补，下一次仍按原节奏重新预告。普通合理低输出组合在完整治疗周期内必须仍有净进度。

### 4.3 M3 护势护卫

只保护自己，不给首领或全队套盾。第 1／4／7…回合用自己的唯一行动切换护势，物理防护、法术防护交替；其他回合普通攻击。开局无护势，第 1 回合实际出手后才生效；每次持续 3 回合，包含施放回合。开战快照显示“第 1 回合将开启物防”，以后下一次类型在上一回合开始前显示。

首测对对应伤害类型减伤：普通 30%、困难 40%，不免疫伤害、不附带控制抗性。允许按已有驱散规则移除，移除后等下一个预定切换回合才能重建；切换行动被合法控制阻止则跳过此次，下一次按原计划类型继续。

玩家可以换攻击类型，也可以暂时打首领、驱散，或用同类攻击继续磨。回春版更鼓励先处理护卫；护势版允许先击倒首领，再处理护卫。两种版本材料相同，不要求每日轮流打。

### 4.4 战斗公共规则

- 每个人物、每只宝宝各有一次正常行动；宝宝“主动攻击（含物攻、法攻）／障碍／辅助”是三个分类，不是三次行动。被动、追击、开场技按技能文档触发，不能主动多排一次。
- 展示全部已学且合法的技能，按分类浏览；不增加固定四技能或宝宝两技能装备槽。人物 A40 护盾与治疗各用自己的行动，不做过量治疗自动转盾。
- 主目标手选，额外目标按当前技能规则随机且不重复；确认前不画确定的随机副目标。用实际技能配置显示目标数和资格。
- 睡眠被实际伤害唤醒；冰冻期间不能行动、免伤并阻止新增障碍，合法治疗、保护、解除等遵循技能公用规则。不要提示“冻住后集火”。
- 加减速影响下一回合普通排速，本回合不插队；首领慢重劈由已公开的特殊时序处理。
- 自动操作复用现有自动战斗策略，按实际支持显示，不承诺它能聪明处理所有预告。手动选择、防御、查看机制均免费。关闭自动从下一个尚未锁定的行动窗口生效。

## 5. 不肝的资源、退出与重连规则

### 5.1 试炼临时状态

试炼保留玩家真实等级、装备、已学技能和出战宝宝成长；不是论剑的公共数值预设。只在本局战斗副本中初始化满气血、满法力、初始冷却与本局状态，再按既有开场规则生成本局增益；场景临时增益、药物和剩余冷却不带入。

试炼内不使用真实背包道具，不开放捕捉、换宠、付费复活或临时购买；恢复靠本局合法技能与效果。战斗 HUD 隐藏本玩法不可用的道具、捕捉、换宠入口，并在规则中说明。无需在失败后购买药品才能再来。

结算不得把临时血蓝、Buff、冷却、死亡与复活状态写回场景或永久宝宝；也不得退出时“恢复整份开局玩家快照”，以免覆盖同期合法资产变动。复用现有结算入口，由服务端锁定的试炼策略明确哪些状态可写：本玩法只有胜负结果、难度解锁、通关记录和共用材料资格等必要事实可落地。

没有通用掉落、经验、金币、捕捉收益或击杀任务计数，避免额度拿满后出现隐藏刷取路线；不把试炼目标伪装成世界怪物。通关记录首发仅保存各难度／护卫是否通关，不加最快排行、每日连续打卡奖励或独立成就货币。

### 5.2 退出

首发采用**确定退出**：人物选择“退出试炼”并二次确认，无随机逃跑失败、不消耗道具。以服务端回合状态定序：指令窗口尚未锁定时先移出本人和本人宝宝；回合已锁定时先完整结算当前回合（含慢重劈、回合末效果及胜负判定），若已产生终局则正常终局优先，否则执行退出。客户端是否正在播放动画不决定先后顺序。

退出生效后取消本人及本人宝宝尚未执行的行动，已执行动作不回滚；不取消队友和队友宝宝的行动。本人不获本局材料及通关记录，其他人继续战斗；全员退出结束本局。人物已经倒地时仍可主动退出并带走宝宝。重复请求只查询原玩家原战斗的退出结果，不能误退出下一场。此规则是试炼专用待实现行为，不把当前通用随机逃跑直接改名冒充。

### 5.3 断线与恢复

断线不自动判逃跑、不暂停全队。截止时未提交动作走现有战斗自动补全；重连后恢复同一战斗、回合、宝宝归属、预告、已接收指令和自动状态，不能再发一套重复指令。断线期间队伍正常获胜，未退出成员仍按正常资格结算。

战斗实例失效按既有作废规则返回，不伪造胜利、不扣奖励额度；临时状态直接随实例结束。显示“本次试炼未完成，可重新挑战”。战斗已结束但玩家结果尚未可靠保存时显示结算确认中，按原战斗身份查询；不能以“重试”再发一次材料。

## 6. 免费收益与小额付费边界

### 6.1 共用材料账

沿用已经存在的材料系统：PVE 获胜、匹配 PVP 正常完成计额度，合计每天 20 份。**本试炼普通、困难都是每次合格胜利 10 份，不新增一份 PVE 日上限，也不采用困难额外 5 份或 25 份上限。** 最新“简单、不肝”要求优先，因此旧稿困难提高养成收益的设想不进入 V1。

| 情况 | 试炼材料额度 |
|---|---|
| 当日未获得额度，试炼正常获胜 | +10，可自行选打造材料／强化石分配 |
| 当日其他来源已获得 10，再试炼获胜 | +10，共享当日合计 20 |
| 当日已获得 20，再获胜 | +0，可练习／陪朋友；仍能完成本人正常通关记录 |
| 本人倒地，但仍在队且队伍胜利 | 与存活成员同资格，宝宝倒地不扣资格 |
| 本人退出、失败、回合耗尽、作废或零回合结束 | +0，不消耗未来胜利资格 |

按 scene 首次应用权威结算的游戏日计入，每日 UTC+8 05:00 换日，客户端显示服务端提供的下次刷新时间。战斗跨日、迟到结算不按开局日期追溯；时钟回拨不得重开额度。已赚未领余额跨日保留，未参加的日额度不积攒、不补领，首发没有补签或追回欠账入口。

20 份是打造材料与强化石的合计，不是各 20。每次自选领取批次为 `min(20, 当前可领余额)`，实际由服务端提供；两个材料数量之和必须等于本次批次。额度获得和材料入包是两个步骤。已有余额可能大于 20，不把“当日已获得”与“全部可领余额”画成同一个数。领取后的绑定／流通属性沿用统一装备经济正式规则，试炼不另定拆分或交易资格。

普通两次胜利的目标为约 10～16 分钟，给调整搭配和失败重试留出余量；仍须实测从进入到领取的总时长。全游戏“每天约半小时目标 20 份”是设计目标，不要求玩家每天做满，不把累计 300＋300 的养成目标转成强制出勤任务。

### 6.2 小小氪金

小额消费沿用既有人物易容；现行形象卡为 10 元，具体价格和使用合同以易容系统及统一商城正式配置为准。本稿不把形象卡改写为人物永久收藏，也不发放未定的免费人物。

默认形象与付费形象在试炼中的规则、胜利资格、材料上限相同。试炼入口、失败页、结算页不新增购买按钮；不卖门票、额外每日额度、跳过机制、额外行动、保底抵抗或付费复活。其他养成消费服从装备与商城统一设计；材料售价未定，本稿不承诺“0.1 元一份”或新增 SKU。

## 8. U01 挑战页：内容、按钮与状态

默认选择普通、回春；再次进入记住本地上次选择，但资格和配置以本次服务端返回为准。左右选择不弹全屏确认，也不自动开局。

内容包括：玩法名、首领与选中护卫预览、普通／困难说明、预计时长、机制短句、本人有效出战宝宝、队伍名单及准备情况、当日已获得／20、全部可领余额、刷新说明。装备、技能、宝宝三个小入口打开现有界面，关闭后返回此页并刷新准备状态。

| 按钮／控件 | 可用条件与动作 | 不可用／反馈 |
|---|---|---|
| 普通／困难 | 单人或队长在未开局时可选；切换后刷新规则并撤销准备 | 未解锁困难显示“通关任意普通试炼后开放”；队员显示“由队长选择” |
| 回春／护势卡 | 只选一种；卡上直接显示机制与相同材料收益 | 已选描边＋勾选；开局确认中锁定 |
| 查看机制／玩法说明 | 打开 C01，任何准备状态可查看 | 加载失败给重试；不遮住页面返回能力 |
| 装备／技能／宝宝 | 未开局且本人未锁定配置时进入既有面板 | 已准备先取消本人准备；已开局显示不可调整 |
| 单人“开始挑战” | 准入通过且数据可信，点击后发起一次开局 | 无宝宝只给行内提醒；失败展示具体原因；提交中“正在开战…” |
| 队员“准备／取消准备” | 切换本人准备；队长也先确认本人准备 | 队伍资料不可信或有禁入原因时不能准备，显示原因 |
| 队长“开始挑战” | 包括队长在内全部准备、名单版本一致时可点 | 提示“等待 2 位队友准备”等具体原因；未准备时主按钮为“准备” |
| 队长“取消准备” | 本人已准备时的次按钮 | 开局已被接受后不可撤销开局 |

| 返回 | 普通浏览直接返回，已准备先撤销本次准备 | 开局结果未知可收起面板，但保持恢复任务，不能重复开局 |

状态：加载中显示占位，不显示假 0；加载失败“暂时无法读取试炼信息，重试”；条件未达成显示具体条件；无队伍按单人；部分队友离线显示对应头像状态；准备失效给一条变化提示；今日额度已满显示“今日材料已拿满，仍可练习或陪朋友”；开局未知显示“正在确认是否已进入战斗”，提供“查询进度”，不再次显示可点的开局按钮。

## 9. U02 战斗页：指令和敌方预告

### 9.1 预告与战场

每条预告显示来源头像、动作名、发动回合、目标、伤害／治疗类型。可点开 C01 查看一句反制。最多两条危险机制并排，长文进入展开区，不遮住被点名单位血条。

预告状态：即将发动 → 本回合发动 → 已发动／已取消／目标失效；断线期间标记“同步中”，不本地推算取消。重劈对象头像和战场单位用同形标记关联；物法护势显示类型、剩余回合和可驱散标记，不能画成免疫。

播放可缩短非关键信息停顿，沿用既有表现能力；跳过表现不能跳过服务端回合、重发动作或提前提交下一回合。首发不做全 PVE 录像系统，只展示本局已有事件支持的提示。

### 9.2 人物／宝宝操作

| 控件 | 行为与限制 |
|---|---|
| 人物／宝宝页签 | 只控制本人两单位，显示各自“待选、已选、提交中、已接收、无法行动、倒地、退场”；切换保留未提交草稿 |
| 普通攻击 | 进入合法目标选择；选中后显示动作摘要，不立即发出 |
| 技能分类／技能 | 读取当前合法技能；显示消耗、冷却、封印或其他不可用原因；技能详情不占正常行动 |
| 防御 | 选定本单位防御草稿；说明“本回合行动时生效”，被重劈点名时提醒当回合防御可先于重劈生效 |
| 目标／取消选择 | 只允许合法主目标；取消回动作列表，不撤销已被服务器接收的行动 |
| 确认行动 | 当前单位草稿完整且窗口有效时提交；接收后锁定该单位本回合动作，可自动转到另一个待操作单位 |
| 自动开／关 | 调用既有自动控制，等待权威回显后改状态；不取消已锁定动作，不触发连续开局 |
| 机制说明 | 打开 C01，仍能看到剩余指令时间 |
| 退出试炼 | 打开 C02；不把按下按钮当作已退出 |

首发提交被接受后不能修改该单位本回合行动；下一回合再选。人物和宝宝分别确认，不以一次提交伪装两单位都成功。请求携带真实 `battle_id`、`round_index`、`actor_id`；手动宝宝用战斗运行时单位 ID，不能把宝宝模板 ID 当作单位。

达到倒计时边界后停止本地提交，等待服务端补全与回合结果；不能因最后一帧点击就显示已接受。超时或断线导致提交结果未知时，以原动作查证／按既有幂等契约恢复，不自动换目标、换技能或生成新行动。服务器已转入下一回合时丢弃旧草稿，旧响应不得锁住新回合。

人物倒地但宝宝尚存时默认切宝宝，保留人物倒地信息；人物受控时技能按钮按实际控制禁用，不把整个宝宝栏一起禁用。合法复活后从服务端允许行动的回合恢复操作，不补发错过的行动。

## 10. U03 结算页：先确认，再展示到账

结果展示分两个层次：战斗胜负已确定；玩家个人结算是否已确认。胜利大字可先出现，资产区域在确认前只显示“奖励结算中”。不能把 `BattleEndS2C` 的原始结算意图直接当作材料已入包。

| 状态 | 展示 | 按钮 |
|---|---|---|
| 获胜、结算确认中 | 胜利；正在确认本局材料额度；不先加数 | 查询进度、返回；再来一局等占用释放 |
| 获胜、新增额度已确认 | “本局新增 10 份可领取额度”，另列当前余额、今日已获得 | 自选材料、再来一局、返回 |
| 获胜、当日已满 | “今日材料已拿满”；正常记录通关；有历史余额仍显示余额 | 有余额时自选材料；再来一局、返回 |
| 失败／回合耗尽 | “未能通关”及简短原因；“免费重试，试炼内满血满蓝开局” | 调整配置、再来一局、返回 |
| 双方同时全灭平局 | “双方力竭，本次未通关”，无材料额度 | 调整配置、再来一局、返回 |
| 本人主动退出 | “已退出试炼，本人及宝宝已离场，本局无材料”；多人注明队友继续 | 返回；待本人占用释放且队伍可用后才能再开 |
| 作废 | 本次试炼未完成；无材料，不扣后续胜利资格 | 重新挑战、返回 |
| 请求失败／结果未知 | 保留已知结果；“正在确认结算，请稍后查看” | 查询原结果、返回；不出现重新发奖 |

“再来一局／重新挑战”回 U01，保留所选难度与护卫、刷新资格与队伍准备；不自动拉队友进入战斗。“调整配置”先回 U01 再打开对应既有面板。不要在失败页出现充值、购买药品或付费复活。

本局材料增量必须来自该玩家该 `battle_id` 的可靠结算记录；当前总余额的前后差不能充当本局增量。正式接入需补齐该事实，未具备时只显示“结算完成，查看当前自选余额”，不猜 +10。即便全局额度或领取余额随后改变，历史结果也不能重写成另一份本局奖励。

`GetRecentBattleResults` 用于读取同一场个人结果，`AckBattleResults` 仅确认已读；领取材料调用独立的材料领取接口。当前场景血蓝从场景状态刷新，不能套用旧战斗结果；新战斗开始后迟到的旧回包仅归档到旧战斗。

## 11. 弹层、通用按钮状态和文案

### 11.1 C01 机制说明

三张短说明：重劈“看点名，在发动回合防御”；回春“护卫要治疗首领，可先击杀或打断”；护势“只保护护卫，可换目标或换伤害类型”。展开后可查看第 4 节完整边界，关闭回到发起位置。首次进入只给可跳过的一次提示，不强制每次阅读。

### 11.2 C02 退出确认

标题“退出试炼？”；正文“你和自己的宝宝将退出，本局不获得材料。队友会继续战斗。”单人去掉队友句。按钮“继续战斗”（默认焦点）、“确认退出”。确认提交中只允许查询，不重复发起；若本局终局已先到达，关闭弹层进入正常结算。

### 11.3 C03 材料自选

使用正式材料名、图标、拥有数量，显示“本次可分配 X 份／全部可领 Y 份”。打造、强化两行各有减号、数量、加号；默认沿用玩家上次偏好，首次默认各半，仍须用户确认。调整范围为 0～本次批次；任一改动同步另一项，合计始终为批次；输入非法数值则提示并禁用确认。

| 按钮／状态 | 规定 |
|---|---|
| 加减／数量输入 | 只编辑本地分配；提交中锁定；不读取客户端背包猜余额 |
| 确认领取 | 分配有效、余额可信、无恢复请求时可用；提交原请求身份与领取版本 |
| 领取处理中 | 显示进度，禁止连点；尚无可靠确认不显示“已到账” |
| 领取已执行但尚未确认保存 | “领取结果确认中”；保留原分配，不再开新领取 |
| 确认成功 | 显示两种实际材料数量，刷新背包、余额；有剩余余额可再开始下一批 |
| 背包不足／规则拒绝 | 不扣额度；可打开既有背包整理后重新查询；**材料自选不自动转邮件** |
| 余额或批次变化 | 提示“可分配份额已更新”，刷新后让用户重选；不静默改提交数量 |
| 超时／未知 | “正在确认领取结果”，按原请求重试／恢复；关闭后仍保留恢复入口 |
| 无余额 | “暂无可领取材料”，可关闭；不能本地补出 20 份 |

通用战斗掉落可能走溢出邮件，但本试炼首发不产该类掉落，且既有材料自选是背包严格事务；因此不为试炼制造“材料已转邮件”演示成功态。

### 11.4 通用表现

每个主按钮至少有默认、悬停／聚焦、按下、禁用、处理中五态；可选卡增加选中，结果区增加成功、失败、未知。禁用要给短原因，网络未知不能伪装普通失败。提示尽量行内，只有退出使用二次确认；不连续弹多个模态窗。

## 12. 页面状态、数据与事件契约

主流程：`读取信息 → 可准备 → 开局确认中 → 战斗指令／战斗播放 → 个人结算确认中 → 已确认结果`。每阶段可叠加连接恢复，但不能因此回到可创建另一局的状态。页面开关只是显示状态，战斗、结算和领取各有自己的权威生命周期。

| 数据组 | UI 必需内容 | 权威与恢复要求 |
|---|---|---|
| 玩法信息 | 可用难度、解锁原因、护卫选项、规则说明、正常时长提示 | 正式配置；缺数据不猜可用 |
| 准备快照 | 本次准备身份／版本、队长、成员、各自准备与禁入原因、选项 | 开局提交复核同版；队伍变化使准备失效 |
| 开局结果 | 请求身份、接受／拒绝／未知、权威战斗身份 | 同一开局不能创建两场；拒绝给正式错误原因 |
| 战斗快照 | 战斗和回合、阶段及截止时刻、单位归属、血蓝、状态、技能、已接受动作、自动状态 | 重连一次恢复当前真相；不凭客户端动画推权威阶段 |
| 敌方意图 | 来源、固定目标、动作类型、预告／兑现回合、当前状态、护势类型和剩余时长 | 服务器创建、取消和重放；客户端不预测随机目标 |

## 16. 首测参数与验收清单

### 16.1 数值制作约束

第 4 节节奏、治疗比例和护势比例是本稿首测配置；最终怪物 HP、攻击、防御、速度须引用当前正式成长曲线，逐人数档输出一份可复现配置，不凭本稿杜撰玩家基础数值。数值未测不阻碍 UI 制作，但阻止宣称战斗平衡完成。

基准使用同档正常装备、常见已学技能和普通出战宝宝，覆盖人物物攻、法攻、障碍、辅助四方向与有输出的合理搭配；不要求满强化、指定稀有宝宝或必学 A40。至少测试纯物理、纯法术、人物辅助＋输出宝宝。

- 普通基准单位满血遭一次未防御重劈应能存活；正确防御后再承受同轮合理普攻压力仍应有恢复机会。困难提高压力，但正确防御不能仍被无解一击击倒。
- 普通机制错峰，困难最多同时应对重劈＋治疗两项；接受一次回血或控制抵抗不能必败。不要用血量翻数倍延长困难。
- 普通合理组合稳定推进、不被周期治疗无限抵消；护势不会让单一伤害类型无法通关。
- 对 1～5 人分别记录回合数、总时长、重试时间、操作等待占比和失败点；普通两胜＋合理调整重试力争在半小时内拿满共享日收益。
- 若达不到目标，先调敌方血量、基础伤害、治疗量和演出停顿；不新增养成门槛或出售解决方案。

## 17. 设计取舍与执行边界

需求分析：玩家希望短时间获得有意思的回合决策，个人或少量朋友随时能玩；两个制作端需要同一份可执行规格。策略深度来自已有技能、宝宝与目标选择，不靠增加日课数量。

设计取舍：用两种护卫复用同一首领和战场，降低资产与教学成本；普通承担日常收益，困难提供自愿挑战；失败无消耗让尝试搭配有价值；三个主页面降低制作工作量；沿用共用材料账和商城避免新增经济系统。

代价与风险：资源隔离、慢重劈、准备和确定退出需要补代码，不能假装配表即可完成；这些接缝带来的是玩家可理解的规则，按第 13、16 节完整验证后才能开放。简单指玩法和界面清楚，不意味着省略资产一致性和恢复。

两端执行顺序为“先契约与状态样例 → UI 离线制作和逻辑单人闭环并行 → 组队困难 → 联调与平衡”。Gemini 与 UI Codex 以任务文件边界协作，任何新增需求先写回本文，再调整契约；不要在一台电脑的代码里私自改变奖励或难度规则。
