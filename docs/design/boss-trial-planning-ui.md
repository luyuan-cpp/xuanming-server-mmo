## 2. 首版范围与参与条件

### 2.1 核心体验

一局是一场完整的回合制首领战：看懂敌方预告，在人物与宝宝的有限行动中选择输出、控制、防御、治疗或护盾。无需先接每日任务，不靠陌生玩家在线才能体验主要内容。

| 项目 | 首版基线 |
|---|---|
| 模式 | 首领试炼，一个常驻入口 |
| 人数 | 1～5 位真人，单人立即进入准备，已有队伍按当前人数开战 |
| 控制权 | 各自控制本人人物和本人的出战宝宝；队长负责选择与开局，不接管队员 |
| 助战 | 首发不增加 NPC 助战；宝宝、自动战斗和队友不是 NPC 助战系统 |
| 内容量 | 一种首领、两种护卫版本、普通／困难两档，尽量复用现有场景和模型 |
| 单人阵容 | 一只首领加一只所选类型护卫；己方以人物加自己的出战宝宝体验完整配合 |
| 多人阵容 | 始终一只首领；护卫数量、组合、血量和普通伤害按入场人数档配置 |
| 时长 | 普通 5～8 分钟、困难 8～10 分钟，含准备和结算的试玩目标，不是已测结果或强制等待 |
| 重复体验 | 更换护卫版本、难度、人物与宝宝配合；同局重连不换阵容 |

首发不同时制作爬塔、长地图连战、随机路线、大量独立首领、助战养成、专属货币或专属商城。原型可使用既有图标和文字占位，本稿不要求新关卡资产。

### 2.2 准入和解锁

- 普通入口在基础战斗与宝宝功能可用后开放；具体最低等级／前置条件由后续配置确定。原型用“已开放”和“条件未达成”两套数据，不写死等级。
- 本稿采用“本人通关普通一次后可选困难”；组队困难要求每位成员满足本人资格，不能仅队长解锁就带全队绕过。具体解锁记录是待接入能力。
- 不设职业配额，不要求同时有物攻、法攻、控制、治疗四种真人，也不把满强化作为普通准入条件。
- 无出战宝宝显示“未出战宝宝，建议先选择”，提供已有宝宝界面入口；不自行追加“必须拥有稀有宝宝”的门槛。能否无宝宝直接挑战由正式准入配置返回，UI 不自行封锁或保证能过。
- 开局必须由服务端复核在线、战斗占用、角色状态、名单、难度资格与合法出战配置。不能同时打另一场或在上一场结算未完成时重开。
- 不增加强制每日接取、每日交付或强制看教程。首次机制说明可跳过，战斗中始终能重新查看。

### 2.3 人数与难度是两个维度

人数档解决“几个人参加”，难度解决“同时需要处理多少机制”。不能用组队人数自动替代难度选择。

人数在开局原件中锁定，不按装备强弱追着抬高敌人；开局后退出、断线、人物倒地、宝宝退场都不触发降血、补怪或奖励加倍。加入新成员须等下一局，战中不补人。

多人组合不能简单复制多只治疗护卫，叠成打不动的治疗墙。各档最多同时出现的危险机制数量单独配；首版普通错峰，困难最多两种同时需要关注。具体 2～5 人护卫名单和系数是待定配表，原型不把“每人一整组怪”当作试炼规则。

## 3. 一局流程与可操作示例

### 3.1 主流程

```text
玩法入口 → 选择难度／护卫版本 → 单人准备 或 当前队伍准备
         → 查看机制／调整配置 → 准备确认 → 正在开战 → 战斗
         → 胜负已定／结算处理中 → 结算确认 → 再战回准备 或 返回入口
```

“再战”只发起下一局准备，不自动开战；多人需重新准备。返回入口不自动解散现有社交队伍。

### 3.2 单人普通·回春版本的一次体验

1. 玩家从入口选普通与回春护卫，查看“首领预告物理重击；护卫会治疗首领”。收益区显示本人的当前资格，不先承诺材料已到账。
2. 准备页确认当前血蓝、出战宝宝和已学合法技能；可以先查看“输出人物＋保护宝宝”或“辅助人物＋输出宝宝”的搭配说明，不强制套用。
3. 开战第一轮优先压护卫。服务端公开下一轮重劈的目标与发动回合，玩家能在完整的提交窗口内考虑对应行动。
4. 若重劈点名人物，可在重劈兑现回合、且防御能先于攻击生效时由人物防御、宝宝继续攻击；若点名宝宝，则考虑宝宝防御、人物提前提供合法保护。低速单位应在准备轮布置能持续到重劈时的保护，不能假定上轮防御自动跨轮。也可以安排足够早的封物与后续输出。控制可能抵抗，不能把这条路线标成必胜。
5. 护卫开始预告治疗时，选择提前击杀、封灵、减疗，或者暂时保命并接受敌方回血。若人物在治疗，则本轮不能再免费施放 A40 护盾；宝宝同样只能选一项正常行动。
6. 护卫倒下后集中处理首领；按己方资源决定继续输出还是先恢复。首领的重劈仍需预告，不在残血时突然无提示秒杀。
7. 胜利后先看到结果，再看到服务端确认的奖励和战后状态。选择再战会回准备页，保留所选难度与版本，重新读取血蓝和收益资格。

这是决策示例，不是固定脚本或必胜顺序。伤害、速度、技能资格和控制结果均会改变实际过程。

## 4. 三种机制及反制

所有名称都是工作名，可换正式美术命名；机制编号仅用于本稿引用。

### 4.1 M1：破阵首领·预告重劈

| 项目 | 规则 |
|---|---|
| 提示内容 | 首领、重劈、物理伤害、发动回合、被点名单位、可考虑的反制 |
| 预告时点 | 本稿建议在 R 回合指令开始前公开 R+1 回合重劈；至少留完整 R 回合准备，不在同轮最后一秒突然预告 |
| 单人压力 | 一次点名最多一个己方单位，人物或宝宝均可能被点名；多人目标数另按人数档配置 |
| 攻击反制 | 普通伤害、物攻削弱等可减轻压力；高输出可争取提前结束，但普通不要求靠爆发跳过机制 |
| 控制反制 | 有效封物／封灵或无法行动类控制是否阻止这次动作，以对应技能标签和行动时点为准；不统一免控 |
| 辅助反制 | 防御、提前恢复、合法护盾／保护，选择与敌人伤害类型匹配的手段 |
| 被阻止后 | 服务端确认本次重劈取消；不会在控制解除后无预告补发。下次重劈重新预告 |
| 目标失效 | 已锁定目标倒地／退场等不再合法时，本次对该目标的重击取消，不偷偷换打另一名单位 |

封物成功但晚于重劈出手，不能撤回已经造成的伤害；睡眠在动作前被群攻打醒，也不保证仍能阻止重劈。UI 只能依据服务端的预告状态显示“已取消”，不能看到控制图标就自行取消预警。

当前引擎在防御动作执行时设置防御状态，且回合末摘除；因此 R 轮防御不能当作 R+1 轮重劈的保护。**R 轮用于提前治疗补足气血，或布置能持续到 R+1 轮重劈时的护盾／增益；若选择防御抵挡重劈，应在 R+1 轮选择，并要求防御在重劈前实际生效。** 治疗不产生持续保护；护盾／增益必须核对剩余时长。

防御优先级、低速单位的可用保护和重劈出手顺序需与正式战斗时序一起验收，属于真实开放的阻塞条件。本稿不私自修改全局防御优先级；演示只能在明确“防御已生效”的场景显示成功减伤，不能承诺点防御必挡。普通数值应给未成功阻止重劈的合理阵容保留恢复机会。

### 4.2 M2：回春护卫·准备治疗

护卫准备给首领回血时公开受益目标、发动回合和“治疗”标签。建议采用有间隔的主动治疗，不采用常驻无限回血光环。

- 物理、法术都可以集火护卫，不设某一伤害类型完全无效。
- 封灵或使其无法行动的合法控制可阻止对应行动；**封法只限制法术攻击，不能默认阻止治疗**。
- 减疗可以降低收益；接受本次回血、先处理重劈也是合法选择。
- 首领已满血、倒地或退场时，按预告锁定的目标规则处理，不暗中换目标。无有效治疗量时显示“未恢复气血”，不伪造治疗飘字。
- 低输出但合理的单人搭配，在一个完整治疗周期内仍应有正向击杀进度；护卫治疗不能无限抵消其所有输出。

本次治疗被阻止后取消，不在解控后追补。多人不堆叠多个同轮大治疗；困难可以让一次治疗预告与一次重劈预告重叠。

### 4.3 M3：护势卫·物法防护轮换

护卫拥有偏物理或偏法术防护的“护势”，显示伤害类型、剩余时长及是否可驱散；轮换前应明确提示下一种护势。

- 护势是减伤／防护偏向，不是伤害免疫，不新增强制物法双修门槛。
- 可以换另一类攻击、攻击首领、驱散可驱散的护势，或先控制护卫调整节奏。
- 纯物理、纯法术搭配仍可稳定造成有效伤害；轮换间隔、减伤幅度待试测。
- 本稿按可驱散增益设计；被驱散后不在同一行动无条件补回，要等下一次合法生成时机。
- 护势不顺便增加全部控制抗性。若有特殊抗性必须独立展示，不能把“物理减伤”标成“抗封物”。

### 4.4 通用控制与目标边界

- 主目标由玩家选择，其他目标随机且不重复；人物群攻 5、常规辅助多为 7；宝宝物法攻击 2、辅助／多数障碍 1，按技能条目具体规则显示。
- 不预画已经确定的随机副目标，不要求玩家依次点满全部受益者。目标不足不重复打同一个凑人数。
- 睡眠会被伤害唤醒，群攻可能打醒护卫；冰冻期间不能行动、不能受伤、不能新增障碍。冰冻用于恢复和争取节奏，不能提示“冻住后集火”。
- 控制逐目标按对应条目判定，不新增道行／武学，也不因首领身份统一免疫所有控制。
- 加减速只影响下一回合排速，当前回合顺序不重排；本稿不新增即时插队机制。
- 首领防无限连控、控制时长、驱散数量、冰冻边界等通用问题依赖技能线，不在本玩法另写第二套公式。

## 5. 难度、时长与免费收益

### 5.1 难度与数值要求

普通以理解和执行单个机制为主，危险动作错开；困难以资源分配和双机制取舍为主，不把普通血量简单翻数倍。

验收使用同档合理配置的四类人物方向，分别搭配可用宝宝。保证每种人物方向都有可玩的搭配，不承诺辅助人物加辅助宝宝等任意组合都能同速通关。

| 需要验证的数值 | 通过方向 |
|---|---|
| 普通重击 | 正确使用防御／保护的同档合理气血目标可承受，不要求满强化；一次控制抵抗不直接等于失败 |
| 普通续航 | 合理控辅人物配输出宝宝能逐步击杀，不陷入永久互相治疗 |
| 困难双机制 | 可放弃处理其中一个，承担可恢复的代价；不要求单人两次行动完成三件必要事项 |
| 人数缩放 | 1、2、3、4、5 人各有可行组合；固定一只首领，治疗不随人数堆成墙 |
| 输出差异 | 物理、法术各有合适决策，纯某类输出也有通路，不通过免疫逼迫付费改装 |
| 时间 | 统计进入、准备、战斗、失败恢复、结算的总耗时及回合数，快局不靠强制等待凑时长 |

当前手动提交窗口上限为 25 秒，全员就绪可提前推进；这不是每回合必须等满的播放时长。试炼回合上限、超时结果、各档伤害／血量／速度／治疗参数仍待定；原型可演示超时失败，正式以服务端原因区分失败、平局和作废。

### 5.2 与全游戏预算对齐

装备线已确认整个游戏每天约半小时目标 20 份自选材料，打造材料和强化石合计，不是各 20 份。PVE 与 PVP 的主养成预算共享，试炼不再另领一份日上限。

两次主要奖励各 10 份仍是组织建议；困难当日额外 5 份仍待确认。本稿不把次数、重置时间、每日 25 份、材料价格或商城入口写成已定。UI 读取统一收益资格、剩余额度、适用奖励和刷新说明，不能自己按本机日期清次数。

普通通关应能获得关键成长材料，困难提高同类收益或效率，不独占推进普通养成所必需的材料。奖励额度用完后仍可练习，入口明确显示“本次无主要养成材料奖励”；如将来还有其他奖励，必须来自真实配置，不自行赠送。

本稿普通 5～8 分钟与装备页的 8～10 分钟组织建议是不同试玩目标，尚未实测。不能因局长更短自动多送两次材料，也不能承诺困难额外奖励必然塞得进半小时。正式开放前统一验证全游戏预算与失败余量。

## 6. 失败、退出、断线与结算

### 6.1 失败和再战

- 失败不发通关材料，不扣成功奖励资格；已实际消耗的合法道具、血蓝按战斗结算，不因为失败全部回滚。
- 先沿用真实战后状态。准备页显示血蓝不足，可打开已有补给／宝宝管理界面；不暗中免费回满，不新增付费复活或付费继续挑战。
- 上一局结果未确认、战斗占用未释放时，“再战”不可用。可以返回普通界面查看状态，但不能利用关面板绕过占用。
- 再战生成新局，重新确认配置和名单；重连、补拉、重复点击不是新局，不重新抽奖励。
- 失败页展示已有事实，例如“第 6 回合，重劈命中后倒地”；不存在对应记录时只显示失败和通用机制说明，不编造失败诊断。

### 6.2 退出

本稿采用战斗内“逃跑”动作，不把关闭弹窗、返回上一层或退出应用等同逃跑。逃跑可能失败；成功与否由服务端判定，不在客户端投骰。

**目标规则：本人逃跑成功时，本人的出战宝宝同步离场；本人本局不获通关材料。** 这是必须补齐的服务端行为：当前实现只标记人物逃跑，尚未同步移除宝宝。正式接入前不能仅做 UI 隐藏宝宝来假装已经撤离。

队长不能替全队逃跑。其他成员可继续，敌人数值保持入场档位；最后一位参战者及其宝宝退场后结束该方战斗。主动退出者不得以重连重新加入或恢复奖励资格，结果与占用释放仍等服务端确认。

逃跑按人物的合法行动时点结算。若宝宝已在本回合先行动，其已发生效果不回滚；人物逃跑成功后，尚未执行的本人出战宝宝行动取消，不影响队友的宝宝。失败时宝宝继续依原合法指令执行，不额外获得一次行动。该联动同样属于待补规则。

### 6.3 断线、托管和作废

- 断线不算主动退出。战斗继续，未提交的行动依规则托管；已接受的手动行动不会因断线被重复执行。
- 重连拉取当前回合、单位状态、已提交情况、预告和结算阶段，不回到第一回合，不重播一长串旧操作强迫玩家等待。
- 手动宝宝接入后，其超时／断线默认行动必须与本人控制权、每回合一招共用同一校验。现有自动宝宝只是当前事实，不代表新规则已完成。
- 无法确认房间是否存在时显示“正在确认战斗状态”，不能立即宣称失败或免费重开。服务端确认作废后再展示作废原因及真实处理结果。
- 作废不发通关奖励、不消耗成功奖励资格；资产和道具按作废结算契约处理，不由 UI 自行退款或承诺全额返还。

### 6.4 胜利和到账

首版目标：队伍胜利时，未主动退出的参战成员获得各自资格对应的一份奖励，包括倒地成员和仍在托管的断线成员，不按伤害排行榜剥夺辅助奖励。这与当前“本人存活且未逃跑才给奖”不同，需要服务端改规则。

胜负确定、奖励资格核定、资产到账、邮件投递是不同事实。结果页区分“胜利，结算中”“已到账”“待邮件投递／已转邮件”“奖励额度已用完”“主动退出无奖励”等，不把未知状态显示成零奖励。

不增加手动领材料按钮。奖励自动结算；“确认／返回”只关闭结果，“已读确认”也不是领奖。重连和重复结果通知按同一场战斗去重，不重复发材料。

共享额度在服务端结算时串行确认；一个玩家在另一玩法刚用掉额度时，本局显示最终实际资格，不能各入口分别算余额。重试和跨日归属须由统一预算规则提供，本 UI 不自行扣次或返次。

### 7.2 通用布局与操作规则

- 延续项目现有美术风格，以信息层级、状态和操作路径为本稿交付重点。横屏是本稿制作假设；已有客户端规范另有要求时沿用其规范，勿为本玩法更改全局横竖屏。
- 原型可用 1920×1080 参考画布，采用锚点与容器；检查 16:9、20:9 和 4:3。窄屏缩小预览／折叠次要详情，不裁掉开始、提交、取消和预警目标。
- 关键操作位于安全区内，装饰可延伸至边缘。触屏主要按钮按实际设备可稳定点击设计，不把小图标的可见面积等同点击面积。
- 信息用文字＋形状／图标表达：已准备用勾与文字，锁定用锁与条件，物法伤害用标签，不只靠红绿区分。
- 字号与文本区域支持长名字、两行原因和放大显示。收益条目可换行，不能以省略号隐藏“无奖励”“结算中”等关键区别。
- 触屏单击可完成全部操作，不依赖悬停；鼠标可显示辅助提示。支持键盘焦点和返回，已有手柄支持时沿用导航，不为本轮新增输入框架。
- 最上层弹窗独占输入，关闭后焦点回到来源按钮；默认焦点不得落在逃跑确认等破坏当前战局的按钮。
- 返回键优先收起详情／目标选择／确认框。战斗页无“暂停战斗”按钮；查看详情、打开设置均不停止服务端计时。
- 通用按钮有可用、选中、不可用并附原因、发送中、等待确认五种状态；发送中防连点，不用动画结束当服务器确认。
- 页面数据为空、正在加载、请求失败、能力未接入四种状态分开。未知数值显示“—／正在获取”，不假显示 0。
- 状态按服务端更新刷新；倒计时可本地插值显示，但归零只表示等待服务端推进，不由客户端判回合或胜负。

## 9. U02：准备页

### 9.1 信息区

上方显示首领、难度、护卫版本、人数档与预计时间。左侧是成员列表；右侧是本人的人物／宝宝卡及机制摘要；下方显示本人的奖励说明和主要按钮。

成员卡包含昵称、队长标志、在线／离线、准备状态、配置同步状态。列表按稳定成员身份渲染，不能把第一个卡片永久当作队长。本人卡展开当前血蓝与出战宝宝；他人的详细属性、技能和库存仅显示服务端已授权公开的数据，不猜测或请求私有背包。

本稿采用保留当前状态的重试规则：血蓝卡显示当前值／最大值和恢复入口；提示不能只说“战力不足”，而要说“气血未满”“宝宝未出战”等可操作事实。

### 9.2 单人和多人按钮

| 按钮 | 条件与权限 | 成功后的状态 | 异常处理 |
|---|---|---|---|
| 装备／技能／宝宝 | 本人、尚未发起开局 | 打开既有管理页；返回后同步配置 | 同步前不可准备；战内锁定规则沿用对应系统 |
| 查看补给 | 本人、存在已有补给能力 | 打开背包／已有恢复入口 | 不自动使用道具，不新增购买或付费复活 |
| 查看机制 | 所有人 | 开 U03 | 关闭不改变准备状态 |
| 准备 | 多人本人，配置同步且资格满足 | 等服务器确认后显示已准备 | 失败保持未准备并显示原因，不替别人准备 |
| 取消准备 | 多人本人、尚未开始创建本局 | 确认后显示未准备 | 与开局竞争时按权威结果进入开局／战斗 |
| 开始挑战 | 单人本人；或队长且全部当前成员已准备 | 进入 U04，锁住本局相关操作 | 超时不是失败，保留原开局意图查状态 |
| 邀请队友 | 准备阶段且仍有位置 | 打开既有邀请入口 | 新人真正入队后才更新人数，不等邀请名单自动开 |
| 返回入口 | 未发起开局 | 本人退出试炼准备、撤销本人准备；保留社交队伍 | 撤销未确认时不显示为已离开 |
| 离开队伍 | 使用既有队伍面板明确操作 | 同步队伍结果后回单人入口或新状态 | 不用“返回”暗中执行 LeaveTeam |

单人没有多余的“先准备再开始”两次点击；本人完成同步后直接开始。多人队长也须准备自己的配置，不能用开始按钮替其他成员准备。无人组队时不会出现必须等满五人的倒计时。

### 9.3 准备状态失效规则（新增契约需求）

准备不是纯本地勾选。服务端应将其与本次试炼选择、权威名单和本人战斗配置版本关联：

| 变化 | 谁需要重新准备 | 提示 |
|---|---|---|
| 难度、护卫版本、影响战斗的关卡规则变化 | 全队 | “试炼设置已变更，请重新准备” |
| 成员加入／离开、人数变化 | 全队 | “队伍成员已变化，请重新准备” |
| 队长变更 | 全队；新队长继承可见选择，重新确认 | “队长已变更” |
| 本人换装、技能配置、出战宝宝或影响快照的状态变化 | 该成员；其他成员仍显示其自身确认状态 | “你的战斗配置已更新，请重新准备” |
| 成员掉线 | 该成员；开局按钮禁用 | “等待成员恢复连接” |
| 成员重连 | 先同步本人配置，再重新准备 | 不把旧准备勾自动带回来 |
| 只查看详情、滚动列表 | 无人 | 不额外打断准备 |

开局同时核对公共选择版本、名单和每人的已确认配置，不能用“全员绿色”代替服务端复核。名单变化前发出的迟到准备回包不能把新房间误标已准备。

队长返回入口意味着退出本次试炼准备；本稿建议关闭该队的本次试炼准备上下文，其他人回到“等待队长选择”，社交队伍仍在。通过既有功能转让队长时按表中变更规则处理。服务端没有准备房协议时，以上只在隔离原型中演示。

## 10. U03／U04：机制详情与开战恢复

### 10.1 U03 机制详情

详情固定呈现：敌人图标与工作名、机制标签、何时发生、影响谁、能做什么、常见误解。战前显示通用说明；战中另显示本次锁定目标和状态，不能用通用攻略代替本次事实。

预告示例文案：

> 破阵首领 · 重劈｜物理伤害  
> 第 4 回合发动｜目标：你的宝宝  
> 可考虑：提前保护、防御，或在其行动前有效限制物理攻击。控制可能被抵抗。

只显示已公开信息；不知道精确伤害就不画“必定损失 63% 气血”。睡眠详情提醒受伤会醒，冰冻详情提醒不能受伤；A40 显示独立护盾，不把治疗按钮附带“过量转盾”。

### 10.2 U04 开战状态

| 状态 | 主提示 | 操作 |
|---|---|---|
| 发起中 | 正在创建战斗 | 开始按钮单飞；显示当前选择，禁止改配置 |
| 等待分配 | 正在准备进入战斗 | 按已有开局意图查询，不新建另一请求 |
| 连接中 | 正在连接战斗 | 取得本局状态后再进可操作 HUD |
| 结果未知 | 正在确认是否已开始 | “查询状态”；可以最小化界面但保留恢复入口和占用 |
| 已确认未开始 | 本次未能开始：具体原因 | 回 U02，更新准备和资格，允许用户重新发起 |
| 已确认取消 | 本次开局已取消 | 回 U02；不能仅凭查询无记录认定取消 |
| 已开战 | 正在同步第 N 回合 | 同步成功进入 U05；不因迟到取消回包退出已存在的局 |
| 已结束／作废 | 战斗已结束，正在确认结果 | 进入 U07 对应状态 |

只在现有或将来契约明确允许取消开局时显示“取消进入”。点击后显示“正在取消”，旧意图确认撤销前不能重新建局。战斗一旦已创建，取消排队不能冒充逃跑。

开局 request_id 与意图须跨页面关闭和短线恢复保存；账号切换后不得套用另一个账号的旧状态。所有迟到消息先核对账号、队伍和本局，再改变当前页面。

## 11. U05／U06：战斗、选招、目标与逃跑

### 11.1 HUD 布局

```text
左上：首领／难度／回合              顶部中央：危险预告卡，最多突出两项
右上：连接状态／详情／菜单          场中：敌我单位、气血、状态与点名标记
左下：本人 [待选择／已提交] 宝宝 [待选择／已提交／自动／倒地]
底部：当前单位 → 动作分类 → 技能列表 → 主目标 → 确认该行动
右下：剩余提交时间；自己的提交状态；自动战斗开关
```

战斗单位身份以 actor_id 等真实标识绑定，名字与站位只是显示；宝宝归属通过主人关系判定，不能靠“人物旁边那个单位”判断可操作。

首领预告与敌方状态图标分开。预告标记要同时落在目标头顶和可点击卡片上；被点名的宝宝不能仅在人物卡上显示红框。卡片使用“蓄力中／已取消／已执行／目标失效”等状态，不让旧预告跨回合残留。

当前 TurnResult 的 action_order 是已结算回合的演出顺序，不是敌方下一轮预告，也不保证在提交前可预测。正式预告未接入时不从回放顺序伪造。

### 11.2 人物与宝宝动作

- 点本人或宝宝标签切换操作对象，各自保留未提交的本轮草稿；切换不发送指令。只能操作本人所属单位，队友点选只打开公开详情。
- 宝宝显示“主动攻击／障碍／辅助”三个分类，每类可有多招已学合法技能；**不是三个装备槽，也不是每类都能用一次**。三个入口与普攻／防御等正常动作共用该宝宝一轮一次行动。
- 人物按技能线最终可用集合显示，不能据本稿擅自开放“全部已学”或写死“4 主动＋2 战法”。
- 技能卡显示名称、目标上限、类型、实际耗蓝、冷却和可用原因。缺未接入的新字段时用“未提供”或演示数据，不从旧数值猜新公式。
- 选技能后进入主目标选择；目标合法性先用服务端可用数据提示，提交仍由服务端重新校验。法力／冷却／受控变化会使原草稿失效。
- 本稿采用分别“确认人物行动”“确认宝宝行动”，不增加一个假原子“全体提交”。一个单位确认不代表另一个已确认。
- 正式动作契约需携带可校验的本局、回合、操作单位与去重信息；当前协议没有这些完整能力，宝宝命令 UI 先走演示适配。

### 11.3 选中、提交与回合状态

| 状态 | 表现 | 按钮规则 |
|---|---|---|
| 待选择 | 当前单位高亮；列合法动作 | 可选招和主目标 |
| 无合法目标 | 提示原因，不高亮无效对象 | 确认禁用；可取消选招改行动 |
| 法力不足／冷却／受控 | 技能卡灰且可点击查看原因 | 不自动使用药品或换成另一技能 |
| 草稿已选 | 显示动作、主目标和“其余随机” | 可修改草稿；尚未扣资源 |
| 提交中 | 当前单位卡显示发送中 | 防连点，其他尚可操作单位不被无故锁死 |
| 已接受 | 对应单位显示已提交 | 本稿不开放无契约保证的“撤销指令”；全员就绪可能提前结算 |
| 接受情况未知 | 显示正在确认 | 查询当前状态，不盲重发；没有回显能力时不捏造已选技能 |
| 服务端拒绝 | 显示具体原因并刷新快照 | 若仍在同一可操作回合，允许重新选；已过期则等下轮 |
| 截止／结算中 | 技能区停止收新草稿，显示战斗推进中 | 不因客户端倒计时误差判自己出手成功 |
| 新回合 | 按最新状态复位本轮草稿、截止和提交标记 | 不能把旧回合迟到响应标记到新回合 |
| 倒地／退场 | 人物、宝宝分别显示 | 倒地单位不可选招；另一存活且可控单位依规则继续 |
| 终局 | 关闭目标选择，显示终局过渡 | 不再接受任何战斗操作 |

目标预览只把手选主目标画实线／实框，副目标仅提示“其余最多 N 个合法目标随机”；不预先抽取随机目标，不把选择成功画成障碍已经命中。目标在提交前失效时清草稿并提示；提交后失效的处理依正式技能契约，UI 不代换目标或再次提交。

人物 A40 护盾与治疗分别选招、分别消耗正常行动；宝宝 B05／B06 仍按自身资格显示。当前原型的预估效果只用于展示，不计算真实护盾或更新真实气血。

### 11.4 自动战斗与断线

现有自动开关控制请求者本人。首版 UI 不给队长增加“全队自动”，也不假称现接口可分别配置人物、宝宝两套策略。宝宝手动接入后的自动范围必须有明确状态回包；原型展示“本人托管／宝宝由默认策略行动”等适用标签，不静默扩大开关权限。

自动开关也有发送中／已确认／未知状态，不能点后即保证本回合由自动替代已接受的手动动作。手动优先及何时切换由权威回合状态决定。

断线时保留画面并加遮罩“连接中断，战斗仍在继续”；未恢复前禁止选招。大厅与战斗连接可分别显示，但玩家只需看懂“能否操作”和“正在恢复”。恢复成功以当前快照重建气血、预告和可操作对象，不重复播放旧确认动画。

### 11.5 U06 逃跑确认

弹窗标题“尝试逃跑”，正文建议：

> 逃跑会占用人物本回合行动，可能失败。成功后你和出战宝宝将离开本场，本次不获得通关材料；其他队友可以继续。关闭界面不会停止战斗。

上面“宝宝一起离开”只可在目标服务端能力启用后作为正式文案；原型可以演示，现版实接须使用当前真实语义并显式标注能力未完成。

按钮为“继续战斗”（默认焦点）和“确认尝试”。确认后仍留在战斗画面等行动结果；成功显示已撤离、等待个人结果，失败显示本次未能逃离并继续战局。不使用 StopWatchBattle、LeaveTeam 或 CancelQueue 代替逃跑。人物已提交、倒地或当前回合不允许逃跑时，显示不可用原因，不通过关闭应用模拟。

## 12. U07：结果、到账和重登补看

### 12.1 页面内容

上方是胜利／失败／平局／作废／已退出，显示难度、护卫版本、回合数；耗时只有存在可靠记录时展示。中部是本人的奖励、消耗、战后人物与宝宝状态；下部是机制回顾和操作按钮。

机制回顾首版只做有来源的简要记录，不新增整场 PVE 回放制作范围。当前完整战报回放以 PVP 为主，不能把 ListBattleReports 当作试炼机制回顾已实现的证据。

奖励区域按实际数据分为材料／货币／经验／其他掉落；没有实际配置的类目隐藏。自选材料在本玩法显示为实际获得的物品或资格，具体开箱选择沿用统一物品规则，不在结算页擅自添加一次有资产副作用的二次选择操作。

### 12.2 结果状态与按钮

| 状态 | 文案与表现 | 再战 | 返回／其他操作 |
|---|---|---|---|
| 胜负已定，个人结算未确认 | 按权威结果显示“战斗胜利／失败／平局／已退出”，另列“个人结算确认中”；未知时只显示确认中，奖励占位不标已获得 | 禁用 | 可返回入口，入口保留结果确认入口；不解除服务端占用 |
| 本人胜利奖励已确认 | 显示真实所得、消耗及战后状态 | 占用已释放后回准备 | 确认关闭；展示后标已读 |
| 胜利但额度已用完 | “本次为练习，未获得主要养成材料”；其他实际奖励另列 | 可回准备 | 不把练习算成失败，不弹充值 |
| 获胜队伍中的倒地成员 | 目标规则下同样显示本人已确认奖励 | 状态已恢复且占用释放后可用 | 当前服务端未实现该资格，演示与实接分开 |
| 失败／平局 | 显示原因、实际消耗、战后状态；没有通关材料 | 结算确认后可用 | “调整配置”回准备；不能免费复原资产 |
| 主动退出 | “你已退出本场，不获得通关材料” | 本人旧局占用释放后才可回准备 | 队伍他人仍战斗时，只显示等待或返回，不发全队再战 |
| 作废已确认 | 显示作废原因和已确认资产处理 | 占用释放后可回准备 | 不展示胜利宝箱，不假称已退款 |
| 掉落改走邮件 | 以 items_mailed 等真实标志提示“奖励转邮件发放” | 不因邮件分支重复发奖 | 可“查看邮箱”；邮件尚未送达时保持投递中，不宣称已可领取 |
| 查询失败／状态未知 | “结果暂未确认，请稍后查询” | 禁用 | “刷新结果”“返回”；不显示空奖励冒充完成 |
| 重登恢复已有结果 | 按同一 battle_id 展示最近未读结果 | 当前资格允许时回准备 | 不重复入账，展示后只确认已读 |

结果页有“再战”“调整配置”“返回入口”“查看邮箱”（有需要时）和“刷新结果”（未知时）。不设“领取奖励”“付费复活”“立即买材料”“自动连续挑战”。

多人再战时，队长回到当前队伍准备；普通成员只能返回本人的准备视图等待队长，不替队长新开队伍。队伍已解散或本人离队时回单人入口；不能把上一局名单复活成新队伍。有人仍在上一局结算时，允许看准备页但禁止发起。

### 12.3 结果恢复的真实边界

服务端已确认的个人结果通过 SceneBattleResultClientPlayer.GetRecentBattleResults 补看，按 battle_id 去重、result_seq 排序，展示后 AckBattleResults。后者只是标记已看，不执行奖励发放。

**实际所得与消耗以该 battle_id 的 PlayerBattleResult 为准，不直接取 BattleEndS2C.settlement 当到账明细。** 当前 BattleEnd 仍可携带原始结算载荷；scene 实际应用时可能过滤被封禁的奖励、调整实际消耗。收到结束消息后补查个人战果，取不到时保持确认中，不能拿原载荷先涨库存或显示“已获得”。战后人物／宝宝气血法力另刷新当前权威状态，战斗终值不一定等于死亡复活处理后的当前值；旧局结果不得覆盖新局状态。

近期结果目前最多保留 10 条；查不到某局不证明没有奖励、战败或已退款，也可能仍在结算或记录已经淘汰。若 UI 需要精确展示某局的长期到账进度，须新增可查询的个人状态契约；不能让客户端直连内部终态裁决接口。

## 13. 客户端展示数据与现有接口对照

### 13.1 UI 需要的数据

下面列的是语义需求，不是建议手写一套与 proto 重复的结构。UI 原型可用演示模型，正式接入优先映射已有协议，缺口再按项目流程扩展。

| 数据组 | 必须能表达的内容 | 权威和缺口 |
|---|---|---|
| 试炼目录 | 稳定玩法／关卡／难度／版本标识，开放状态、说明、参与条件、预计时长文案 | 当前模板配置可参考；完整面向客户端的试炼目录与资格待补 |
| 个人资格 | 解锁结果与原因、当前战斗占用、共享收益资格、剩余额度、更新时间／规则版本 | 不由 UI 根据等级、日期、战力或本地通关动画自行判定 |
| 队伍 | team_id、成员身份、队长、在线、战斗状态、名单版本 | 复用队伍快照；试炼准备与版本契约待补 |
| 准备 | 公共选择版本、各人战斗配置版本、准备确认、拒绝原因、开局意图 | 现有队伍没有 ready 字段，不能本地广播假准备 |
| 己方状态 | 人物／宝宝身份、归属、生命法力、倒地退场、合法动作和技能、冷却与资源 | 基础单位状态可复用；新技能与宝宝手动依赖技能线 |
| 本轮操作 | battle_id、当前回合、可控单位、截止、接受状态、动作回显、请求关联 | 现有状态不包含完整宝宝手动和动作回显；不能把缺失字段拼成已实现能力 |
| 敌方机制 | 稳定预告身份／版本、来源单位、类型、发动回合、锁定目标、状态、可公开反制、阶段 | 新增权威同步需求；同时用于增量推送和重连快照 |
| 结果 | 胜负与个人原因、实际奖励和消耗、到账／转邮件状态、战后状态、是否已读 | 已提交近期结果可复用；更细的处理中与资格原因待补 |
| 错误 | 明确业务原因、是否可恢复、需要刷新哪些事实 | 使用既有 tip／错误路径；新码不在客户端自编数字 |

64 位身份在跨语言 UI 层保留精度，不能转成会丢精度的浮点数；展示顺序与业务 ID 分开。实际开战模板、难度和护卫版本的映射由服务端目录给出，不把演示编号写进正式开局请求。

### 13.2 可复用的协议与不能冒用的能力

| 能力 | 当前协议入口 | 本次接入说明 |
|---|---|---|
| 单人开局 | MatchService.JoinQueue；mode、battle_config_id、team_size、request_id | 单人走 PVE_SOLO；不要用废弃 party_member_ids 发整队 |
| 单人意图查询／取消 | GetQueueStatus、CancelQueue，关联原 request_id | 保留同一意图；NOT_QUEUED 不是撤销成功证明，需看 request_cancelled 等权威结果 |
| 组队开局 | ClientPlayerTeam.StartTeamMatch；expected_team_id、request_id、battle_config_id、target_team_size、match_mode | target_team_size=0 表示当前人数；由队长发，服务端取名单；准备确认仍需新增 |
| 队伍和意图恢复 | GetMyTeam、NotifyTeamSnapshot；GetMyTeamRequest.match_request_id、TeamResponse.match_intent | 区分恢复中、已建房、确定中止；意图暂查不到不等于迟到请求不会创建 |
| 人物行动 | BattleClientPlayer.SubmitBattleAction | 现请求只有 battle_id 与 action；不能直接用来手动操作宝宝或确保跨回合去重 |
| 自动战斗 | SetAutoBattle；battle_id、enabled | 当前切换请求者本人；不能冒充全队或两套单位策略配置 |
| 战斗快照 | GetBattleState、BattleStateS2C | 复用 round_index、actors、action_deadline_ms、outcome、pending_actor_ids、self_items；预告／宝宝提交态等待扩展 |
| 战斗恢复 | MatchService.RequestBattleTicket；BattleReconnectS2C | 取得票据恢复直连后补拉；无有效快照前不放开操作 |
| 演出事件 | TurnResultS2C、events、action_order | 复用表现；action_order 是已经结算的回合顺序，不是首领机制预告 |
| 逃跑 | BattleAction.action_type=FLEE；FLEE 事件 success | 当前可能失败且只标人物退场；同步宝宝离场需补实现 |
| 本人结果 | BattleEndS2C、GetRecentBattleResults、AckBattleResults | 结束消息触发补查；实际奖励／消耗取同 battle_id 的 PlayerBattleResult，不直接显示原 settlement 为实得；已读不等于领奖 |

### 13.3 需要单独补齐的能力

1. 试炼目录、普通通关／困难解锁、人数档与护卫配置；模板 3 目前有首领但没有开放的 PlayMode 行，不能直接把它当成上线玩法。
2. 多人准备、配置版本绑定和开局原子复核；后台 PrepareBattle 不等于玩家点击准备。
3. 宝宝手动下令与归属校验、回合号／动作标识、接受回显及重连恢复。当前 BattleAction 没有 actor_id、round_index 或命令序号，不能只靠 UI 延时规避迟到动作。
4. 首领预告、取消／兑现、阶段、目标锁定与重连完整恢复；现有剧本可以帮助选择行动，但不能单独承载完整机制状态。
5. 首领固定一只的人数配置。现生产供给仍按每名玩家复制整组怪，直接开放旧首领模板会重复首领。
6. 逃跑成功同时撤走自己的宝宝；倒地未退出成员的胜利奖励资格。
7. 全游戏共享收益预算、困难奖励与资格原因；这些不在当前按场奖励能力中自动存在。
8. 必要时补个人结算处理中／作废／邮件投递的可查询状态，以及有来源的简要机制回顾；没有数据时采用本稿保守展示。

这些是需求清单，未指定新的正式 RPC 名、字段号或服务归属。服务内部查询不能当客户端接口开放；本轮不修改协议和生成物。

## 14. 服务端权威、状态与存储需求

本节只说明后续接入必须保证什么，不把所有字段都塞进玩家永久存档，也不另造平行战斗服务。

| 状态 | 所有者／保存范围 | 必须保证的行为 |
|---|---|---|
| 玩法与机制定义 | 版本化配置 | 入场冻结实际版本；开局后的配置变化不能改写本局预告和奖励 |
| 准备和开局意图 | 队伍／匹配编排权威 | 选择、名单、个人准备及配置版本一致；同一请求只创建一局；离线／失效可收敛 |
| 人物与宝宝快照 | 现有备战链 | 冻结实际合法属性、技能、出战和资产使用范围，UI 无权构造真快照 |
| 本轮动作 | 战斗权威 | 核对身份、归属、本局、回合、期限、资格；每单位至多一次正常行动，派生效果依技能规则 |
| 机制状态 | 对局内运行状态，并纳入既有恢复／重放输入 | 预告与兑现同源；目标、取消、轮换与随机选择可恢复，不能重连重抽 |
| 普通通关／困难资格 | 持久玩法记录，粒度由设计确定 | 只在合法结算点登记，不由客户端胜利动画解锁；不存在记录不擅自补通关 |
| 共享收益与个人结算 | 统一预算及已有资产结算边界 | 资格与发奖防重复，失败／退出不误扣成功资格；跨玩法不会同时超领 |
| 个人结果与已读 | 现有近期战果及必要扩展 | 结果与资产来源关联；通知丢失可补查，重复展示不会重新发奖 |

开局只能在服务端确认旧局占用释放后进行；请求超时不自动创建新意图。动作、结算、发奖都必须有各自明确的去重依据，不能把 UI 的按钮禁用当作一致性保障。

最后一个敌人或己方单位倒下时，先完成技能线规定的死亡、持续效果、合法复活等结算顺序，再裁决胜负。客户端不能看到某一瞬间全员血条为零就提前宣布失败，尤其不能绕过回生印。

首领伤害类型和攻击属性须能被物攻削弱、物防／法防、护盾等目标规则正确读取；旧怪物默认伤害不能仅改个“物理”标签就声称 A03 等新机制已生效。公式与新技能基础均需实接后验证。

两版服务器后续均需按各自实现状态验收。本稿只核对当前 C++／Go 的局部事实，未检查或实现独立 Java 版；不可据本文宣称两版试炼已完成。

## 15. 给 UI 制作的演示场景与验收

### 15.1 演示数据原则

用独立、可切换的 UI 演示入口驱动以下场景；在演示环境固定显示“UI 演示数据”，与真实服务和玩家资产隔离。正式玩家流程不出现开发字段、未实现接口名或“请等待程序开发”等内部文案；未开放能力应按产品状态隐藏或显示未开放原因。

演示用角色名、气血、材料余量只为排版与交互验证，不进正式配置。示例给出假 battle 标识时使用明显的演示命名空间，不能提交给真实服务器。覆盖已有接口的数据可以制作真实适配，但本聊天没有授权修改客户端或发送真实开局请求。

### 15.2 可一键切换的场景

| 场景 | 输入状态 | 必须看到的结果 |
|---|---|---|
| D01 正常单人 | 普通开放、一个人物一个宝宝、资格可用 | 从 U01 到准备、选招、预告、结果的完整流程 |
| D02 困难锁定 | 普通未通关 | 说明解锁条件，不写固定等级、不出现可发请求的困难按钮 |
| D03 无宝宝／残血 | 出战为空或血蓝不足 | 明确提醒及已有管理入口，不自动买宠或回满 |
| D04 二人队伍 | 队长已准备、队员未准备 | 队长不能开，队员能自己准备；不用等五人 |
| D05 准备失效 | 有人换装、新人入队、切难度 | 按第 9.3 节精确撤销对应准备，不保留假绿勾 |
| D06 开局超时 | 请求已发、回包未知，随后收到已建房 | 不发第二局；恢复原局而非弹失败重试 |
| D07 双单位操作 | 人物选治疗、宝宝选攻击 | 各有独立草稿与提交态；宝宝切分类不多一次行动 |
| D08 随机副目标 | 人物五目标、宝宝两目标技能 | 只确定主目标，其余随机；不画固定五连线 |
| D09 预告与反制 | 宝宝被重劈点名；有效控制／抵抗；上一轮防御与本轮已生效防御对照 | 显示准确对象；仅权威取消后撤预告，抵抗仍危险；不把上一轮防御保留到本轮 |
| D10 睡眠与冰冻 | 敌人带睡眠／冰冻 | 睡眠受伤可醒；冰冻不能显示可伤害爆发预览 |
| D11 A40 与治疗 | 有两种合法人物主动 | 分开选招；不能本轮治疗后免费补盾，过量治疗不产盾 |
| D12 目标／回合过期 | 选中后目标退场或收到下一轮状态 | 清理失效草稿，不自动改目标、不把旧确认贴到新轮 |
| D13 战斗断线 | 掉线期间推进两轮 | 恢复当前快照与预告，不能重新开局或重复出手 |
| D14 逃跑失败／成功 | 宝宝已提交；分别演示宝宝先行动、主人先逃跑、逃跑失败 | 已发生的合法动作与消耗保留；成功后未执行宝宝动作取消；失败照原指令继续，不重复行动 |
| D15 队伍胜利本人倒地 | 本人未退出、最终有奖励资格 | 目标原型展示所得；实接前明确这一资格尚未实现 |
| D16 胜利到账延迟 | 公共胜利先到、个人结果后到；结束消息原件与实际战果数额不同 | 先显示结算中，按同局 PlayerBattleResult 显示实得，不提前涨库存、不照抄原件 |
| D17 邮件与重登 | items_mailed、重复结果、重登未读 | 指向邮箱、投递未到不假成功；同局不重复累计 |
| D18 无额度／服务失败 | 已用完共享额度；查询失败另一个场景 | 用完仍可练习；失败显示未知，二者不混成零奖励 |
| D19 作废与复活时序 | 房间暂查不到；随后作废，或全倒后合法复活 | 未确认前不判败；胜负依最终状态，不依瞬间血条 |
| D20 队长离开／换人 | 准备阶段或结算后权威名单变化 | 不代准备、不复活旧名单；再战使用当前队伍 |

UI 验收至少提交以上关键场景的可运行演示或逐状态截图；覆盖 16:9、20:9、4:3、安全区、长名字、中文放大、触屏及鼠标／键盘焦点。弹窗不能点击穿透；主要按钮和预警不能被刘海、底部系统区域或技能列表遮挡。

### 15.3 后续服务端验收，不在本轮执行

- 单人以物攻、法攻、控制、辅助人物各搭合理宝宝完成普通；低输出合理阵容能压过护卫治疗周期。
- 正确反制、控制抵抗、速度不足、预告目标倒地、多人同时控制均有确定结果；不出现无预告补刀。
- 1～5 人只出现一只首领；队员掉线／退出不动态降档，人均奖励不随怪物数放大。
- 本人、宝宝、队友的控制权分别校验；旧回合迟到动作、重复提交、全员提前就绪不造成多次行动。
- 失败、平局、作废、主动退出、倒地获胜分别核对奖励资格、消耗和占用释放；同局重投不重复发奖。
- 开局响应丢失、连接断开、终局通知丢失、资产到账延迟、邮件延迟和重登均可恢复；UI 不先宣布未经确认的结果。
- 共享预算跨 PVE／PVP 不超领；每天目标材料和失败余量放回整个游戏约半小时内测量，不单测某一条线就宣称达标。

## 16. 待定项与制作优先级

| 待定项 | 当前占位方式 | 是否阻塞 UI 框架 |
|---|---|---|
| 正式名称、图标与主题场景 | 使用工作名、既有图标和场景预览 | 不阻塞 |
| 最低等级／精确解锁条件 | 服务端条件列表＋锁定态 | 不阻塞 |
| 各人数护卫名单和机制时间表 | 1 人回春／护势两套，2～5 人可替换演示 | 不阻塞布局，阻塞真实平衡与开放 |
| 伤害、血量、治疗、护势幅度与速度 | 所有数值可替换，明确演示 | 不阻塞布局，阻塞实服参数 |
| 困难额外收益、次数、跨日与额度组织 | 已确认全游戏 20 份目标；其他读取统一资格 | 不阻塞奖励状态框架，阻塞正式发奖 |
| 防连控、控制时长、技能边界 | 引用技能线，不写本玩法专属公式 | 不阻塞界面，阻塞相关战斗实现 |
| 防御时点与重劈配速 | 当前防御不跨轮；使用明确已生效／未生效演示 | 不阻塞布局，阻塞真实反制和开放验收 |
| 普通通关解锁记录粒度 | 本人完成普通解锁困难的制作基线 | 不阻塞锁定／解锁原型，需正式契约 |
| 失败后恢复体验 | 先真实血蓝、已有补给；不免费重置 | 可制作；需试玩确认时间与消耗负担 |

建议制作顺序：U01／U02 和详情抽屉 → U05 的人物／宝宝操作与预告 → U04 异步恢复 → U07 全部结果状态 → 各比例和极端文案验收。不要只做胜利截图而遗漏失败、未知、无额度、重连和操作拒绝。

交付物为可复用页面／组件、页面跳转、按钮状态、独立演示场景和验收截图／记录。完成 UI 原型不等于试炼可正式开战；只有服务端能力、真实数据与端到端验收完成后才能对玩家开放对应操作。

## 17. 可复制给另一台电脑的制作说明

> 按服务端仓 `docs/design/boss-trial-planning-ui.md` 制作“首领试炼”UI。首版一个首领、回春／护势两种护卫、普通／困难两档，单人或当前 1～5 人队伍即可进入准备，无 NPC 助战和强制每日接任务。完成 U01～U07、C01～C03 的布局、按钮、页面流及 D01～D20 演示场景；尽量复用现有组队、装备、技能、宝宝、背包与邮件界面。各自操作人物和自己的宝宝；宝宝三个分类共用每回合一次行动。主目标手选、其余随机，不画假确定名单。人物护盾采用 A40 独立主动友 7，不做过量治疗转盾。新准备房、宝宝手动、敌方预告、逃跑带宠、倒地成员奖励、共享收益资格仍有服务端缺口，先用明确隔离的 UI 演示数据，不伪造真实成功，也不自行修改服务端协议。重点完成开局未知、动作未知、重连、结算中、转邮件、无额度、失败重试。奖励按已确认全游戏每天约半小时目标 20 份统一预算展示，不自加 PVE 额度，不把困难额外 5 份或售价写成已定。正式接入只映射已存在且语义相符的接口，缺口按第 13 节单列；未获授权不修改服务端、正式配置或玩家资产。
