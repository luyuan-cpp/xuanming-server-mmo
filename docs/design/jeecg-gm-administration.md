# 独立 JeecgBoot GM 管理系统

2026-11-17：用户确认采用配套 Vue 3 前端和 Java 后端，授权开始接入。GM 管理员身份独立于游戏玩家账号。

## 职责与边界

浏览器只调用 JeecgBoot；其原有登录、会话、角色及权限体系负责管理员认证。新增 `/gm/**` 每次在服务端检查认证及具体权限，操作者从认证主体读取，不接受请求提供的操作者。游戏侧密钥仅保留在后端环境中。

固定上游 v3.9.6，提交 `49c29032e18df784f1a75123d90647bc8f74cedb`。`java/gm_admin` 保存自有扩展、配置模板及构建脚本；上游源码和构建产物放 `build/gm-admin-upstream`，由准备脚本校验提交后应用扩展，避免把第三方源码混入本仓改动。独立管理库保存账号、权限及管理日志，不跨库 SQL 修改玩家。

首批接入：区服只读列表、按玩家 ID 精确查询公开资料及在线状态、个人邮件附件发银两和物品、持久命令与审计。玩家 ID、金额、邮件号保持十进制字符串，不经过 JavaScript Number。查询不返回登录令牌或账号认证材料。

## 发放契约

正式发放复用 `mailpb.MailAdmin.SendPersonalMail`，不借玩家登录、不调用仅开发服开放的客户端 GM RPC、不绕过资产围栏直接修改数据库。发送成功表示邮件已投递，附件在玩家领取后进入资产流程。

网页先创建草稿：管理员、客户端幂等号、玩家、原因、标题正文、附件、请求号及绝对过期时间持久化。确认发送只接受草稿号，不能临时替换目标或附件。数据库条件更新保证同一命令单飞；实际 RPC 在数据库事务外执行，调用前先持久记录发送意图。超时或进程退出后的不确定状态保留原请求，显式重试始终复用原 `sender_kind/request_id/expire_ms` 和载荷，服务端邮件幂等负责最终去重。发送不自动重试，也不把未知结果记为失败或成功。

调用签名严格采用权威 `ServiceCallAuth`：清空 auth 后确定性 protobuf 序列化摘要，HMAC 绑定完整 RPC 方法、caller=admin、时间戳和载荷。协议描述由现有 `proto/` 编译生成，不复制手写消息结构。

权限：`gm:zone:read`、`gm:player:read`、`gm:mail:prepare`、`gm:mail:send`、`gm:audit:read`。原生账号管理维护角色分配；新增经济命令的操作者、目标、原因、冻结载荷和结果在管理库留存。未配置邮件服务或签名密钥时拒绝发放；不使用假响应填充成功状态。

## 部署与验证

管理前后端、MySQL/Redis 独立启动，初始仅绑定本机 loopback。启动材料不使用上游示例口令；管理员口令与基础设施口令随机生成到忽略目录，启动时从环境注入。连接现有本机服务使用明确的 loopback 端口；非本机 gRPC 采用 TLS。

验收分别覆盖：鉴权与越权拒绝、真实协议签名、64 位 ID、草稿幂等、并发发送、超时后同号重放、审计持久化、前端构建及真实登录。集成检查不对用户已有角色发放资产。当前运行栈尚无 mail，接入状态必须如实显示并单独完成部署验收。

本模块首先接当前 C++/Go/Java 网关混合服务端。独立 Java 全服务版使用不同内部管理协议，不能假称已兼容；需独立适配并登记 PARITY。
