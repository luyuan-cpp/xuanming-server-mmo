## 1. 状态与本轮范围

用户要求解释治疗和护盾依赖什么属性、辅助人物怎样加点，并提供详细 UI 说明交给另一台电脑制作。**四维、人物装备与宝宝统一条目点的分工、治疗与护盾分别施放均已确认。** 装备词条与修正层按[装备首发规格 V1](../equipment-v1-affixes-artifacts.md)的接入基线；本页的具体配点比例、技能基础曲线及A40首测参数仍须分别评审，不能把设计规格当成现有服务端能力。用户没有确认人物“全部已学可选”，旧“4 主动＋2 共享战法”也仍是草案。

本轮只写说明，不改服务端、协议、正式表、客户端或运行服务。另一台电脑可以先做现有接口接入、界面布局、状态与隔离的演示数据；设计已有规格的部分也须由服务端及正式契约实现后才能接入真实数据。

人物的词条养成来源已定为装备，宝宝的条目由宝宝自身持有，具体见[宝宝条目与 UI 交接](pet-entries-ui.md)。人物装备已有[八部位策划](../equipment-eight-slot-planning.md)的确认骨架：武器、帽子、衣服、鞋子、两个首饰位、两个法宝位；四件基础装强化至+10且必成，首饰和法宝不另设强化，首套材料总预算与日常目标产出也已确认。不能把这些重写为“装备来源、数量及获取规则全部未定”。

[装备首发规格 V1](../equipment-v1-affixes-artifacts.md)现已给出四个方向位、四个效能位、四个通用位、36项固定词条与八件法宝的实现基线，不再把具体词条池、数值和法宝目录全部写成待定。施放治疗D03与护盾容量D04是独立方向，各单条+8%，不是合并治疗／护盾词条；分类节用也分别处理。后续重铸／免费调整成本、材料人民币售价及旧资产转换等仍按装备文档另行收口。本页不复制维护装备数值表或操作成本。人物辅助页只做来源查看与装备对比，不把宝宝的条目点重分配复制为人物点池或任意免费选词条编辑器；装备专页的合法打造、装词条、强化操作按其规格与服务端能力推进。

“人物靠装备词条”不撤销已有合法被动或临时技能效果。P05等被动仍按技能资格与适用规则提供各自效果，UI将装备、被动、临时状态分开标来源；不能把被动贡献标成装备词条，也不能为了只留装备来源而删除被动。主人合法施加给宝宝的临时状态按技能规则单独显示，不等于宝宝继承主人装备。

## 2. 推荐的治疗与护盾关系

### 2.1 四维与装备来源已定；区分 V1 修正规格和技能基础曲线

人物可分配属性固定为体质、灵力、力量、敏捷，不新增神识、慧心、治疗点、护盾点或宝宝式条目点。人物用装备词条加强擅长方向；技能基础、合法被动及临时状态按自身规则结算。装备V1将治疗基础H0、护盾基础S0分别交由技能等级／人物等级曲线提供，修正层与取整按其第4节；具体技能基础曲线仍须技能线提供，现有服务器尚未改为这套计算。体质与敏捷决定辅助的生存及出手时机。

| 项目 | 推荐方案中的作用 | UI 应怎样解释 |
|---|---|---|
| 人物等级 | 决定对应治疗技能的基础成长 | 在该技能的效果来源中显示，不显示成额外可分配点 |
| 技能等级／重数 | 决定该技能的治疗基数或倍率 | 显示当前重数；升级收益由服务端提供，客户端不猜 |
| 治疗效果加成 | V1的D03增强适用的施放治疗；不增强护盾 | 显示百分比与适用范围；另列P05等合法被动或临时贡献，不能与“自己受到治疗”混淆 |
| 护盾容量加成 | V1的D04增强人物A40容量；不增强治疗 | 与治疗分开；技能基础曲线另行提供，不能凭空增加产盾被动或护罩次数 |
| 受疗者的增疗／减疗 | 修正目标这次应得到的恢复 | 战斗条件；中立技能预览不声称已包含未知目标条件 |
| 体质 | 气血上限与防御，保障存活 | 不在新方案中自动提高治疗量或生成护盾容量 |
| 敏捷 | 战斗速度、行动时机 | 不增加治疗量、护盾容量或控制成功率 |
| 灵力 | 既有法伤与法力上限 | 新方案不因法伤提高而附送治疗加成；不能承诺一定多施法几次 |
| 力量 | 既有物理攻击 | 不直接提高治疗或护盾 |

治疗与护盾装备词条已有V1规格，但当前角色面板尚无完整新字段与来源契约。人物不因改走辅助而失去其他已获准技能的使用资格，最终使用范围仍须按人物规则确认。

### 2.2 治疗的展示关系

以下用于解释展示层级；装备修正与取整以V1第4节为准，技能基础曲线仍由技能线提供，客户端不能自行计算生产结果：

```text
本技能基础治疗 = 对应技能按人物等级、技能等级计算的基数
本次应治疗量 = 基础治疗 × 施法者适用治疗修正 × 目标适用受疗修正
实际恢复量 = min(本次应治疗量, 目标当前缺少的气血)
过量治疗 = max(0, 本次应治疗量 - 实际恢复量)
```

装备、适用被动／临时效果及本次法宝修正在V1规定的施放修正层计入一次，再应用技能条件倍率和目标增减疗，不重复乘装备加成。具体规则引用V1，不在UI另建公式。物法暴击不自动引入治疗暴击；A12残血增幅逐目标判断，A26持续回血与复活初始血量分开显示。

**示意数值，仅用于 UI 演示**：基础治疗1000、适用治疗总修正20%、目标无增减疗，得到应治疗1200。目标缺血700时实际恢复700，过量500；过量不产生护盾。20%只是隔离样例的总修正，不代表一条装备词条或装备V1的某套固定配装，示例系数不落正式表。

### 2.3 人物护盾改为 A40 独立主动技能（机制已定）

用户明确要求护盾是单独技能、友方最多7目标。人物A40选择主目标，其余最多6个合法友方随机且不重复，人物和宝宝都计入目标；施放后为各目标创建独立容量，不是全队共享盾池。不需要先治疗，不以治疗过量为触发条件，也不恢复气血。它单独占用正常行动，学习资格、法力、冷却和受控情况按技能规则校验，不能在治疗后免费补放。

以下容量关系用于展示，修正层按装备V1，A40技能基础曲线和首测参数仍待技能线定案：

```text
本技能基础容量 = 对应技能按人物等级、技能等级计算的基数
初始护盾容量 = 基础容量 × 适用护盾容量修正
```

护盾容量与治疗量、治疗加成分开计算，不读取过量治疗、施法者气血或目标减疗。七目标已经确认；技能参数采用人物主动3.2的首测试值供隔离演示，基础曲线、吸收标签、时长、耗蓝、冷却、覆盖和驱散按技能线继续评审。特殊目标资格以正式技能规则和合法目标数据为准，装备V1不擅自改技能人数或生命周期。

**独立 UI 演示**：同档普通治疗基础1000作为配表比较标尺，A40自身基础容量设800、适用护盾容量加成20%，本次每目标初始容量为960。80%只用于设计校准，不在施放时读取治疗结果；该示例不消耗上一段治疗的过量500。示例最大法力2000、无施法减耗，按8%试值整招耗160；持续R1施放至R2回合末，R4可再次施放。改变目标缺血量或治疗加成，不自动改变盾容量；以上数值均非正式服配置。

如意灵环B05、神龙护体B06仍是宝宝专属护罩，不因新增A40就开放给人物。容量、类型、抵挡次数与持续时间分别展示，不能把容量加成写成额外次数。P11旧编号仅留撤回记录，不再出现在有效技能或产盾依赖中。

### 2.4 已定规则仍然有效

- 人物 A10／A12／A26 最多友方 7 目标，不因预估治疗数值变化改人数。
- 主目标手选，其余合法目标随机、不重复；不能在下指令时把其余六个预估为确定对象。
- A26 最多五次回合末恢复；目标通过该印记复活立即消费自己的整份印记，重挂可再复活。界面不显示“每场只能复活一次”。
- 加减速从下一回合排速生效；回生印、净化等不会自动补回已经错过的行动。

## 3. 辅助人物怎样加点

下面仅为新治疗方案的试用建议，不是已验证最优配点，也不改当前职业自动加点表：

| 方案 | 新增可分配点的示意比例 | 适用思路 | 代价 |
|---|---|---|---|
| 耐久辅助 | 体质 80%、敏捷 20% | 承压后治疗、维持长回合存活 | 先手有限，可能先被控制 |
| 配速辅助 | 体质 60%、敏捷 40% | 在关键队友出手前净化或保护 | 比耐久方案少气血和防御；不保证一定先手 |
| 极端速度方案 | 由玩家手动提高敏捷占比 | 针对特定队伍速度安排 | 明确牺牲生存；不是默认推荐 |

现有每级 5 点的规则下，前两种便于理解为“4 体 1 敏”“3 体 2 敏”，但正式按钮读取方案配置，不把每级点数写死。比例只作用于待分配点，不会自动洗掉已花出的点；小样本余数分配规则待方案配置确认。

灵力是否值得补，必须看实际技能的耗蓝规则。当前现代技能按最大法力比例耗蓝，加灵力会同时提高法力上限和单次成本，不能显示“加灵力必然增加可施放次数”。存在固定耗蓝、固定回蓝或其他特定机制时再单独比较；本页不另加回蓝、减耗效果。

低速治疗或净化只是时机选择，不是无条件优势：必须活到行动；队友已经错过的行动不能补回。推荐方案名称使用“耐久辅助／配速辅助”，不写“最强奶妈／必胜方案”。

## 4. UI 范围：改造现有面板，新增详情和条件展示

### 4.1 人物属性总览

入口：原人物头像／角色按钮 → 属性。沿用现有角色面板的布局与视觉风格。

- 顶部：角色等级、当前加点方案、剩余属性点。
- 基础属性区：体质、灵力、力量、敏捷；数据来自服务器维度列表，名称、描述、排序、外部加成沿用下发值。不制作神识／慧心的加点行、点数池或六维雷达图。
- 战斗面板区：气血当前／上限、法力当前／上限、物理攻击、法术攻击、防御、速度。当前服务器只有统一防御，不能造出“物防／法防”两项数值。
- 战斗条目区：现有必杀、抗物理、抗法术等按服务器 `combat` 列表展示。
- 辅助效果区：契约具备后分别显示“施放治疗加成”“护盾容量加成”等；点击打开各自来源和适用范围。装备词条、合法被动与临时状态贡献分别标记，不混作一份装备数值。未支持的字段不伪造为0%，正式服可以暂时隐藏该行。
- “查看治疗效果”“查看护盾效果”分别打开对应技能详情；没有已学技能时跳到技能目录，不自动解锁。A40未实现前仅在隔离演示入口展示，不能变成虚假的联网施放按钮。

不要额外加一根“辅助战力”评分条，也不要显示没有明确技能含义的统一“每次治疗量”。同一人物的 A10、A12、A26 本来就不同。

### 4.2 加点面板

入口：人物属性 → 分配属性点。四行属性各显示“当前已分配”“本次准备增加”，提供 `−`、`＋` 与数值输入；四维下方显示本次总投入与剩余点。

- `＋` 只修改本地草稿，校验剩余点和单项上限；`−` 只能撤回本次草稿，不能撤回已提交点数。
- “清空本次选择”只清草稿，不能调用整池洗点。
- “自动建议”读取已有 `AutoAllocateAttributePoints`，当前是职业表建议，不能换个标签就称为新辅助方案。
- “耐久辅助／配速辅助”先做演示选项或可配置入口；服务端尚未提供新方案时，正式界面不能冒用原自动加点结果。
- “确认加点”发送目标已分配值；等待时防重复提交，回包成功后以完整面板替换。失败显示实际原因，不能先显示已成功。
- “重置已分配点”与清草稿分开，确认弹窗显示服务器给出的整池费用。当前为免费时显示免费，不猜收费档位。
- 有草稿时离开页面，提供继续编辑／放弃本次选择。收到外部属性变化时，重核草稿并提示刷新；不能用旧余额提交超额方案。

**预览能力边界**：现有接口可以准确预览准备加几点，没有任意草稿对应的派生属性预览。没有新预览契约前，不显示精确“气血增加 300／奶量增加 100”等推算。也不能先提交、拿真实面板后再回滚来模拟预览。

新规则采用后，属性帮助可以说明“体质提高气血与防御”“敏捷影响行动先后”“治疗量由对应技能和治疗效果决定”；仍连接旧治疗规则时须使用旧规则说明，不能把新说明硬贴到旧计算上。

### 4.3 技能目录与技能详情

入口：技能 → 选择技能。先复用现有列表与详情，分类通过数据驱动，不提前制作不可修改的四槽布局。人物自由技能范围与三分类全可选仍待确认，界面原型可以展示这个候选形态，但不能冒充已上线的学习资格。

每个技能详情至少包含：名称／图标、主动或被动、已学等级、目标阵营与上限、主要效果、耗蓝规则、冷却、持续条件、无法使用原因。技能效果和升级成本读取服务端，未提供的精确数值不在客户端重建公式。

**A40 独立护盾详情原型（七目标已定，其他数值仅作首测演示）：**


### 4.4 人物装备词条来源与装备对比

入口：属性中的辅助条目、装备详情、技能详情里的“效果来源”。

人物辅助界面提供查看与比较：查看装备词条、当前效果来源、候选装备与当前装备差异。不把宝宝统一条目点面板复制成人物点池或任意选词条编辑器。八部位及操作边界沿用[八部位装备策划](../equipment-eight-slot-planning.md)，词条、数值与法宝按[装备V1](../equipment-v1-affixes-artifacts.md)；装备专页的合法打造、装词条和材料页面仍按其规格推进。

- 汇总行：条目名、单位、当前生效值、适用范围。
- 来源行：来源类别（装备／被动／临时状态）、来源名称、贡献值、生效或不生效原因；有真实来源数据才展示逐项清单。装备来源指人物实际装备，被动来源保留P05等合法技能，临时来源标明技能或状态；各项只计入一次。
- 人物与宝宝按所属主体分开。主人换装备不重写宝宝条目点；宝宝接受合法临时技能状态时单独标来源，不叫装备继承。宝宝页使用替代旧自选条目的统一预算及可增可减的全量草稿，见[宝宝条目点与 UI 交接](pet-entries-ui.md)；这不改变人物原四维只增加点／整池洗点的语义，也不新增人物条目点或宝宝装备栏。
- “施放治疗加成”与“受到治疗加成”分开命名；前者改善自己给别人治疗，后者改善别人给自己治疗。
- “护盾容量加成”与“护盾剩余值”分开；前者是生成时的修正方向，后者是战斗状态。治疗条目、护盾条目各显示适用范围，不因都属辅助就相互套用。
- D03／D04分两行，E05／E06分别显示治疗／护盾减耗；济生佩与固元印的条件增效按V1标明主目标及触发条件，不能显示成七目标常驻通用加成。正式值和生效状态仍从服务器读取。
- 装备对比可以显示这件装备已有明确条目的数值差。没有服务器整体替换预览时，不能声称这就是换装后的最终治疗差值。
- 同值也显示文字；提升／降低有加减号和文案，不只靠红绿颜色。没有数据和真实零值要区分。

当前协议没有完整V1词条来源明细或新辅助终值，来源列表先做演示，不从装备名称推算贡献。人物此处是查看与比较，**不增加脱离装备规则的自由选词条编辑器、“一键购买治疗条目”或“洗练治疗条目”按钮**；装备专页按[八部位策划](../equipment-eight-slot-planning.md)与[装备V1](../equipment-v1-affixes-artifacts.md)接入，设计规格齐全不等于正式接口已经存在。

### 4.5 战斗中的效果详情

已有战斗界面上补状态信息，不重做整个 HUD：

- 治疗动作：指令阶段显示技能与主目标；实际行动结算后才显示实际恢复量。过量治疗可在详细战报显示，与血量增加区分。
- 护盾动作：独立选择A40并指定合法主目标，显示自己的耗蓝、冷却及当前不可用原因；目标上限7、其余随机，选择治疗不自动提交护盾动作。随机副目标在服务器选定前不预告为保证受益对象。
- 护盾状态：状态图标加盾标识；血条旁或下方显示独立容量条，不能把盾容量写进气血上限。点按或长按可打开详情。
- 详情字段：来源技能、剩余容量、适用伤害类型、剩余次数（仅适用于有次数的护罩）、到期时机／剩余回合、是否可驱散（有规则数据时）。不适用字段隐藏。
- 多种盾并存时逐项列出，不能把仅挡物伤和仅挡法伤的容量加成一个无条件可用总盾。
- 人物独立护盾显示来源A40的正式技能名，不再显示“余泽成盾”或治疗过量转化。盾破、到期或按规则驱散后同步移除显示。
- A26 回生印显示剩余恢复次数；该目标复活消费整印后立即移除其图标，其他目标不受影响。
- 受控、倒地、耗蓝不足、冷却等分别给原因；正常净化不额外改成概率技能。

## 6. 现版治疗与新建议的差异

当前治疗实现位于 `cpp/libs/services/battle/system/turn_battle_engine.cpp`，其核心关系仍为：

```text
(法伤 × heal_multiplier + 施法者等级 × heal_per_level)
× 技能重数系数 × (1 + 适用治疗被动)
```

当前现代技能 `mana_percent` 按最大法力比例计算单次成本。因此旧规则下灵力会间接影响治疗与耗蓝，不能把本页的新关系直接当成当前正式说明。装备V1已要求治疗与法攻分开，但技能基础曲线、改表／服务端接入及验证仍须完成；本轮未执行。

当前丹心自动加点是旧表的“2 灵 2 体 1 敏”，本文件的“4 体 1 敏／3 体 2 敏”不替换它。现有四维到派生属性的关系和点数换算以[角色属性加点系统](../player-attribute-allocation.md)为准。
