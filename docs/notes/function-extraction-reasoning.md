# 函数提取的思考话术

两段代码只是结构相似，承担的规则不同：进入要填充实体创建数据，离开只发送实体编号。几行相似的 `Clear → 填充 → 广播`，还不足以支持一个通用抽象。

外层函数值得保留：它封装了“通知观察者可见性变化”的完整职责，共享编号校验，并且已经被普通移动和瞬移清理复用。继续拆内部几行，会增加阅读跳转，收益有限。

以后出现特殊逻辑，可以先放在对应分支。出现以下情况时，再分别提取进入、离开两个私有函数：

- 分支形成了独立、需要命名解释的业务规则。
- 分支明显变复杂，遮住了外层流程。
- 其他调用点也需要复用这一段完整行为。

**整洁代码追求的是理解和修改更容易，不是函数越短、数量越多越好。** 这里保留两个直白分支，也给以后分别演进留下了空间。
