## 1. 需求分析

### 1.1 为什么 V1 不够好玩：4 个必须根治的产品短板

对照[项目设定](project-vision.md)（**好玩优先、不肝、小小氪金**）与 2026-11-23 全游戏最新系统现状，V1「试炼手记」守住了“不肝”，但作为**长期养成**存在 4 个核心体验断层与 1 个跨文档硬冲突：

1. **舞台过小，撑不起“长期”**：V1 仅绑定 1 个首领 × 2 种护卫 × 2 档难度 = 4 个打卡格。玩家在凑齐首套装备的 40～60 场战斗中早把这 4 格打穿，毕业后只剩对着同一个 Boss 凹单人最少回合，普通玩家几乎没有回访动力。
2. **单维竞速（最少回合）挤压流派多样性**：V1 唯一认可的成绩是“单人最少回合”，天然把玩家推向唯一最优的纯爆发输出流；不仅防守/治疗/护盾/控制流派在手记里零存在感，连[八件法宝](equipment-v1-affixes-artifacts.md)中超过一半的法宝（如破盾向 `F01/F02`、抗控向 `F08`、生存续航向 `F04~F07`）在常驻首领试炼里都缺少用武之地。
3. **660 永久上限切断了“毕业后换新法宝试打法”的免费循环**：V1 写于 11-22，假设玩家可凭每日 20 份继续花 12 天（240 份）收齐其余 6 件法宝；但 11-23 修订的[核心循环 V1](core-gameplay-loop.md) 已改为**每角色永久上限 660 份**（首套成本 600，仅余 60 份给流通余量，封顶停产）。若不补齐横向构筑获取口子，玩家毕业后根本换不起其余法宝、也洗不动第二套词条。
4. **零情绪反馈、无复盘抓手、边缘化组队**：V1 破纪录既不记当时带了哪只宝宝/哪两件法宝（无法复盘策略优化），满印后也没有任何零战力纪念物或叙事回响，且多人组队在点亮 4 格后完全没有纪录痕迹，反而把 MMO 玩家赶回纯单机。

### 2.2 「攻·守·巧」多维战法印：让每一种流派与每一件法宝都有主场

彻底改变 V1 “只有爆发速通才算数”的单一维度，每格围绕该首领的真实机制设计 **3 枚定位分明的战法印**——所有条件均支持 **1～5 名真人入场（单人带宠或好友组队皆可点亮）**，由战斗引擎根据真实结算事件权威判定：

#### 卷一 · 破阵试炼（首发 4 格 × 3 印 = 12 枚永久印）

| 关卡格（稳定业务 ID） | 印记 ① · 破阵（通） | 印记 ② · 守心 / 速破 | 印记 ③ · 巧策（机制解题） | 适配流派与法宝 |
|---|---|---|---|---|
| **普通·回春** | 首次有效通关 | **速破**：在表配回合数内通关（首测暂定 `≤ 7` 回合） | **断愈**：全场首领未从回春护卫获得任何有效气血恢复（`boss_guard_heal_total == 0`）并胜出 | 爆发压回合 / 控场打断（`F03 回响铃`） |
| **普通·护势** | 首次有效通关 | **速破**：在表配回合数内通关（首测暂定 `≤ 7` 回合） | **破势**：己方本场成功驱散过敌方护势，**或**己方对敌方同时造成过有效物理直伤与有效法术直伤并胜出 | 驱散辅助 / 人宠物法混编 |
| **困难·回春** | 首次有效通关困难 | **无损**：困难模式下，**本人及本人出战宝宝全程从未倒地**并胜出 | **断愈**：困难模式下，首领全程未获有效回春治疗并胜出（不卡回合数，护航控辅流） | 治疗/护盾/保命（`F04 济生佩`、`F05 固元印`、`F06 护心珠`、`F07 归元葫`、`固阵守印`、`聚息援印`） |
| **困难·护势** | 首次有效通关困难 | **无损**：困难模式下，**本人及本人出战宝宝全程从未倒地**并胜出 | **破势**：困难模式下，己方成功驱散过护势或物法双系均造成有效直伤并胜出（不卡回合数） | 稳健续航 / 驱散 / 混编双修 |

> **为什么「无损」按本人及本人宝宝判定，而非全队连坐？**  
> 在 2～5 人合作中，如果因为一位陌生队友失误倒地就牵连其他认真防御/套盾的玩家拿不到「无损」，会滋生野队甩锅与踢人；按本人及本人出战宝宝在整场从未触发 `BATTLE_EVENT_DEATH`（含死亡后再复活仍算曾倒地）判定，单人时等价于全队无损，多人时专注做好自己的人宠保命与治疗协作，体验远更健康。

### 2.3 个人纪录与复盘快照：把“干数字”变成“策略手记”

每个试炼格（卷一 4 格 + 卷二 3 格）同时维护两条互相独立的轻量纪录（均在当前可比 `rule_version` 内取最小正整数回合，平手或更慢不覆盖）：

1. **单人最佳回合（仅入场恰好 1 名真人，一人队亦同）**：
   - 存储字段：`best_rounds`（`uint32`）、`achieved_at_ms`（`uint64`）、**策略复盘快照（仅 4 个整型字段）**：
     - `used_pet_table_id`（出战宝宝种类 ID，无宠为 `0`）；
     - `used_artifact_effect_ids`（至多 2 个 `uint32`，对应开局穿戴的 `F01..F08`，允许同名重复，按升序稳定存储）；
     - `used_season_seal_id`（当局生效的赛季印 ID，无则为 `0`）。
   - **体验变化**：玩家翻开单人纪录，不再只看到冷冰冰的 `6 回合`，而是看到 **「最好 6 回合 · 灵狐｜破阵刃 + 聚息援印」**。过两周换了金猊和新法宝再打，立刻能直观对比搭配优劣。
2. **好友合战最快回合（入场 2～5 名真人，仅存在本人私藏手记中）**：
   - 存储字段：`best_rounds`、`party_size`（2～5）、`achieved_at_ms`、`used_pet_table_id`、以及开局冻结的**至多 4 名队友展示名**（经内容安全过滤，纯快照文本）。
   - **防毒设计**：全游戏**不建立全服多人竞速榜**（不按多人回合排名），但让和朋友开黑打出的好成绩留在各自手记里，既可留念截图，又零野队内卷。
   - **与野外试炼碑联动**：卷二三张野外图的「试炼碑」展示本服前 3 队真名与阵容时，直接复用同一份战斗终局阵容快照结构。

- **永久位图域**：

  - `repeated SeasonJournalArchive season_records`：按 `season_id` 索引，内部仅存当季的 `repeated uint32 lit_seal_ids` 与 `repeated uint32 claimed_milestone_ids`（每季仅 4 印 + 2 档，体积 < 32 字节），绝不污染永久全局位图。

#### 3. 战斗冻结事实扩展（Battle → Match → Scene 单向权威流）
在 `BattleSettlementData` 追加轻量子结构 `BattleTrialJournalFacts`（普通非试炼旧局留空，零影响旧路径）：
- 身份上下文：`journal_entry_id`、`trial_rule_version`、`initial_human_count`、`season_id`；
- 战法事实（由 `TurnBattleEngine` 在回合结算事件落地时同步累加，终局前冻结）：
  - `bool self_or_pet_ever_died`（本人或本人出战宝宝本场任一时刻触发过 `BATTLE_EVENT_DEATH`）；
  - `uint64 boss_guard_heal_total`（回春护卫对首领实际造成的有效气血恢复总量）；
  - `bool guard_stance_dispelled`（己方队伍成功驱散过护势护卫状态）；
  - `bool team_dealt_physical_direct_damage` / `bool team_dealt_magic_direct_damage`（己方对敌方造成过 >0 物理/法术直接伤害，及碧渊水宫「阳钟物理 / 阴鼓法术」相位标记）；
  - `bool guard_survived`（护卫救援保住回春护卫）；
  - `bool self_triggered_shield_break`（本人通过 `F01/F02/破阵锐印/破阵玄印` 产生 >0 实际削盾）；
  - `bool self_triggered_anti_control_or_season_skill`（本人触发 `F08 清心符`、成功净化己方障碍或施放当季免费赛季技能）；
- 轻量阵容快照：`used_pet_table_id`、`repeated uint32 used_artifact_effect_ids`（至多 2 个）、`used_season_seal_id`、`repeated string teammate_names`（入场队友冻结名，至多 4 个）。

#### 4. 客户端 RPC 契约（最小 3 个接口，零多余写入面）
新增 `proto/scene/player_trial_journal.proto`（`SceneTrialJournalClientPlayer`，登记跨节点换场景可重投白名单）：
1. `GetTrialJournal`（纯只读）：一次拉齐当前有效卷目录、各格已点亮印记、当前可比规则的单人/合战最佳纪录与配装快照、里程碑进度与可领/已领状态、当前已持有自用法宝拓印数、人物评语解锁态与「前往挑战」准入原因。
2. `ClaimTrialJournalMilestone`（写操作，强制 `client_request_id != 0`）：领取已达标的一次性里程碑（自用重铸砂 / 自用法宝拓印 / 名片印戳 / 终极专属形象）；走严格背包预检 + `ClientRequestLedgerComp` 去重 + 同帧存盘。
3. `RedeemBoundArtifactVoucher`（写操作，强制 `client_request_id != 0`）：消耗 1 张背包内「自用法宝拓印」，指定兑换 8 件 V1 法宝中的任意 1 件（产出仅自用实例）；同样走背包预检 + 幂等账本 + 同帧存盘。

## 3. 思想分析

1. **为什么长期养成不能靠“多发材料 / 加新强化上限”，而必须走“横向解题解锁玩具”？**  
   回合制 MMO 一旦把长期目标绑在垂直战力（+15、洗极品随机词条、周常必刷代币）上，就会立刻毁掉「不肝」与「老玩家歇几周回来照样能打」的立身之本。反过来，如果像 V1 那样把一切奖励和趣味题都砍到零，只剩 4 个打卡勾，玩家又没有动力去换流派。本方案把**“垂直封顶（660 / +10）”与“横向玩具解封（6 张仅自用法宝拓印 + 6 份自用重铸砂）”彻底拆层**，让玩家打完首套后自然进入“解题 → 得新法宝/改配 → 换套路破新题”的策略心流，既好玩又绝不破坏数值公平。
2. **为什么选“每格攻/守/巧 3 印 + 18/21 容错”，而不是“只比最少回合”或“强制全清”？**  
   [项目设定](project-vision.md)强调「换一套技能能让人物和宝宝打出不同的配合」。只比最少回合会让 8 件法宝废掉一半、把所有玩家逼成纯输出；加入「断愈」「破势」「无损」「应钟」「趁汐」后，辅助、控制、坦盾、双修都能靠自己的看家本领亮印，18/21 的终极门槛更是允许玩家按偏好跳过少数不擅长的速通题，真正尊重流派自由。
3. **为什么坚持把卷三（赛季轮换）和卷一/卷二（永久）在存储上物理隔离？**  
   既为了体验（错过一季不留永久遗憾、不锁永久形象与 8 法宝收集），也为了严格遵守仓库 [bit-storage-and-table-ids.md](../rules/bit-storage-and-table-ids.md) 红线——绝不把高频轮换 ID 塞入永久单调递增的全局位图。
4. **为什么优先把终极目标挂到已落地的 `GrantAppearance`，而不造新货币/新养成槽？**  
   永久多人物收藏衣柜与 `GrantAppearance` 已于 2026-11-23 在双服落码完毕。把试炼志终极荣誉直接接入衣柜，不仅实现成本几乎为零，还能在主城、野外潮汐聚人、同屏观战和论剑开场中被其他真人直观看到——这正是 MMO 里最健康、最有含金量的零战力炫耀载体。

## 4. 漏洞分析

| 潜在漏洞 / 风险 | 攻击面或故障场景 | V2 硬性防护与边界 |
|---|---|---|
| **1. 死亡后复活骗取「无损」印** | 玩家人物或宝宝中途阵亡，最后回合靠复活技能拉起来，终局 `is_dead == false` | 引擎内单独维护 `self_or_pet_ever_died`，只要本人或本人出战宝宝任一时刻触发 `BATTLE_EVENT_DEATH` 立即永久置 `true`（本场内不可逆），绝不拿终局存活状态替代 |
| **2. 逃跑/挂机/切磋/回放混入刷印** | 队员中途逃跑队友打赢、玩家开切磋找朋友放水、或观看高手回放 | 仅服务端冻结的正式匹配/首领试炼/野外明雷/轮换终局原件进入结算判定；必须本人未逃跑、属于胜方（卷三「明心应劫」等明确标明有效对局的除外）、`total_rounds > 0`、`outcome != VOID` 且满足个人有效参与；观战/回放/切磋路径物理隔离 |
| **3. 里程碑连点/背包满丢奖励/双领拓印** | 玩家弱网连点「领取里程碑」或背包已满时点击领取，导致连发两张拓印或先置位后物品入包失败 | ① `ClaimTrialJournalMilestone` 强制 `client_request_id != 0` 接入 `ClientRequestLedgerComp`；② **先校验背包空间（含堆叠/实例位）与全部前提条件，全部通过后在同一玩家同步帧内原子完成“置位 `claimed_milestone_bits` + 发放道具 + 调用 `GrantAppearance` + 写幂等回执”并触发 `SavePlayerForAssetCommit`**；背包满时直接拒绝且绝不置位 |
| **4. 自用法宝拓印被洗白成可交易资产或重铸砂** | 用拓印换出法宝后试图上架集市/聚宝斋、当面交易、或拆解换砂 | 拓印本体与兑换出的法宝实例强制写入绑定标记（仅自用）；法宝延续[旧装回收 V1](equipment-recycling-trade-economy-v1.md)白名单规则**禁止拆解**，且不进入银两/聚宝斋交易白名单 |
| **5. 策划删行/热更/灰度回滚破坏位图** | 停用某格试炼导致计数分母出错，或新版本点亮高位印记后切回旧版本节点被截断 | 严格遵守 [bit-storage-and-table-ids.md](../rules/bit-storage-and-table-ids.md)：① 严禁复用已删 ID，优先 `enabled = 0` 下架；② 计数一律遍历当前有效目录行过滤，**禁用 `bitset.count()`**；③ 读盘遇到超出本地容量的高位 bit 存入 `unknown_*_bits` 并在存盘时原样回写；④ 启动校验失败（缺映射、无效 `grant_appearance_id` 或 `card_unlockable != 0`）一律 fail-closed |
| **6. 规则换代与收件箱乱序重投覆盖纪录** | 首领血量/机制改版后，老版本迟到的结算包把新版最好回合覆盖掉，或收件箱重投反复触发结算 | 沿用 `player_inbox` 战斗域永久消费水位防重（与材料账同一去重锚点）；`rule_version` 在开局冻结，迟到的旧版终局仅能更新对应旧 `rule_version` 的历史纪录，绝不覆写新版；**永久战法印跨 `rule_version` 永久保留** |
| **7. 队友改名/违规昵称污染合战快照** | 合战纪录保存队友名字后，原队友因违规被强制改名或注销 | 冻结队友名时先过既有内容安全展示名管线（[rename-and-content-safety.md](../design/rename-and-content-safety.md)），不存对方账号或敏感信息；如后续需要按 ID 脱敏，可由前端/服务端按既有内容安全展示规则兜底；严禁把 `player_id` 写入任何 Prometheus 标签 |
| **8. 跨版本/双服（C++ 与 Java）漂移** | C++ 接完战法事实统计与试炼志后，独立 Java 版遗漏部分事实或宝宝条目差异导致判定不一致 | 所有客户端可见 `.proto`、`Tip.xlsx` 与 3 张新表走统一权威源生成并同步四端；明确记录 Java 版先对齐卷一契约与缺失的战斗事件统计（同时留意 Java 现有宝宝条目能力边界），在 Java 仓 `PARITY.md` 逐里程碑登记，不未验先报 |

## 5. 步骤分析

按“**先立卷一完整玩法闭环（最快可玩） → 再随世界地图 M3 无缝扩卷二与终极形象 → 再随首季轮换接卷三 → 二期按数据决定是否加自选禁律**”拆分为 4 个清晰里程碑：
