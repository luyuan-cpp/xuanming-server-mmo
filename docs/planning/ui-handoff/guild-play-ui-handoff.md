# 帮会会武 · Unity UI 异机交接

> **[2026-11-25 已作废 — 已被 V2 UI 交接全面替代]** 请改用 [guild-play-v2-ui-handoff.md](guild-play-v2-ui-handoff.md) 与 [guild-play-v2.md](../guild-play-v2.md) 进行帮会玩法 UI 制作与联调；本文对应的 V1 2V2 匹配会武与公共预设入口已停用。

另一台电脑的 Codex 负责 Unity 页面、Prefab、表现和最终联机。Gemini 负责两版服务端、共享契约、客户端生成绑定及非 UI 联网逻辑。两边可并行开工。当前交付为设计，文末的演示与截图是验收要求。

开工时一起取本文件、[帮会首发规格](../guild-play-v1.md)和[公共竞技预设](../ranked-play-season-ui-candidate.md)。以主规格决定会武规则，以公共预设决定角色和宝宝选项。论剑的赛季、段位与榜单仅在论剑展示。文中数值文案是演示样例，正式界面读版本配套的配置及权威回执。

## 从帮会入口打一局

1. 点「帮会」。已入帮直接看到帮旗、首胜署名和「帮会会武」。想合作打怪，点旁边的「同道历练」。一个人可选「普通历练」，跳到既有单人 PVE。
2. 点「帮会会武」，入口副文案可用「2 对 2 · 每人带一只宝宝」。直接约一位在线帮友，已有空闲双人队可沿用原名单。两人各自选择并确认本局人物和宝宝。邀请上标明首测预计时长，排队后显示实际等待时间。对手由系统安排。
3. 成局进入原战斗界面。本人仍能分别给人物、宝宝下指令。断线后从原局继续。关窗只收起界面。
4. 赛后先看胜负，再看自己的材料可领额度。若是帮旗首次题名，看到两位队友的名字。随后可「回帮会」或打开原材料自选领取。

### 四个页面与按钮

优先扩展现有帮会窗口。在一个窗口内切页、展开行或弹出确认框均可。已有组队、同道历练、战斗、战报、材料领取和易容使用客户端原入口。

| 页面 | 首屏和按钮 | 谁能点、点后发生什么 |
|---|---|---|
| 帮会首页 · 无帮会 | 本区帮会列表、自己的申请。「申请加入」「撤回申请」「创建帮会」 | 无帮角色可选允许申请的帮会；仅能撤回自己的待审申请。建帮沿用现有表单及条件。提交中锁住该项，权威答复后更新，审批通过后切到新帮首页。 |
| 帮会首页 · 已入帮 | 上方帮旗、帮名及首胜两人，下方「帮会会武」「同道历练」，次级「成员」「会武记录」 | 本帮成员可进入。首胜为空时写「等待本帮首次题名」，记录为空时写「还没有会武记录」。有进行中的报名或对局，主按钮换成「查看报名」或「回到对局」。 |
| 帮会首页 · 合作 | 「同道历练」「普通历练」 | 前者跳现有同帮多人邀请页，依原活动状态展示参与条件。独自想开打时去普通 PVE。已有会武票据要先查明能否切换，明确取消后才开放另一玩法报名。 |
| 成员管理 · 全员 | 成员名单、职位、在线状态。「组队」进入既有组队界面 | 可邀请时仅由本人发出邀请，对方自行接受。查不到在线状态显示「状态未知」。队友换帮或离线时按最新资格刷新。 |
| 成员管理 · 已有管理操作 | 「同意／拒绝申请」「编辑公告」「移出帮会」「任命／卸任长老」「转让帮主」「退出帮会」「解散」 | 长老与帮主可审批、改公告。长老只能移出普通成员，帮主还可移出长老；帮主可任免、转让和解散。普通成员与长老可退出。涉及移出、转让、退出及解散时确认目标与后果，收到结果再更新。其他现有管理项沿原入口。 |
| 会武准备大厅 · 约帮友 | 同排两张队友名签，每张留人物、宝宝两个格。空格可「选一位帮友」，选好后「发起会武」 | 空闲成员直接选本帮可邀请的在线成员；已有空闲同帮二人队时直接带出搭档，无需另建队。队伍被其他活动占用时可「查看当前队伍」。发起者选自己的预设后发起，同时确认自己。 |
| 会武准备大厅 · 确认 | 「人物预设」「宝宝预设」「确认参战」「谢绝」「撤回邀请」 | 本人只改自己的组合，能查看该版本预设说明。受邀者选择后亲自确认或谢绝。发起者可按权威状态撤回。确认后自己的组合只读；要更改，结束原报名再开。 |
| 会武准备大厅 · 匹配 | 「继续等待」「申请取消」「查看状态」「回到对局」 | 已排队的任一队员可申请整队取消。继续等保留原顺序。取消中只读；查原票得到已锁结果时进原局。锁后仅向参战者展现双方帮名、名签与人宠预设，再接原战斗页。 |
| 结果与记录 · 本人 | 「回帮会」「自选材料」「查看本场战报」「再约一场」 | 仅原参战者按个人结果权限访问本场完整战报，有可用录像才显示回放。已有材料余额可进原领取页。再约一场回准备页，重新校验当前帮会和队伍，双方重新确认。已离帮者经个人对局入口查看原场。 |
| 结果与记录 · 本帮 | 首胜署名、最近会武摘要、空态及「返回」 | 当前本帮成员读本帮近况，按权威顺序列胜负平、双方帮名、本帮二人、终局时间和回合数。非参战成员只看摘要。首胜题名独立保留，近期列表翻过该场仍看得见两人名字。 |

首页已有捐献、商店、节庆等功能保留原路径。会武首屏无需购买、打卡或领帮贡。已有角色形象可在人物名签展示，可选的小额易容沿用原入口；本轮美术素材清单见下，不另建商城页。

### 状态文案与恢复

| 触发条件 | 玩家看见什么 | 可做什么 |
|---|---|---|
| 帮会资料或预设加载失败 | 「帮会资料暂未取到」或「会武规则暂未取到」，保留返回和重试 | 重读对应资料；空列表、零余额、尚无首胜都要有成功读取作依据。 |
| 当前版本未开放会武或公共配置未就绪 | 「此版本暂未开放会武」，保留帮会与普通 PVE 入口 | 按权威开放状态禁用新报名。原局重连向服务端恢复该局冻结配置，不能套用新版本或演示预设。 |
| 独自打开、队友条件不符 | 「选一位在线帮友一起会武」，没有合适人选或队伍有占用时展示对应原因 | 有合适人选就发起邀请，也可去普通 PVE；仅在本人明确操作后发出邀请。 |
| 本人已确认，队友待确认 | 两个姓名旁分别写「已确认」「待确认」，显示服务器给出的截止时间 | 本人可收起；遇到谢绝、撤回、超时或人员变化，按查到的结束原因返回准备。倒计时归零先查状态。 |
| 配置版本变化、所选预设失效 | 原票仍有效则标出该票沿用版本；服务端已让旧选择失效时提示「会武规则已更新，请重新确认」 | 跟随原票查询结果继续等待，或在确定取消后重选重报。已经成局则读本局冻结版本。 |
| 排队久候、尚未匹配 | 「仍在寻找本区其他帮会的队伍」及实际等待时长，区取服务端确认的角色归属区 | 示例在 02:00 出现「继续等待／申请取消」。提示出现时不退队，不展示对手名单。 |
| 取消已发、传输超时、重复点击 | 「正在核对原报名」，保留原队友与入口 | 只查原票或通过适配层恢复原请求。确认已取消才解锁改预设、另报或转历练；若成局则「回到对局」。 |
| 战斗中关窗、断线或重登 | 大厅或原重连提示给「回到对局」，沿用战斗页的托管与接回提示 | 取原局并恢复人物与宝宝指令。房间故障由服务端裁决，等待时不展示平局或胜负。 |
| 对局已结束，部分结果未到 | 分列「比赛结果」「本局新增可领取额度」「帮旗题名」，只在各项待确定处显示「待确认」 | 可返回，重进按同一局刷新。比赛胜负平、材料资格与两人题名资格各读其结果，不互相推断。 |
| 额度到账、上限、材料资格不足 | 样例「可领取额度 +10」或「今日共享额度已满，本局 +0」；资格不足单列具体原因 | 可进原领取页选打造材料、百炼石，名称取正式配置，沿原确认和失败恢复。只有领取成功才显示实际材料入包。 |
| 首胜竞写、离帮、被踢或转帮 | 帮旗只显示正式收录的首胜与两位署名；本人原局保留开战时的帮会名和个人结果 | 锁前成员变更回查报名。锁后仍由原参战者回原局，已离帮者从个人结果回查；切回当前帮会时重新查可见范围。 |

## Unity 表现与素材

按项目既有的统一 UI 美术风格执行（本文档不另定风格、材质或色号）。首页用一面帮旗占据上方，旗下两行等大姓名并列题名，没有题名时保留同一版式。大厅把两位队友放在一起，让每人一眼分清“我的人物、我的宝宝”和队友的选择。结果先读胜负和参战者，再展开材料与历史。首胜印记只在权威收录后出现一次，重开页面保留静态题名。

| 所需素材 | 复用与分层 |
|---|---|
| 帮旗、首胜印 | 复用已有旗形或无字简旗底、一枚单色印。帮名和署名用独立文字层，帮旗也能在列表小尺寸辨认。 |
| 人物与宝宝 | 复用现有人物外观、宠物头像及公共预设图标；缺合法出战宠时画预设默认宝宝。宝宝旁始终保留本局战法名称。头像加载失败换通用轮廓，保留名字与选择。 |
| 面板与状态 | 复用项目既有面板与按钮资源（不另定风格或色号）。用文字配合勾、时钟等符号标识“已确认／等待／失败”。胜负平都使用可读文字。 |

关键按钮及姓名锚定横屏安全区，细长屏或大字号时将名签换行、历史列表滚动，展开行可读完整长帮名和双人署名。字号和触控区沿项目可读设置，弹框在最大字号下仍可滚动到操作区。键盘可导航、确认、返回；弹框锁住焦点，关闭后回发起处。鼠标和触屏都能查看规则与失败原因。声音、颜色和动画都配等价文字反馈。

## Gemini 交给 Codex 的数据清单

以下是页面需要读写的信息。正式名称、字段、单位、权限和请求恢复方法以 Gemini 交付的生成绑定及适配为准。

| 切面 | 必须交付的读状态、动作及恢复依据 |
|---|---|
| 身份、帮会、管理 | 当前角色、归属区、帮会身份与职务，各目标允许操作及拒绝原因。注明本区列表、自己的申请、成员名单、管理回执、变更通知后重读位置。 |
| 同帮双人准备 | 当前队伍、本人和另一成员、发起资格、邀请截止、双方正式确认、允许操作、可用的公共人物／宝宝预设与展示外观、规则版本。本地选择草稿只供本人预览。给出发起、本人同意、谢绝、撤回及更新后的原票查询。 |
| 匿名撮合和入战 | 原报名标识、报名或成局阶段、排队起点、服务器时间、可否取消、实际结束原因、当前角色可恢复的原战斗入口。说明发送成功、正式取消、撮合锁定三者的分界。 |
| 个人结算和材料账 | 原局及角色、双方身份快照、胜负平或作废及原因、本人资格。逐局材料新增值和未增原因须能按「原对局＋本人」持久回查；当日已赚、上限、可领余额及实领回执由原材料账给出。跨日、其他场入账或已领取后，总余额差不能还原本局新增。附个人历史与[原材料领取](../../design/equipment-eight-slot-implementation.md)的恢复入口。 |
| 帮旗与记录 | 当前帮会、题名是否已收录、两位署名的展示快照、允许读取的近期摘要、原参战人的战报权限与定位。说明并发首胜、本人离帮与个人查回路径。 |

随清单交两版服务端的对应版本与差异、Unity 绑定及非 UI 适配的版本和取件位置、可直接运行的脱敏样例。至少覆盖下表各条，特别是同一次取消得到不同终态、战斗已结而材料待确认。正式 tip 与状态变化以服务端结果为准，界面只发出本人操作意图。

## 可点演示与截图验收

| 场景 | 演示动作与可见证据 |
|---|---|
| 入帮和权限 | 无帮→申请→已申请→审批通过→本帮首页；分别用普通成员与长老查看同一目标，允许的操作不同。断开读取时能重试。 |
| 两人想开一场 | 单人可约帮友或去普通 PVE；已有同帮双人队直接复用。截图标清本人已确认、队友待确认及无宠默认头像；原票仍兼容时继续，失效则重选重报。 |
| 没等到对手 | 久候可继续或申请取消。关窗重进仍是同一次报名。取消结果未定时不能另报，分别演示最终取消后去历练、锁定优先后回原局。 |
| 一场真会武 | 两个同服不同帮会、四名真人的本局经原战斗页操作人宠并断线回局。原战斗不带论剑段位变化。正常结束、健康房间到限平局、故障作废分别可辨。 |
| 首次合格获胜与材料 | 先演示胜负已定、材料仍待确认，再演示可领 +10 而背包未变，最后沿原弹窗实领。当天已满时呈现 +0。胜方有人不合格仍获胜，帮旗等下一场达标题名。 |
| 老记录与新帮会 | 有权成员读最近摘要；非参战成员没有完整战报入口。已离帮的原参战者重登能查自己的原局。模拟近期列表已轮换，帮旗仍保留当初两名署名。 |
| 移动端和键鼠 | 同一首页、准备页和结果页分别在 16:9 与带刘海的细长横屏截图。用最大字号和长中文名再验成员操作、题名与弹框；用键盘和触控各走一次确认、返回。 |

开发演示从专用模拟入口注入同一组视图数据，画面标「演示」。模拟控件只作用于本地，正式入口只接 Gemini 的适配，断网进恢复态。先交可点演示与截图，再用正式绑定走报名、撤销、战斗、回查和材料实领。交付附 Prefab／素材位置、各场景对应截图、演示或联机标记，以及仍缺哪一项真实回执。
