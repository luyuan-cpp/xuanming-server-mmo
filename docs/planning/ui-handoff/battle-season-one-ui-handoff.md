## 应交付的界面

**一张赛季页，以及对准备／匹配、战斗和结果三个界面的调整。** 先画一条「自己去打首领、看预告、保住护卫、回到赛季页」的可点击路径，再用同一套列表、战斗 HUD 和结果样式接通真人路线。主视觉用现有横版战斗画幅及既有角色/灵宠素材（按项目既有的统一 UI 美术风格，本文档不另定画风或色号）。普通与救援分别复用同一名首领、同一名护卫的立绘。可用有明确含义的物理刀纹、法术符纹、护卫护符区分规则，每个图标并列文字。战斗中不遮住被点名者、选招区和行动倒计时。

| 所在位置 | 玩家看到什么 | 按钮和动作 |
|---|---|---|
| **赛季页** | 标题「破阵之季」，服务端时段转本地显示。常驻两行「人宠会武 · 自带养成」「破阵首领 · 单人可开」。只显示当前一张「本期玩法」卡，附一句胜利目标与构筑来源。页尾一行「今日基础材料」及本人可获份数 | 「参加会武」到原真人匹配。「挑战首领」到试炼准备。活动按钮按内容显示「救出护卫」或「参加易势」。点「玩法说明」可重读目标。「自选材料」到原装备材料页 |
| **准备／匹配** | 会武在原匹配面板选每侧真人数、确认人宠／组队。首领按试炼准备设计显示实际队伍、敌方机制、难度与就绪。救援预览标记敌方回春护卫「须存活」，提示「默认人宠单体打首领，留护卫一命」。救援与易势都显示「本局试用」，默认搭配可直接开局或排队。两行选择「人物打法」「宝宝战法」显示服务端给的候选和招式详情 | 会武「开始匹配」。首领／救援单人「开始挑战」，队员「准备」与「取消准备」，队长「按当前人数开始」。两项轮换均可「更换打法」，易势点「开始匹配」。已挂票时「取消匹配」「改打首领」等待撤票结果 |
| **战斗 HUD** | 正规会武沿原 HUD。首领点名在目标头顶显示标记＋「下回合重劈」，并用发送方和目标区分护卫预告的「将治疗首领」。救援保留护卫血条旁的护符、目标说明及群攻伤及护卫提示。易势在回合号旁显示「当前物势／法势」及「下次换势回合」，两边同样可见 | 沿原战斗选择人物或宝宝、技能和主目标，提交后等权威回执。「机制」可点开重读，不暂停回合。脱离、自动、重连沿实际玩法能力。PVP 不展示投降按钮。普通防御提示依据生效时点，不能只凭按下按钮显示「已挡住」 |
| **结果／材料** | 胜、负、平、作废以权威终局为准。救援失败举例「护卫阵亡」，成功「护卫获救」。列本局基础、胜局加成与「新增可选份数」。正式常规会武才显示原评分变化，易势显示「本场不计分」。本局战果、可领余额、材料入包分别读对应状态 | 「再战」回准备或同档匹配确认，不自动再开。「调整搭配」去本人已有技能／宝宝页，救援、易势回本局试用选择。「自选材料」开装备页。「返回」收起。沿用既有结果回看，关闭页面不丢奖励 |

首季只有一个人宠会武入口。从原大厅和从赛季页进入时，应打开同一原匹配页，沿用原榜入口。页面不添加第二套竞技大厅、段位门槛、赛季登录任务、补签或活动商城。两项轮换都借用人物「破阵、控场、守心」和宝宝「破甲、灵咒、护主」的配置外观与招式选择，使用临时属性。救援默认用「破阵＋护主」，人物和护主宝宝都可普攻单点。换破甲宝宝提示「普攻可能追击护卫」。两种轮换的介绍卡按救援目标／物法交替区分，常规卡标明自带养成。美术若需先画占位图，以姿态、轮廓和文字表现定位，不把角色皮肤画成属性来源。

## 交互状态与可复制文案

| 时刻 | 反馈与后续动作 |
|---|---|
| 首次打开／重试失败／当前无期次 | 「正在获取本期玩法」暂缓季节报名。失败显示「暂时无法获取玩法」「重试」。空档显示「本期活动已结束」，会武与试炼按各自返回的可用状态显示 |
| 材料额度用完／无余额 | 「今日基础材料已拿满，仍可参加」。可继续开局。材料页区分「暂无可选份数」与「余额读取中」 |
| 队伍变化／配置失效 | 「队伍已变化，请重新准备」或服务器给出的可读原因。名单与新配置齐备后重新准备。队长不能替队员确认 |
| 真人少／撤票与开局相撞 | 匹配屏显示真实等待时长和「改打首领」，不展示虚构人数或承诺入场时间。改打时先显示「正在取消匹配」，确认撤销后才去试炼。若已成局则显示「对局已开始，正在进入」 |
| 战斗开始时／换势时／预告取消 | 救援和易势显示「本局使用试用搭配」。仅易势显示权威开场势。切换时用轻量文本提示。首领改为「重劈已取消」须收到实际取消事件。禁用过期目标的点选，不能用客户端推演补播攻击或造出护卫死亡 |
| 断线、请求超时或重登 | 「正在恢复当前对局」。重取本局和当前可操作回合，锁定的构筑、势和预告均用完整快照恢复。开局或动作结果未知时不重复建房或假报提交成功。已终局则进恢复结果 |
| 结算不同步 | 胜负已确认、份数尚未知显示「胜利 · 材料结算中」。基础已用完且实际为零才显示「本局新增 0 份」。回执确认后显示「已增加可选份数」，去原材料页选定并收到入包回执后才显示材料和数量 |
| 救援同一招击倒两只敌人 | 按权威结果显示「救援失败 · 护卫阵亡」，保留再战与单体攻击提示。普通首领胜负照原界面 |

## Gemini 应提供的显示数据

以下是数据语义，用于服务端和 UI 对接。命名与字段号由正式协议源生成。UI 开始接真数据时，先核实当前客户端生成版本。已有入口可参考 `BattleQueuePanel`、`BattleHud`、`BattleResultPanel`、`BattleResultRecoveryClient` 及 `EquipmentWindow.Materials`，以所用客户端提交为准。

| 数据来源 | 必需语义 |
|---|---|
| 赛季目录、角色可参与状态 | 服务端当前时间，期次、有效时段和当前活动，玩法／规则版本，构筑来源、人数范围、计分语义，准入与禁用原因，当前基础资格／领取余额，数据是否就绪。日额度与本地日期无关 |
| 准备和撮合 | 当前人数、队长／队员、准备成员、权威票据与终态、当前对局标识。救援和易势提供候选人物／宝宝预设及其合法招式、选中搭配、锁定状态。报名失败可重试、已成局则恢复、取消成功才另开 |
| 战斗增量与重连全量 | 当前回合、可操作单位与技能／目标、提交状态。预告施放者与目标、执行回合、取消与结束状态。受保护的局内单位和生存状态。当前势、换势回合、可信规则版本。回合结算后行动序列不作为敌方下回合预告 |
| 个人终局与原账本 | 对局、玩法与规则身份、胜负／失败原因、计分适用性与权威评分变化，材料回执状态、本局基础和胜局加成实发、未发原因。原材料页给当前余额、批次和选领结果。并发领取时不能用前后两次余额之差反推本局所得 |

## 可以先做与联机验收

制作端可在独立预览场景中用带「演示」标记的本地样例驱动画面，不连生产接口，不写角色资产。样例覆盖正常、空态、禁用、异步中、拒绝、重连和作废。菜单入口切到正式版时只接权威数据，可用性、势、胜负、评分与到账缺一项就展示相应等待或不可用状态。客户端手动切势、造赢局、展示假发奖只能留在独立预览。

交付时录制以下三段短流程，同时附各状态截图和待接契约清单。

1. **一个人玩。** 首页进救援，看懂谁须保护，选默认人宠单体普攻，或让护主宝宝保护被点名者。演示成功与误伤失败，再战回准备。在正规试炼击败护卫不会出现救援失败。
2. **有人匹配与没人匹配。** 从原大厅和赛季页打开同一会武人数选择，正常局展示评分。易势用默认搭配开局，能换预设、看懂两种势、断线恢复，结果不计分。没有真人时撤票后改去首领。分别展示撤销成功与已经成局。
3. **知道自己到底拿了什么。** 用主稿的混打、两胜和已满额样例分别展示战果。回执未到时无确定份数，回来能恢复同一结算。在原有页面分配打造材料和强化石，看到实际入包后可返回。重复打开结果不会重复增加数量。
