> **[2026-11-25 已作废 — 已被 V2 全面替代]** 负责人已于 2026-11-24 拍板取消 V1 的“2V2 匹配排队 + 公共免费预设 + 一次性永久首胜”路线，全面升级为 [guild-play-v2.md](guild-play-v2.md)（本人真实养成、全天无匹配随时开打、野外 3 处灵脉据点、守旗阵快照与江湖追杀令）；配套 UI 交接以 [guild-play-v2-ui-handoff.md](ui-handoff/guild-play-v2-ui-handoff.md) 为准。本文件仅保留作历史候选记录与技术参考。

2026-11-22。**想跟朋友配合，就约一位帮友，两人各带一只宝宝，代表自己的帮会打一场。** 四名真人到齐即开战，一场定胜负。第一对为本帮拿下合格胜局的人，名字会一起留在帮旗上。想合作打怪时，沿用已有的同道历练。一个人上线也能照常玩普通 PVE、取得装备材料。

本文是本轮按负责人目标收口的**实现基线**。人数、首胜题名、候场提示和时间参数是选定的首测设计。实际候场时长、战斗时长、参与意愿和流派胜率须通过试玩检验。本文交付设计，Gemini 负责两个版本的服务器业务、协议和客户端非 UI 接入，另一台电脑的 Codex 负责 Unity 界面与联机验收。[异机 UI 制作交接](ui-handoff/guild-play-ui-handoff.md)

## 一、需求分析与取舍

| 玩家当时想做什么 | 首发能做什么 |
|---|---|
| 和一个朋友打一场有来有回的对战 | 两位同帮成员任选公共人物和宝宝打法。对手由系统从同归属区的其他帮会队伍中撮合 |
| 赢了有件大家能看见的事 | 胜方结算亮出帮旗。首次合格胜利的两人永久并列题名。其他胜负平局留在本帮近 20 场会武记录里 |
| 今天只想合作，或眼下人少 | 同帮 2–5 人可在活动开放且符合原条件时走「同道历练」。没凑到两人、没人应战或不想入帮时，普通 PVE 仍能挣同一日常材料 |
| 错过几个晚上再回来 | 会武常开、自由组人，无固定集合时段。帮旗首胜在同一帮会存续期间一直有效，赛季更替也保留 |
| 偶尔小额付费 | 普通养成保留原有免费路径与小额提速边界。会武全员免费使用相同的公开预设，帮会入口没有商品、次数购买或付费报名 |

早先草案要求每帮组织两队、分三个据点打三个阶段。低人数时可能从布阵到结束都没有碰到敌队，也会花掉另外四人的集合时间。首发让每组到场的人直接交手，第三个帮友可以和其他人另组一队。大地图据点战留到实际证明有足够玩家愿意同时集合时再评估。[项目设定](project-vision.md)

## 二、设计分析 · 玩家怎样打一场

### 1. 找一位帮友

任意当前成员都可以从帮会会武入口邀请一位同帮在线成员。帮主和长老没有专属名额，帮会等级、帮贡、捐献、装备评分、入帮天数均不作为会武门槛。每场每帮一队，每队恰好两名不同真人角色。人数多的帮会可以同时派出多组不同成员。空位不补路人、机器人或宝宝，四名真人各自控制本人的角色与一只局内宝宝。

- 发起人选好本人预设并发起，同时确认自己的出战意愿。对方看见帮友、活动名和本人的预设，自行确认。邀请从服务端创建起 **30 秒**有效。拒绝、撤回或未确认到期，原邀请结束，双方均可重新约人。
- 确认前可以改自己的预设。双人确认后整队报名，改预设或换人要先取消原票。两人已经组好空闲二人队时，复用其名单及就绪入口，只确认本次会武一次。已有其他队伍、活动或排队占用时说明原因，沿原入口处理占用。
- 归属区、角色、帮会、成员身份、本人确认、正式参赛资格都由服务端校验。四个角色及两侧帮会在成局时各自唯一，执行现有身份与占用规则。报名没有新设的账号关联推断、网络地址人数限制或战力门槛。

### 2. 系统找另一帮的双人队

按同一帮会归属区、兼容的会武规则版本、可用的战斗承载和不同帮会选对手。区由服务端按角色 home zone 确定。每次从最早入队且有合格对手的票开始，取等得最久的兼容异帮票。时间完全相同用稳定票标识破同一时刻的平手。候场顺序看进入正式队列的时间。可重复遇见同一帮，尤其是全区只有两帮在线时。

- 单独标识**正式匿名会武撮合**。入战前不展示队列的人名、帮名、候选对手和阵容，没有挑对手、拒绝指定对手再换一家或双方约定奖励战的入口。本帮邀请只选队友。
- 会武使用独立的非评级赛制。这里的胜负只记会武战绩，论剑段位、个人 Elo、赛季局数、玉符进度和榜分继续从原论剑入口取得。首测只按上述条件先到先配。
- 等待 **120 秒**时显示实际已等时长，给「继续等待」「取消匹配」。任一队员都可申请取消整张票。只有服务端确认原票已取消，才能换人、重新报名或转去历练。等待时间到、切屏、请求超时都不能替客户端决定胜负或释放已成局的名额。
- 只有一个帮、没有异帮双人队、区内网络承载不合适时继续真实等待。愿意继续就保留原顺序。想打怪可先取消，再走历练或原普通 PVE。系统不得暗中转排位、跨区补人或生成假对手。[帮会归属区与权限](../design/guild-zone-client-access.md)

### 3. 进场与战斗

**双方总共四名真人、四只局内宝宝。** 人物和宝宝各有三种免费预设，分别选择。默认搭配、可用技能、宝宝临时身份、同速处理、属性和可见外观以服务端提供的同版论剑公共配置为准。复用其对局快照、收令、自动、重连和结算隔离。已经有合法出战宝宝可保留名字与外观，没带或没有真实宝宝也可用所选预设默认展示。会武不额外消耗背包道具，不回写竞技气血、法力、技能、资质和局内宠物，也不另造伙伴。[论剑公共竞技配置](ranked-play-season-ui-candidate.md) · [人宠技能规则](skill-planning/README.md)

四人锁定后公开双方帮名、参战名签和预设。每人决定自己的人物和宝宝在本回合怎么行动。例如，一人用破甲宝宝为物攻队友创造窗口，另一人判断对面会不会集火，选择让护主宝宝保人或把行动留给治疗。行动次序与目标以技能表、速度、合法目标和引擎结果为准，点下预设不保证连招成功。人物、宝宝各沿用原有行动预算，没有强制职业分工或新增公会技能。

| 条件 | 权威结果 |
|---|---|
| 在同一次完整回合结算后只有一侧全灭 | 另一侧胜。沿用引擎的人宠存活判定，个别人物或宝宝倒下时仍可由队友打完 |
| 同一回合两侧同时全灭 | 平局 |
| 双方仍有存活单位，打满竞技模板 120 个逻辑回合 | 平局。须在会武权威终局修正现有通用引擎「回合上限判 B 胜」的分支 |
| 健康战斗房间开战后达到 720 秒，仍未产生自然终局 | 由房间冻结最后已提交状态并权威判平。末回合已整体提交且自然结束的，保留该自然结果。只允许一个终局 |
| 节点故障、建房失败、丢失有效原件 | 进恢复流程，只有具备可靠作废证明时才显示作废。客户端倒计时或网络中断不能提交平局 |

首测目标是**正常交手约 6–10 分钟**。720 秒按竞技模板相当于 120 个逻辑回合，是规则的两个终止条件。邀请、排队、分配及备战另计。正常判平也须走与胜负相同的原件、战报和资格管线。模板按本局冻结版本读取。[战斗服务与期限](../design/turn-based-battle-server.md) · [当前通用胜负分支](../../cpp/libs/services/battle/system/turn_battle_engine.cpp)

### 4. 取消、断线与换帮

| 发生阶段 | 玩家看到什么，服务器怎样处理 |
|---|---|
| 邀请中拒绝或到期 | 邀请结束。迟到的同意复查原邀请，不能重新建票 |
| 排队中成员退帮、被踢、断线被权威服务判定离线、队伍解散或撤销本人同意 | 取消该队原票。另一支尚未被成局提交的有效异帮队保留原队列时间。归属或操作结果暂不明确时显示正在确认 |
| 取消与成局同时到达 | 以服务端串行的成局/取消决定为准。取消成功时不会开局。已经成局则返回原战斗入口与原名单，禁止重开第二局 |
| 成局后某人退帮、被踢、帮主换人、角色改名或队伍变化 | 按成局时冻结的双方帮会与四名角色完成比赛。不换人、不追加成员。个人已挣取的额度归原角色，胜局归当时代表的帮会 |
| 成局后关面板、掉线或重新登录 | 沿既有缺令默认行动，重连回本人原局，恢复可用预设并继续下令。会武没有单人认输、全队投降或主动逃跑按钮。失去连接不等于逃跑 |
| 终局或作废后重登 | 读本人权威近期结果与当前票状态。材料余额、帮旗和战绩可各自显示同步中。已确认终局不因一方未重连而重赛 |

### 5. 一次首胜与最近战绩

1. **胜负**按四人原局结果确认，不因成员断线、改名、阵亡、已到材料上限或不满足题名资格而改判。帮会得到胜、负或平的战绩。作废及零个有效回合只给参战者说明情况，不写帮内近况。
2. **永久首胜**要求有效正式会武、至少一个已结算回合、己方获胜且**两位胜方队员都实际参与**。个人参与沿公共竞技认定，未逃离且有服务端接受的本人或宝宝指令，或已亲自进入并明确启用本局自动。已实际入场却在第一次可操作机会前终局、倒地或一直受限者，按权威入场与机会记录认定。本人从未进入、全程只有断线默认动作，不可署名。成员先实际参战后掉线，仍按已取得的事实认定资格。材料用下节独立口径。
3. 帮会首次在自己的权威存储中**成功确认并提交**合格胜局时，永久记录双方在成局时冻结的帮名与名签、两名胜方角色、战斗标识与完成时间。题名两人并列。在不同队伍的合格胜局几乎同时发生时依帮会首次入册提交顺序决定，迟到战报不会换掉已经署名的两人。入口显示「本帮首胜」与两名参战者，后续成员也可查看。没有合格首胜时显示虚位，下一次合格胜利仍可题名。
4. **近 20 场**按每帮自己的视角列正常胜负平、双方帮名、本帮两名队员、终局时间和回合数。按权威完成时间降序，同毫秒按稳定战斗 ID 打破平手。裁剪只影响可见列表；被挤出后首胜资料、服务端防重复记录、已挣材料和个人结果继续按各自规则保存。首胜另存当时的摘要，旧的完整回放可能已过本人保留范围。
5. 本帮当前成员可读本帮旗与本帮摘要。曾经的队员退帮后仍可看本人近期结果、本人保留的回放；失去原帮会页访问资格。帮会解散后不开放其原帮会页、不新建同名帮继承荣誉。对手帮历史保留本局的授权摘要，个人材料照常核算。普通改名保留对局时展示名，账号删除、违规姓名处置遵循现行隐私与名称规则。帮会成员身份不扩大本人战报的访问权限。[战报与回放](../design/battle-report-replay.md)

## 三、思想分析 · 输赢与经济各解决一个问题

**一个朋友和你配合赢了，这一场就值得记下来。** 对手获胜，仍然能凭正常匹配取得材料，自己也能在结算看懂这场打了几个回合；下次可换搭配再试。首胜只记一次，活跃大帮无法凭人数刷出等级优势，也无需每周重复夺一次旗。后来的玩家仍能让自己的名字出现在本帮近况里。

| 当天做的事 | 自选材料额度 | 帮会／论剑记录 |
|---|---:|---|
| 正式匿名会武，胜、负或平；本人未逃离，至少一个已结算回合 | 每次 10，达到同日上限后实际新增 0 | 会武正常战绩。合格首胜额外题名 |
| 既有正式匹配 PVP 或普通 PVE 本方获胜，满足原有资格 | 同一角色同一账本，每次 10 | 按原玩法自行结算 |
| 自由切磋、点名挑战、练习、候场、作废或零回合会武 | 0 | 不记会武战绩与首胜 |
| 既有同道历练 | 使用原有组队 PVE 模式。本方取得合资格胜局时照常每人 10，与其他来源共享 20 | 另有原帮贡、资金与物品规则，按原参战、胜负、入帮和次数判定。该局归同道历练 |

材料每角色按 **UTC+8 每日 05:00** 换日，普通 PVE、正式匹配 PVP 和本次会武共享 **20 份**总额。按 scene 首次应用权威结果所在游戏日入账。10 是增加的可领取额度，成功从原材料入口确认分配后，对应打造材料或百炼石才进包。余额跨日保留。当天已经两次取得额度，仍可继续玩、拿会武首胜、留战绩。

例：今天普通 PVE 胜利取得 10 份，再打会武落败也可到 20；即使接着赢下本帮首胜，第三场的实际材料增量仍是 0。只想自己玩时，两次合资格的普通 PVE 胜利同样可达 20。日常 20、首套 300 打造材料加 300 强化石及原材料领取规则维持既有预算；不承诺半小时一定拿满。[装备材料实施记录](../design/equipment-eight-slot-implementation.md) · [首套预算](equipment-eight-slot-planning.md)

普通养成材料如有独立核准的限量售卖，只走个人商城原有的价格、限购与免费获取口径。装备规划中的材料单价是试算，本文不给它定价或增开商品。已有个人角色形象可随公开预设规则展示。付费不增加会武预设、入队优先级、材料日上限、题名机会或帮会属性。[角色易容](character-appearance-switch.md) · [装备与养成](equipment-eight-slot-planning.md)

同道历练使用原有邀请确认的 2–5 人同帮 PVE，启动资格、每日开局限制、活动物品/帮贡/帮会资金及原成员复核继续由活动服务执行。达开局上限时显示既有原因。历练没有单人开局承诺，合作也不产生新的共同进度、周任务、货币或跨玩法足迹。[同道历练规则](../design/guild-phase2/06-activities.md)

## 四、漏洞分析 · 业务状态与跨服务边界

以下状态名描述对外语义，具体命令、字段和枚举以 Gemini 交付的同版协议为准。

| 权威阶段 | 允许转移与必须保存的事实 |
|---|---|
| 待队友同意 | 帮会/队伍认证发起者及受邀者，各自同意关联确切的两人、原帮、预设、规则版本和邀请。拒绝、撤回、到期都生成可查询的关闭结果 |
| 已报名／队列中 | 记录两人同意、帮会成员资格版本、原请求、票、入队时刻和已有原队关系。与同道历练、一般组队匹配、会武另一组及在战状态共用角色占用纪律。重复同意或重发只返回原票 |
| 撮合提交中 | Match 选中两票后按固定身份顺序持有原票及占用。Guild 对两侧分别核准当前成员、原资格版本、同意与退帮等变更的先后。已核准一侧而另一侧拒绝时撤销配对保留有效方老票，绝不单边开局 |
| 已锁定成局 | 两侧都核准、四人占用完整后，由 Match 唯一提交决定绑定一份正式匿名会武原件与一个战斗 ID。固定归属区、两帮、两组成员/侧别、展示身份、人宠预设、规则/表包版本、模板与有效来源，接下来的建房、重试、结算和重放引用同一原件 |
| 战斗中 | Battle 按锁定配置生成局内单位、收令和记录实际参与事实。重复建房回同一局，重连获得原状态。该赛制不预留真实消耗品、不回写普通人物宝宝培养数据 |
| 已正常终局／已作废 | Match 验证 Battle 权威输入，胜负平只产生一份终局。正面作废证明单独记载。战斗完成与个人额度、题名和摘要各有可恢复回执。取得确定的终态后按原占用身份释放 |
| 状态确认中 | 是查询/恢复期间给用户的反馈。以同一请求或战斗 ID 查原决定，原请求迟到仍可能生效；不要单凭一次未查到或超时创建第二张票、发奖励或释放新票 |

### 关键一致性约束

- **资格的先后。** Guild 对每侧两人用可持久查证的成员版本及准备结果封住提交窗口。资格撤销先于准备即终止该侧。已准备、等待 Match 最终决定时，影响该资格的退帮、踢人、解散或撤销先与该准备串行协调；等原提交或经证明的取消再完成，禁止把一次旧查询当作成局授权。Match 在自己的事务中只提交已具备两侧有效准备的四人原件，其余服务按同一决定恢复。禁止在 SQL 事务里调另一服务或跨库直写。维护、路由代次不明和规则表缺失时拒绝新成局，已有局按冻结原件恢复。
- **单人占用。** 归属、请求身份、成员资格版本和占用在最终接纳点复核。两人并发加入不同票、同一人被另一方再次加入、现存私房/Team/Match/历练占用均须有唯一胜者。允许复用本次已经绑定的准确二人父队，不放宽其他活动的互斥。现有队长申请开局不能代替队员本人确认预设，须有权威的成员级同意及过期旧同意的校验。取消重放只释放原票的占用，永不清后来新票。沿既有按原请求取消和防迟到墓碑处理。[队伍协议](../../proto/team/team.proto) · [匹配占用](../../go/match/internal/authority/occupancy.go) · [原请求撤销契约](../../proto/match/match_internal.proto)
- **隔离赛制。** 使用可信的独立非评级正式会武模式，完整覆盖匹配提交、准备、建房、终局、回放、材料和客户端展示。现有集合流程仅对 `PVP_TEAM` 从成局原件读取显式分边，新模式要贯通冻结的两帮 2+2 侧别与恢复，否则可能把四人放在同一侧。在评分/榜、赛季与历练奖励入口都校验适用来源。仅凭客户端标记、普通 `PVP_TEAM`、私房/直接建战或同帮队伍外观不能识别正式会武。现有 `PVP_TEAM` 写论剑个人 Elo，正式会武不得借此轨道计分。[匹配集合与分边](../../go/match/internal/logic/gather.go) · [现有评分入口](../../go/match/internal/authority/rating.go)
- **依赖与版本。** 论剑的公共人物/宝宝预设、零宠默认战斗单位、对称同速与现代技能效果当前属于待接入的共同依赖。对同一可供排队的版本校验配置、内容签名、技能与双端支持。缺项明确报「会武暂未开放」。不可默默改用真实养成、固定职业、普通 PVP 队列或旧通用上限裁决。热更后，只匹配同一兼容版本，原票按原规则继续或经权威取消，已锁定局只用原版，包括恢复与重放。
- **终局原件。** Match 验证身份、战斗、正式来源、归属、两帮、双方四人及侧别、规则版本、终局类型、回合数、完成时间、入场/有效行动/逃离事实与原成局一致。正常结束、房间故障、零回合、回执等待各自可判定。遇未知或对同一局给出冲突终局时保留原记录、暂停新增副作用并对账。结算、入册或个人领取超时不触发重新开局。[结算恢复](../design/battle-result-recovery.md)
- **首胜与历史。** Match 持久终局后可靠投递到两侧帮会。Guild 按「原帮会 ID、战斗 ID」去重并核对原件摘要。在本帮事务中一起记录战果、按条件只写一次首胜以及更新近 20 视图。镜像战绩允许分时到达，失败沿原事件补办。双方解散、退帮、重组或同名新帮都不能使旧局给新实体题名。按已解散原帮的结果确认消费但不开放/重建帮会页，另一帮和个人的结果继续办理。
- **个人材料。** scene 是唯一装备材料入账方。当前 `IsEligibleBattle` 对 PVP 只有三类白名单，须显式接入带上述可信来源的正式会武，直约、切磋与历练不得借该入口。共用现有 `PrepareBattleCredit`、角色收件箱永久消费水位、额度领取 revision 及背包确认，不由 Guild 发包或发邮件补同一份。按角色和战斗只应用一次，重连、重放、跨日迟到及近况被裁剪也一样。现有余额和今日已赚只有总账，须在同次角色存档提交内给本人近期结果保存本局实际 0/10、资格/原因和游戏日，按本人战斗 ID 查询；晚到另一局、跨日或领取后都能准确显示。结果恢复窗口外按已有个人结果保留策略提示不可用。个人入账证据和组队荣誉互不代替。[材料资格与领取实现](../../cpp/libs/services/scene/player/system/player_equipment_material_reward.cpp) · [近期结果契约](../../proto/scene/player_battle_result.proto)
- **私密性。** 成局前对手隐藏，成局后只向四名参战者公开双方预设与应见资料。正式会武为私密房，首发没有旁观战斗入口。帮内近况提供授权摘要，个人完整回放仍受本人保留列表和已有战报开关限制。新模式需在 PVP 回放录制分类登记。公共查询不下发账号、资格令牌、匹配票、其他玩家材料、指令或回放正文。被处理的展示名使用既有内容安全读出规则，禁止绕回原始违规内容。[观战可见性](../../go/match/internal/logic/spectate_visibility.go) · [战报访问](../../go/match/internal/authority/battle_report.go)
- **重复对手。** 人少时两帮可再遇，正常短局、治疗、连接中断和重复相遇均不能单独改判作弊。玩家无法点名对手，首胜只署名一次，帮会不按累计胜数排名，个人材料仍受统一日额度约束。异常对局保留受权限控制的技术证据，以便复核。

## 五、步骤分析 · Gemini 与异机 Codex 的交接

| 顺序 | 责任方 | 可验收的交付 |
|---|---|---|
| 1 | Gemini | 在 C++/Go 主仓、Java 独立服务端和受影响的共享客户端契约范围分别读仓规、进度与 Java `PARITY.md`。定位公共预设、同帮成员、就绪/占用、匹配、战斗与材料的真实现状，整理需要共享的最小契约 |
| 2 | Gemini | 建立正式匿名非评级会武来源、双人邀请/确认、两侧互斥和同帮身份准备、恢复与权威成局。表和协议只在源头编辑。客户端绑定、消息号、表和必要的非 UI 请求/状态适配由 Gemini 交付 |
| 3 | Gemini | 按公共竞技配置贯通四人四宠入战、共用选择和动作、重连、对称终局、可信材料及原帮会归档。C++/Go 与 Java 对齐。Java 独立服需复核现代宝宝效果和完整战报的缺口，以真实联调证据记录可用能力 |
| 4 | 异机 Codex | 按 UI 交接用 mock/权威状态做最多四个界面视图、Prefab 和美术，复用现有战斗、材料领取与回放。服务端绑定到手后由异机 Codex 验证最终 UI 联机 |
| 5 | 两方 | Gemini 提供可移交的绑定版本、取件位置、真实命令/消息、字段/单位/时间口径、样例和两版接口或 robot 证据。异机 Codex 用相同版本替换模拟数据，提交交互与联机回执 |

Gemini 给 UI 的接口清单至少覆盖以下动作及权威返回。协议名和字段号在落码时按仓规制定。

| 使用位置 | 请求和显示所依赖的权威结果 |
|---|---|
| 帮会主页 | 当前权限、开放/关闭及原因、原历练入口状态、首胜是否存在、两名署名和最近战绩。无帮成员走原建帮/入帮入口 |
| 会武准备 | 本人身份、可邀请成员、被邀请人、两人的确认/占用、本人合法预设及默认/上次选择、邀请截止。服务端原请求句柄只给有权限的本人使用 |
| 匹配及战斗 | 入队、原票查询、整队取消、实际候场起点、可执行动作，成局锁后的对战信息、重连入口、两侧名签/预设、当前回合、对局期限 |
| 个人结算与帮会记录 | 权威胜负平/作废、完成原因、参战回合数、个人实际新增额度与上限/领取余额、首胜是否已确认、帮会摘要权限、完整回放是否还在本人列表 |

提供正常胜、负、超时平、作废，以及邀请过期、队员取消竞态、同区无人、资格变动、首胜等待、额度已满/待确认与回放不可用的同版脱敏样例。公开状态只展示服务器明确返回的字段。异机客户端不根据动画、伤害条或本地倒计时补判结果。

## 六、执行步骤与验收 · 给 Gemini

> 请按本文件落实「帮会玩法首发 V1」。你负责 C++/Go 与独立 Java 服务端、协议/配表、生成绑定及必要的客户端非 UI 请求和数据适配。UI、Prefab、美术和最终 UI 联机由另一台电脑的 Codex 制作。先满足公共竞技配置与两端效果/归档依赖，再开放常开匿名双人会武。复用已有同道历练。用下表做接口/robot 回归，交付真实运行证据及待验项。界面所需契约与样例按第五节交付。

1. 按受影响仓规则完成预检，只改协议源和配表源。依主仓规范导表、运行 `tools/scripts/dev_tools.ps1 -Command proto-gen-run`，同步 Unity 配表、协议、消息号和客户端编译检查。Gemini 的分析与业务代码、生成/编译/冒烟按各仓规定档位分工。
2. C++ 完成无裸指针成员预检，按 `/m:1` 串行构建受影响目标。Go 回归 Guild/Team/Match 等受影响用例并测试真实存储上的身份互斥与重放。Java 按独立服务端仓规实现相同玩家契约，更新对账本，记录测试覆盖到的实际功能。
3. 两版分别以接口或 robot 跑一组四人两帮的端到端对局，核对客户端读出的权威状态、旧论剑评分/次数、材料余额和双方帮会摘要。再交付客户端非 UI 适配与字段样例供异机 Codex 联机。

| 验收情景 | 通过条件 |
|---|---|
| 两帮各 2 人；同帮 4 人多组 | 前者能匿名作战；合法不同人可同时成团。同帮两队始终不能彼此成局 |
| 仅 1 人/1 帮/1 支异帮单人、跨归属区或对手预设版本不兼容 | 不足四名合规真人不成局。120 秒提示不判输。取消确认后可去相应的原玩法 |
| 并发重复邀请、提交/撤销、离帮/踢人、换队、重新登录 | 同成员不会双占。一组拒绝不妨碍另一组继续。返回同一已决定的取消或成局状态，迟到消息不能复活已取消票或碰新票 |
| 低养成、零真实宝宝与高养成玩家选同预设 | 来自同一竞技计算、同种子时效果与行动候选一致，名字外观规则正确。没有合法竞技快照时功能明确不可用 |
| 实战配合、镜像换边、同速、耗尽 120 回合和 720 秒边界 | 人宠各自行动真实生效，回放能重现同一局。测试两侧自然胜、双灭、限回合和整场限时，对称胜负平，末回合不双结算 |
| 真人入场后掉线又回来、只默认行动从未入场、零机会阵亡 | 返回原局不重开。题名资格能区别三种情况，实际先手即被限制的参与者仍可合格。掉线不影响战斗权威胜负 |
| 首胜资格和并发 | 胜方一人始终没有参与则只有正常战绩，下一组合格首胜可题名；两组合格胜局并发只题名一组。次日、下周、换季与重启都保留 |
| 不同到达顺序及近 20 裁剪 | 迟到战报按冻结配置和完成时间归入正确可见位置（或已在最近 20 场以外），题名不被推翻。重放第 21 场以前的结果也无重复额度和荣誉 |
| 一日普通 PVE 胜＋会武负＋会武胜，原始已赚 0 | 按序新增额度 10、10、0。注意额度与物品到账是两步。论剑分、4/8/12 次数、原帮会帮贡/资金均无会武附加变化 |
| 同一天只玩合条件普通 PVE 两次或只打会武两次 | 未入帮的前者也能到 20，后者有效胜负平自由组合也能到 20。直约/切磋伪装会武或重放旧终局不会加料 |
| 到跨日边界才入账或本人申请领取结果不明 | 首次应用结算日只入一次；已赚未领跨日保留；领取按既有请求和水位恢复。材料余额与帮会摘要可以独立追上 |
| 报名后退帮、成局后被踢、帮会解散再建同名帮 | 锁前失效的报名不能成局；锁后个人结果照存、额度不剥夺、新帮不继承、存续的原帮按原名单记录。已解散的帮页不可读 |
| 双方参战者及双方未参战帮友分别尝试回放 | 双方原参战者均可读自己仍保留的本局；其他帮友只能看自己本帮的授权摘要。过期、未录和无权访问按既有战报规则处理 |
| 节点掉线、回执丢失、重复投递、先见 ABORT 再见冲突结果 | 恢复原决定，零回合/作废无额度无题名。冲突留证并阻止额外副作用，不伪造对手胜利或把故障当平局 |
| 同道历练与论剑回归 | 历练仅支持原 2–5 人同帮 PVE 与原活动奖励；普通论剑原赛季规则和 Elo 沿原入口生效，两者和会武的占用均互斥 |

试玩要记录从确认到开战的实际候场时间、开战到结束的中位数和较慢局、多少场因人数不足放弃，以及赛后「还愿不愿和同一位帮友再打一场、想换哪个打法」。区内只有一支队伍的时段也纳入记录。体验结论用试玩结果回答，材料和荣誉正确性用权威账本与两版实战结果核对。
