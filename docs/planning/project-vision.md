## 一、七条不可突破的策划总红线

1. **好玩优先，绝不把核心乐趣拿去当交易税源。**
   - 设计玩法时先看玩家能做什么有意思的选择（如人物技能槽 + 装备词条/法宝 + 宝宝配合）。
   - 换流派、试新搭配必须轻快、低门槛，绝不用“高额重铸成本 / 拆装血亏”卡死玩家尝试新套路。

2. **真不肝，严禁设计成「像上班」的玩法，且防“变相多开变肝”（负责人 2026-11-26 强制强化）。**
   - **禁止一切每日打卡 / 签到 / 点一下收菜**：严禁每日签到、每日点雕像/NPC 观道致敬领高额礼、每日多次捐献打卡、日清活跃度进度条，以及任何「不打架也要每天上线点一下」的机制。
   - **禁止定时定点排班与社交催打卡**：严禁固定钟点强制同时在线活动、每日必刷 N 次强组队副本、逼迫每天清空的高额日限购，以及导致帮会管理天天催帮众捐献/打卡的资金或活跃指标。
   - **禁止“零操作收益倒挂正常游玩”与缺勤惩罚**：任何轻量点击/挂机/仪式互动的产出，绝不得高于正常核心战斗或探索游玩产出；玩家缺席几天或几周回来，不得产生“漏领血亏、进度永久追不上”的追赶焦虑。
   - **坚持“有空就玩、随时能停”**：核心进度以赛季/长期里程碑、一次性成就或宽窗自愿参与（如数日宽窗、想打才打）为主，有十分钟就打一场、离开数日回来无缝续玩。
   - 严防经济机制把玩家逼成“建十个小号轮流搬砖的苦力”：免费可交易起步额度必须**按账号终身限额**而非按角色每日无限刷新。

3. **小小氪金，免费玩家可达 100% 相同战力上限。**
   - 玩家可选择小额付费（6–30 元档）买永久外观、轻便利月卡、加快首套进度，或购买绑定「定星保底符 / 天工秘墨」缩短装备词条品相打磨与稀世绝学制书等待；免费游玩按自己节奏同样能拿满同档 +10 必成 / +11 保底装备、100% 满品相词条与全部永久技能。
   - 绝不做概率碎装、充值抽神兽、宝宝打书顶掉原技能、商城独占技能或逼氪数值通胀；任何卷宗新增永久技能中，稀世绝学占比硬锁 ≤ 10% 且永久保值。

4. **个人开发者必须稳稳赚到钱：官方 7 : 搬砖/工作室 3。**
   - 绝不把“聚宝斋 5% 玩家交易手续费”当作冷启动唯一收入底座，避免出现“工作室拿走 95%、开发者扛 100% 研发与合规风险却倒贴钱”的局面。
   - 借鉴《问道》双轨模式：**玩家/搬砖党提供时间件与基础耗材（约 30% 消费流向），官方商城直售配套功能道具、永久收藏外观、轻便利月卡与搬砖产出通行证（约 70%+ 消费流向）**。
   - 冷启动阶段优先跑通**全端合规的官方商城直售 + 游戏内银两集市**；涉及真钱提现的聚宝斋待主体资质、持牌分账通道与足够 DAU 齐备后再开放。

5. **物价必须稳得住（既防免费脚本砸盘通胀，也防毕业死市通缩）。**
   - **防砸盘（供给有真成本）**：免费零氪账号保证自用毕业，但持续产出可交易材料/银两须具备真实时间成本与月卡/实名门槛，从源头杜绝免费黑号无限多开砸穿物价。
   - **价格双锚（不上天、不归零）**：上方由官方直售绑定提速包/配套道具封顶防恶意炒作；下方由游戏内银两/重铸砂/技能/宝宝/摆摊税等真实横向消耗托底，**绝不做官方现金保底回购**。
   - **防死市与控盘**：纵向战力封顶、横向流派/多宠/外观常青；市场只展示基于真实成交的近 7 日中位参考价与样本量，监控净库存天数与大户集中度，只调未来新供给与新横向消耗，不回溯改旧资产。

6. **游戏内防骗、卖家信用与资金安全是硬门禁，不是免责声明。**
   - **游戏内当面交易防骗**：除双边后端真托管、递增条款修订、明文变更对比、禁金额缩写等技术防线外，必须堵死“免费秒到 0/1 银两当面交易把玩家诱去微信/QQ 站外被骗”的制度后门（首选仅放开低价耗材与单日小额银两互助，贵重品统一走公开集市/聚宝斋；若保留熟人当面转贵重品，则强加 7 天好友时长 + 参考价偏离拦截/冷静锁 + 官方指定买家定向单，并给小额标准品缩短公示期）。
   - **卖家信用评分系统（过户换人清空 + 异地换陌生设备直接清 0 + 防刷分）**：为游戏内集市、摆摊与聚宝斋建立类日常店铺的卖家信用评分与评价记录（仅认官方托管真实成交）；**一旦角色官方过户换人，必须强制清空历史卖家信用并显式提示“已换人重算”**；**单纯换 IP（坐高铁回家、出差、切 5G/Wi-Fi，设备未变）或同网络切换常用设备绝不扣分**，但只要**同时命中从未见过的陌生新设备 + IP 变化**（私下卖号、外地借号、盗号换机），**直接将历史成交、好评与信用分清 0**（同时保留原有违约/差评黑历史，严禁借换机洗白）；**严格防刷分**：同账号自评拒收，买卖同 IP/同设备互评不计分，且同一买家账号、同一买家 IP 或同一买家设备在 7 天窗口内对同一卖家限计有限次好评，杜绝多小号同机/同网刷五星。
   - **防“绑定染毒”手滑毁装**：可交易（T）装备默认严格隔离仅消耗 T 材料，绝不静默混扣绑定（B）材料；主动降级混用须非肌肉记忆二次强确认，并提供不洗白原材料的官方小额剥离/解封路径。
   - **真钱资金链一票否决**：未修复跨端托管引用格式冲突、未补齐逐单争议冻结与提现同账号锁裁决、未接入国内持牌分账渠道（平台收付通/直付通，杜绝二清）与买家保护锁前，真钱寄售与提现开关严禁打开。

7. **零拒审、零被迫下架是绝对红线（一票否决，负责人 2026-11-26 强制）。**
   - **严禁触碰任何商店/平台下架或拒审条款**（App Store / Google Play / 国内安卓商店 / 微信小游戏 / 抖音小游戏）：绝不在游戏客户端内置个人收款码、捐赠打赏入口、爱发电/Patreon 等外链、绕过官方支付的切支付引导，也绝不在未获国内版号前开放小游戏内购充值。
   - **广告商业化只走官方激励视频且四重零拒审兜底**：首审默认服务端关闭（`enabled = 0`）且 App 首审零广告 SDK / 零 ATT 残留；仅开放官方激励视频（禁用插屏/开屏/横幅），只发物理不可交易的**绑定银两**（防脚本刷金砸盘），未就绪时彻底隐藏入口（防苹果 2.1 空按钮），严禁任何「支持作者/捐赠/点广告」诱导文案，确认窗等权展示「观看广告领取」与「关闭」。
   - **合规三大件与隐私声明零妥协**：实名认证防沉迷（无未实名游客）、7 天冷静期真注销（含 Apple 令牌撤销）、UGC 全量内容安全审核、以及未来启用 App 广告时的 iOS ATT 真实弹窗与商店隐私问卷，缺一项即禁止提审或开开关。

## 二、后续所有子文档准入自检（写设计前必答 5 问）

任何新写或修改的玩法、经济、交易、付费文档，落盘前必须先核对这五问，任一不通过即退回重设计：

1. **普通零氪玩家（反「上班」一票否决）**：不花钱、不建小号、每天只玩 10–30 分钟甚至隔周玩，会不会因为每日签到/捐献/日限购/定时同时在线/强组队日常或“点击即领收益倒挂正常游玩”而感到卡脖子、像上班打卡、漏一天就血亏，或玩不到核心乐趣？
2. **个人开发者收入**：这份改动有没有把核心付费流向白送给脚本/工作室，而官方只剩 5% 抽成和 100% 客服/合规风险？
3. **物价与长期循环**：有没有零成本无限产出可交易货源的口子？30–60 天首套毕业后，银两和材料是持续良性消耗，还是会迅速通缩归零或被脚本砸烂？
4. **防骗与资产安全**：骗子能不能利用这个入口把小白诱导去站外私下转账，或让玩家手滑毁掉花钱买的资产？
5. **商店与平台过审/防下架安全**：这项功能、文案、入口、SDK 或付费/广告逻辑，会不会触发苹果 App Store、Google Play、国内应用商店或微信/抖音小游戏的拒审、下架、隐私冲突或广告封号？首审默认是否 100% 干净可控？

## 三、策划设计与研发 / 异机作图协作硬规（2026-11-25 增补）

所有玩法策划、设计落盘与工程接入必须同时遵守以下交付纪律：

1. **玩法全端闭环与持续扩展**：
   - 每项玩法接入完毕后，必须逐一核实该玩法相关的**全部玩法逻辑、游戏服务端（C++/Go + Java/Python 对齐状态）、客户端代码及 UI 接入**均已完成并闭环，不得遗漏 UI 接线或半成品交付。
   - 若评估该玩法确实仍有可继续扩展得**更好玩、更耐玩**且不违背「七条红线」（尤其是**禁止设计成「像上班」**）的空间，才继续扩展；**严禁硬扩展——没有实质可玩性的方向坚决不要扩展**。
2. **AI 职责硬边界（协议 / 编译 / 测试归 Gemini，Codex 只作图）**：
   - **Gemini**：负责协议生成、导表、编译、单元测试、集成/冒烟验证、压测与环境运维等除作图外的全部执行职责（高档模型用于写/改代码与分析，低档模型用于编译/生成/跑测/冒烟，见 `AGENTS.md §10`）。
   - **Codex**：**只用来作图**（新 UI 效果图、美术切图、图标、立绘与视觉精修），不再承担编码、分析、协议生成、编译、测试、压测与运维收尾。
3. **异机 Codex 新 UI / 作图交接铁律（绝不能只给 `.md`、只告诉做什么 UI、严禁定风格、与 Unity 彻底无关）**：
   - 需要让 Codex 制作新 UI 或新美术素材时，必须明确告知负责人。
   - **另一台电脑上的 Codex 拿不到任何本地仓库文件、源码或 `.md` 文档**。因此 UI / 作图交接**严禁只给一个 `.md` 文件路径**：必须先按规范落盘写入 `docs/planning/ui-handoff/<主题>.md` 留档，**随后立刻在对话回复中直接给出可直接整段复制发给 Codex 的纯功能作图信息**。
   - **输出目录固定在图仓 `D:\work\image\designs\<新专题目录>\` 且与 Unity 彻底无关（强制红线）**：新做的 UI 切图/设计一律放到图仓新建目录 `D:\work\image\designs\<专题目录>\` 下；给 Codex 的作图信息**不能和 Unity 或游戏工程有任何关系**——严禁出现 `Unity`、`uGUI`、`Prefab`、`Canvas`、`Sprite`、`spriteBorder`、`.meta`、`mmorpg-client`、`Assets/Resources/...`、C# 类/脚本名或协议/RPC 名等任何引擎或程序术语（导入 Unity 与代码接线完全由本机研发在收到图后完成；若留档 `.md` 需记录本机客户端导入映射，必须单列在文档末尾「本机研发导入备忘」，绝不放进给 Codex 的正文）。
   - **只告诉 Codex 做什么 UI，不要告诉 GPT / Codex 要定什么风格（强制红线）**：交接文档与复制给 Codex 的作图信息中，**绝对禁止**告诉 GPT / Codex 定任何美术风格、画风词、风格词、材质词、装饰画法或色号/配色（例如「道家 Q 版」「水墨」「青玉」「国风」「仙侠」「东方志怪」「宣纸」「细金边」「#244C3E」等，也不得抄旧文档或旧代码的配色词）。
   - **纯功能作图清单固定字段**：只写**要做什么 UI / 元素、界面用途与交互语义、像素尺寸（及界面显示尺寸）、文件名、透明背景（PNG-32，背景完全透明）、文字规则（默认不带文字留空给程序叠放，确需内置题字/印章字单独标明具体字样）、是否可横向/四边拉伸（含左右/上下端头留白像素）以及图仓输出目录 `D:\work\image\designs\<新专题目录>\`**。
