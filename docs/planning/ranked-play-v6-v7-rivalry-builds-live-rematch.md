# 《论剑 / 人宠会武》V6 & V7 玩法策划与全端闭环设计

> 本文为《论剑 / 人宠会武》在 V1–V5 基础上收官扩展的 V6（宿敌恩怨账本 + 问道名局抄作业）与 V7（高段擂台直播实时围观 + 1V1 战后不服再战）玩法设计事实源。
> 对应技术架构、强一致性锁序、水平扩展与防坑方案见 → [ranked-play-production-architecture.md](../design/ranked-play-production-architecture.md)。

## 1. 需求分析与策划红线核验

### 1.1 核心痛点
- **中盘（第 13–50 场）动机断层**：V1–V5 完成了段位、12 场外观里程碑、战前 15 秒明牌变阵、队内标点、连胜/终结与战中唤宠，但玩家打完 12 场后缺少两条长期驱动力：
  1. **社交情绪锚点**：同分段频繁遇到熟人却无历史记忆，赢了无「报仇雪恨」的仪式感，输了缺少立刻再打一局的切磋通道；
  2. **策略学习闭环**：底层具备 62 技能 + 赛季印 + 多宠养成深度，普通玩家战败后不知如何优化配招，高段位精彩对局也缺乏一键围观入口。

### 1.2 红线审查（一票否决）
- **零「像上班」机制**：无每日打卡、无每日观战/复仇任务条、无漏领惩罚，纯按兴致随时开打、随时围观、随时收手。
- **零刷分/零数值溢出**：宿敌「雪耻复仇」为纯荣誉印章，不改 Elo 分；1V1「不服再战」严格走非计分切磋（`MATCH_MODE_PVP_CHALLENGE`），零排位分、零材料刷单，彻底杜绝互刷上分。
- **零过审/合规风险**：无外链、无诱导文案、删角真注销自动清理全部个人排位记录并去标识化公开昵称。

## 2. V6 玩法设计：宿敌恩怨账本 + 问道名局抄作业

### 2.1 方向 A：宿敌恩怨账本（Rivalry Ledger）
1. **自动建账（单赛季维度）**：每次正式自养排位非 0 回合结算后，服务端在评分同一 SQL 事务内为对阵双方任意两名敌对玩家更新主视角交手账本 `match_ranked_rivalry(season_id, player_id, opponent_id)`（记录胜、负、平、最近结局、最近对局 ID 与展示名）。
2. **战前 15 秒明牌提示（严格脱敏）**：
   - 匹配成局冻结 `RankedMatchContext.rivalry_encounters`；
   - 战斗服在战前 15 秒变阵面板仅向本人投影敌方宿敌列表（观众与第三方清空），在敌方阵容栏旁展示轻标签：`宿敌 · <对手名> <N>胜<M>负`，若满足复仇条件（上次输给对方或历史净负 `losses > wins`）额外追加 `(可雪耻)`。
3. **战后「雪耻复仇」荣誉印**：
   - 若本局获胜且击败至少一名满足复仇条件的宿敌，结算页加盖「雪耻复仇」荣誉印章（多人局优先取历史对其负场最多、其次交手胜场最多、再次较小 `opponent_id` 确定性决胜），纯荣誉展示、不改 Elo 分。
4. **大厅档案回看**：论剑抽屉「赛季记录」页展示本季交手最多的前 8 位宿敌战绩。

### 2.2 方向 B：问道名局与一键抄作业（Featured Builds）
1. **高段热门流派自动汇聚**：
   - 正式自养排位（`!use_free_preset`）正常有效参赛终局时，战斗服在 `BattleSettlementData` 中上报玩家真实 `final_season_seal_id`、`starter_pet_table_id` 与最多 4 个去重有序 `core_skill_ids`；
   - 匹配服归一化构造 `build_key = "<seal_id>:<pet_table_id>:<sorted_csv_skills>"`，按赛季汇聚出场数、胜场、青锋及以上高段胜场，并绑定该流派最高分段胜局的代表战报 `featured_battle_id`。
2. **观摩名局（全服公开回放鉴权）**：
   - 论剑抽屉新增第 4 页签「问道名局」，展示本季 Top 5 热门流派（每页 3 张卡片 + 底部分页），支持点击「观摩名局」调用既有 `GetBattleReport` 直接回放该流派代表战报（服务端 `BattleReport` 放行 `match_ranked_featured_build.featured_battle_id` 索引命中的公开名局）。
3. **一键套用（已有即切、缺项明示）**：
   - 客户端只读比对玩家真实拥有的赛季印与灵宠栏，直接调用既有 `Season.EquipSeal` 与 `Pets.Summon` 套用已有配置，缺失的赛季印/灵宠明示差异，核心招式给出技能书参考提示，绝不越权凭空发放。

## 3. V7 玩法设计：高段擂台直播 + 1V1 战后不服再战

### 3.1 高段排位实时围观（擂台直播）
1. **开放条件**：仅正式自养排位（`MATCH_MODE_PVP_TEAM`、`!use_free_preset`）且对局最高分达到青锋及以上（`peak_rating_centi >= TierQingfengCenti`，默认 `152000`）时，成局冻结 `allow_public_spectate = true` 与 `peak_rating_centi`，建房冻结 `ESpectateVisibility = PUBLIC`。低段位、免费预设娱乐场、活动局继续 fail-closed 私密。
2. **复用既有分级观战体系（零新 RPC）**：复用既有 `ListWatchableBattles`、`WatchBattle` 与 L0/L1/L2 分级观战网关，并在 `BattleWatchSummary` 透传 `ranked_team_size` 与 `ranked_peak_rating_centi`。
3. **大厅入口**：在抽屉「问道名局」页签顶部挂载「擂台直播」横幅，支持「换一场」「刷新」「实时围观」，按分段降序展示当前激战中的高段排位局。

### 3.2 1V1 战后「不服再战」（零排位分切磋复仇）
1. **触发边界**：仅现场正常完赛的非作废正式 1V1 论剑排位（`!FromRecovery && !IsVoid && TeamSize == 1`）在结算页底部展示「不服再战」按钮（回放/补查/多人局/作废局自动隐藏）。
2. **复用既有切磋链路（零新 RPC）**：点击后优雅 `AckBattleEnd` 收起结算页，调用既有 `ChallengePlayer`，携带 `CustomDuelRules { use_free_preset=false, allow_public_spectate=true, rematch_source_battle_id=battle_id }`；服务端自动将邀请 TTL 收口至 **15 秒**，并在对手端 `BattleChallengePopup` 显示「论剑不服再战」专用标题与双剑图标；对手点「应战」时自动收起本地结算页并无缝开打。

## 4. V1–V7 玩法收口评估（不再硬扩 V8）

至此，《论剑 / 人宠会武》已完整形成 **匹配定级（V1–V2）→ 15 秒明牌变阵与禁招（V3）→ 队内标点/战后徽记/连胜破势（V4）→ 战中唤宠（V5）→ 宿敌复仇与问道名局抄作业（V6）→ 高段擂台直播与 1V1 不服再战（V7）** 的完整竞技社交闭环。当前节奏紧致、理解成本低且完全符合「有空就玩、随时能停」，不再强行堆叠 V8 系统。
