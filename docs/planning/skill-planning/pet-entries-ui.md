**先画图的执行入口**：[人物／宝宝 UI 画图交接单](D:/work/image/designs/character-pet-ui-20261117/BRIEF.md)。用户指定沿用 `D:\work\image\designs` 的道家Q版现成图，先画宝宝条目点主界面和其余页面／组件；按交接单示例数据即可开画，不等待本页新接口或公式定案。本页继续用于后续交互与真实数据接入，接口尚缺不阻止美术出图。

本文供另一台电脑制作宝宝界面。**保留原四维加点；每只宝宝改用一份统一条目点，在输出、各类障碍命中、治疗、护盾方向之间分配，替代原来的自选条目。** 这不是在旧条目之外白送一套障碍／辅助能力。人物仍走装备词条，不新增人物条目点。新宝宝条目点系统尚未实现；先复用现有宠物面板，新部分使用隔离的演示数据，正式契约提供后再接入。

## 1. 已定规则与待定参数

- 人物和宝宝均保留体质、灵力、力量、敏捷四维，不新增神识／慧心。原四维点与宝宝统一条目点是不同数据；条目点替代旧自选条目培养，不替代基础四维，也不按输出／障碍／辅助再各发一份预算。
- 人物专项词条来自人物装备；宝宝条目点属于每只宝宝自身，不继承主人装备、法宝或百分比，不制作宝宝装备栏或打造页。
- 物理伤害、法术伤害、各类障碍命中、施放治疗、护盾容量共用该宝宝同一总预算。治疗和护盾是两个分配方向，不因投其中一项就同时加强另一项；各类障碍分别分配，不做覆盖全部控制的通用命中方向。
- 总点数、每点收益／曲线、单项上限、允许投入的方向数，以及完整方向目录均待定。**不写死10点、6＋4、4槽或“1固有＋3自选”**；这些不是已确认的预算或槽位。旧候选清单中的生存、抵抗等方向也不能自动附送，若后续获准必须明确如何占用同一预算。
- 获得宝宝后的战外分配与重新分配由新契约支持，战内锁定。不做随机数值洗练、条目材料升级或专门解锁任务；点数获取／成长规则尚未定，不在UI中自行补成升级奖励或每日任务。
- 统一条目点不吞掉合法被动、追击、开场或临时技能效果，也不额外赠送这些效果。各来源分开显示，每项按适用规则结算一次。全部合法已学手动技能仍从主动攻击／障碍／辅助三分类选择，每回合合计一招。
- 某方向分配0点表示没有来自该方向的条目点加成，**不禁用合法已学技能**；投入点数也不自动学会技能、改变目标数、时长或行动次数。
- 治疗与护盾分别选择技能，过量治疗不产盾；容量加成不自动增加护罩次数、反弹或法力承伤换算。人物A40仍是人物最多7友方目标的独立主动护盾，不因此开放给宝宝。
- 小额付费只是商业化方向，暂无本页收费功能方案；不自行制作付费增点、付费扩位、重分配收费或条目商城。

### 五个阶级的展示边界

用户提出五个阶级需求；“普通 → 变异 → 灵兽 → 神兽 → 圣兽”是候选命名，不是已确认的正式枚举。五阶共用同一条目总点／单项上限，是控制强度差距的推荐边界，尚未逐项确认。不得默认高阶多点、提高单项上限，或将第五档设为付费专属。

页头可预留品阶展示位置，正式页面按服务器当前品质值显示；五阶名称、映射、获得方式及差异只能在标明“方案演示”的数据中预览，不能把现有 `PetInfo.quality` 直接解释为这五阶。详细培养状态统一引用[条目点与培养规则](pet-specialties.md)，不在本页复制维护另一份数值表。

## 2. 页面结构与入口

沿用“宝宝列表 → 当前宝宝详情”。详情保留“属性与加点”“技能”，增加“条目点”页签。宽屏可左右展示列表和详情，窄屏按列表→详情逐层进入；方向列表可滚动，不把方向硬做成固定数量插槽。

```text
宝宝详情    [宝宝名]   [等级]   [品质／品阶]   [出战状态]
[属性与加点]    [技能]    [条目点]

条目点       总额 …   已用 …   剩余 …
来源：本宝宝   调整条件：战斗外

方向             当前已分配    [详情]
物理伤害               …
法术伤害               …
某一种障碍命中         …
施放治疗               …
护盾容量               …
其余正式方向按目录排列……

[调整分配]
提示：各方向共用条目点；0点仍可使用合法已学技能。
```

总额、方向目录、分配值来自新契约；没有新契约时正式页面隐藏未支持区域或显示“功能未接入”，开发入口明确标“方案演示”。不把协议缺失当成0点，不显示猜测出的效果或免费扩容按钮。没有宝宝时沿用选择／获得宝宝的现有入口，不伪造默认宠物。

属性页仍显示四维、四维资质、气血／法力、物攻／法攻、防御、速度；成长率为既有服务器展示值，不另做可升级条。当前仅有统一防御，不伪造物防／法防两个实际值。条目点可能参与未来合法效果计算，但最终结果由服务端下发，不在已有派生面板或伤害结果上再加一遍。

## 3. 分配详情与草稿面板

### 3.1 每个分配方向应包含

| 字段 | 展示要求 |
|---|---|
| 名称与分类 | 用正式方向名；输出／障碍／辅助仅便于筛选，不是独立点池 |
| 当前已分配与草稿 | 并列显示两者及差值，例如“当前… → 草稿…”，不只显示临时总数 |
| 单项限制 | 有契约时显示该项上限、开放资格及原因；不凭经验添加上限或强制只能投两项 |
| 最终加成／下一点收益 | 只有新契约提供对应权威数据及版本、适用条件时才显示；无数据则不显示精确数字，不假设线性收益 |
| 单位与来源 | 区分百分比、百分点等；来源为“本宝宝条目点”，与原四维、被动和临时状态分开 |
| 作用范围及不覆盖项 | 明确对应伤害、具体障碍、合格治疗或容量；不自动加强其他方向或解锁技能 |
| 可用技能提示 | 提示当前合法技能中哪些适用；暂无适用技能不自动学会，也不擅自成为禁止分配条件 |

各类障碍按独立方向显示，例如封物命中、冰冻命中；是否开放以正式目录和技能规则为准。中毒命中、毒伤、劝退命中不得混作一个成功率。原候选条目名称和PE编号仅是策划引用，不能直接当作正式方向ID、技能ID或资质字段。

### 3.2 战外全量重新分配流程

1. 按稳定的 `pet_id` 绑定当前宝宝，读取权威总预算、完整分配、规则／配置版本、实例状态版本和调整可用性。不能按名字或列表位置绑定。
2. 基于完整当前分配创建本地草稿。每方向提供 `−`、`＋` 和整数输入；可以减少原先已保存的分配，再把腾出的点投入其他合法方向。这是新条目点重分配，不是旧四维加点的只增操作。
3. 同时显示当前与草稿的总额、已用、剩余；当前已分配与草稿差异始终可查看。对合法草稿，已用等于各方向投入之和，剩余等于该宝宝总额减已用；筛选或滚动不丢失隐藏方向的投入。
4. 本地校验非负整数、总投入不超过预算，以及已下发的单项上限、方向资格和允许投入方向数。负数、非整数、超额、未知方向等明确报错并禁止提交，不悄悄截断或把非法输入保存成0；服务端必须重复全部校验。不得自行要求花光所有点。
5. “恢复当前分配”仅撤销本地草稿，不操作原四维，不调用洗点。变化清单只承诺点数差；只有权威预览数据齐全才显示最终加成和技能参考效果。
6. “保存分配”提交**完整目标分配**和预期状态／配置版本，由新接口原子替换该宝宝的条目点分配。完整清单中0点及省略项的语义须由契约明确；客户端不能因筛选漏传其他已分配方向，也不能用多次逐点请求制造部分成功。
7. 在途禁止重复提交；成功后用权威完整状态覆盖当前值并结束草稿。失败保留可恢复草稿及原因；请求超时先查询实际状态，不把未知结果当作成功或盲目重放。重试不得重复扣点、生效或收费。
8. 版本冲突时拉取最新权威状态，展示旧草稿与当前的冲突，再由玩家重新确认合法草稿；不能自动覆盖另一设备的新分配。切换宝宝、返回或关闭时，对未保存草稿提供继续编辑／放弃，草稿只归属于该 `pet_id`。
9. 进入战斗立即转只读；服务端拒绝战内保存。跨入战斗的在途请求按服务端最终结果处理；未确认草稿不得进入战斗快照。

每只宝宝单独持有预算和分配，不把一只的预算借给另一只，也不自动复制配置。批量套用、自动推荐和多套条目点方案不在本轮已定范围。

### 3.3 预览与异常状态

- 无权威预览时只展示分配点数差。每方向最终加成、下一点收益，以及伤害、治疗、盾容量和障碍最终成功率都不能由名称或演示曲线推算成真实值。预览应绑定宝宝、草稿、配置与状态版本；过期结果失效。
- 参考治疗／初始盾量不等于有效回血／实际吸收；对手抵抗、免疫、目标减疗及缺血未知时，不承诺最终结果。
- 分别处理加载、无目录、无可分配方向、合法0点、没有变化、点数不足、单项／方向数超限、非法输入、战斗锁定、网络失败、版本冲突及宝宝已不存在。
- 在途切换宝宝时旧回包只能更新对应 `pet_id` 缓存；旧版本不能覆盖新状态。草稿始终按宝宝隔离，断线重连后重新校验版本，不自动提交离线草稿。
- 方向0点只显示该项没有条目点投入；仍保留基础四维和合法被动／临时效果的贡献。接口未支持与实际0点必须区分。

## 4. 与技能、战斗页面的关系

- 技能详情按来源分别列出基础技能、原四维相关属性、适用条目点、被动及临时状态；只有对应契约齐全才显示修正后数值。
- 输出、各类障碍命中、治疗、护盾共用一份条目预算，不在选好输出后再送一套完整障碍／辅助条目。0点不禁合法技能，投入点也不解锁技能。
- 条目点不新增战斗按钮或额外行动；宝宝仍从三个技能分类进入，每回合合计一招。
- 服务器解析每项适用来源一次；不能既提高攻击面板又在伤害出口重复乘同一条目点加成，也不能在旧自选条目和新点数两处重复结算。旧自选条目迁移规则须单独确定，不能未迁移就同时发放两套收益。
- 战斗详情显示开局权威快照中的分配和解析效果；合法临时状态可独立变化。战外预览、本地草稿和开窗动画不改变快照或重置次数。
- 宝宝治疗和类型护罩分别选技能。B05／B06的容量／次数／伤害类型按正式规则显示；B14法力承伤、B15蓝换血不冒充普通护盾容量。过量治疗不产盾，复活初始血量不自动吃治疗条目点。

## 5. 现有接口与必须新增的契约

以下是当前协议的静态核对结果，不代表已完成实机接入：

| 能力 | 当前已有 | 本轮接入边界 |
|---|---|---|
| 宝宝列表与详情 | `GetPetList` → `PetListInfo`，含 `PetInfo.pet_id`、四维、资质、派生属性、技能ID | 可复用；完整响应及 `PetListChangedS2C` 整体覆盖，不自行拼增量 |
| 原四维点池 | `PetInfo.total_points/remaining_points/pool_id`、`dimensions[].allocated`；持久化 `PetInstance.allocated` | 只表示原四维预算／分配，不能改名或挪用为新条目点 |
| 原四维加点／重置 | `AllocatePetPoints` 提交目标已分配值，只能增加；`ResetPetPoints` 清空原四维已分配点 | 保留旧语义；不得调用这些接口实现可增可减的新条目点重分配 |
| 自动加点 | `AutoAllocatePetPoints` 返回原四维建议目标点数 | 不是真实保存，也不是条目点分配或任意草稿的效果预览 |
| 资质、成长与品质 | `dimensions[].aptitude`、`growth`、`quality` | 不塞进条目点分配；当前品质不等于候选五阶映射 |
| 宝宝技能 | `PetInfo.skill_table_ids`、实例技能ID列表 | 不把分配方向伪装为技能ID；保留原技能及合法被动语义 |
| 新条目点 | 当前 `PetInfo`、`PetInstance` 未提供本轮独立预算／完整方向分配／曲线／并发版本契约 | 需要新配置、持久化、协议及战斗快照；目前只做隔离演示 |
| 新条目点预览 | 当前无该草稿的权威最终加成、下一点收益或技能效果预览 | 待新契约；不能先真实保存再回滚来假装预览 |

核对入口：[宝宝协议](../../../proto/scene/player_pet.proto)、[宝宝持久化组件](../../../proto/common/component/player_pet_comp.proto)、[既有宝宝系统](../../design/player-pet.md)。现有宠物写操作成功后的 `PetListInfo` 及列表通知仍整体替换；新接口响应究竟是完整单宠状态还是完整列表，须由新契约明确后按其语义更新，不能自行猜测为增量。

以下只是后续契约应承载的语义，不是已存在的字段名或RPC：

| 契约部分 | 必需内容 |
|---|---|
| 方向与规则目录 | 稳定方向ID、名称、分类、单位、适用范围、开放资格、已确定的单项上限和允许方向数、规则／配置版本；收益曲线及计算由服务端持有 |
| 单只宝宝状态 | `pet_id`、独立条目总额、完整已分配值、已用／剩余或一致的计算依据、调整可用性及原因、实例状态版本；与原四维池明确隔离 |
| 整体保存 | 宝宝身份、完整目标分配、预期状态／配置版本及重试标识；校验归属、非负整数、合法方向、总额、单项／方向数限制和战斗锁定后原子保存 |
| 成功与失败 | 成功返回权威完整状态和新版本；失败说明冲突、预算或资格变化等原因；重试不重复生效，不隐式收费 |
| 可选的权威预览 | 每方向最终加成／下一点收益、来源贡献、适用范围及技能参考效果；绑定完整草稿、实例与配置版本和计算条件。缺项不展示精确数字 |
| 战斗快照 | 该宝宝已保存的分配及解析结果、来源身份、配置版本；不混入未保存草稿、旧自选条目重复收益或主人装备聚合值 |
| 迁移与品阶 | 原自选条目若已有资产，需明确替代迁移；五阶映射、点数来源及品阶是否影响预算等另行定案，不能由UI补规则 |

人物装备、宝宝条目点、原四维、被动及状态可以共用底层效果描述，但主体、来源、预算、存档与入口分开。没有新契约时只能演示布局、草稿和状态，不得将本地演示保存称为真实账号培养。

## 6. 制作顺序与验收清单

先复用真实宝宝列表、原四维与技能页，再做条目点总览、方向详情、全量草稿和异常状态的隔离演示，正式契约接入后才验证保存、重登及战斗效果。复用原字体、按钮、弹窗和返回栈；用容器／锚点适配窗口与安全区，长中文换行、方向列表滚动、键盘／手柄焦点可达。数据到达、草稿变化、选择宝宝、战斗状态变化通过事件更新UI，不每帧轮询或重算整页。

| 验收项目 | 预期 |
|---|---|
| 来源与替代关系 | 原四维未增加；统一条目点替代旧自选条目，输出／障碍／治疗／盾共享预算；人物不新增条目点，主人装备不复制给宝宝 |
| 动态规则 | 用不同演示总额、单项上限及方向数量验证布局，不硬写10点、6＋4或固定槽位；五阶与付费差异保持候选状态 |
| 全量重分配 | 能减少当前已保存投入再重新分配；显示总额／已用／剩余和各项当前／草稿差异，筛选不会丢方向；合法状态整体保存 |
| 非法输入 | 负数、非整数、超预算、超单项上限、超允许方向数、未知ID均明确阻止；前端与服务器均校验 |
| 版本与重试 | 两设备修改、规则变更、过期预览、重复提交及超时均覆盖；版本冲突不自动覆盖，不能部分保存或重复应用 |
| 宝宝切换 | 同名不同ID不串配置；迟到回包不覆盖另一只或较新状态；未保存草稿有离开处理 |
| 战斗锁定 | 入战前后和请求在途均处理；只以权威确认状态建快照，草稿不入战 |
