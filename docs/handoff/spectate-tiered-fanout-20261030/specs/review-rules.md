# 语义评审共用规则

只读：不改任何文件，不跑构建 / 测试，不做 git 写操作，不把文件导出到临时目录。只读的 git diff / git log 可以用（基线 HEAD 见 `git log -1`；工作区混有其他会话的改动，只评审本任务相关部分）。
只查**编译查不出的问题**：并发与重入、对象 / 定时器 / 连接生命周期（AGENTS §11.7 weak 绑定）、协议语义与两端对齐、顺序与去重、丢帧后能否自愈、幂等与重放、失败路径（fail-closed、半截状态）、资源泄漏与无界增长、热路径阻塞、指标标签高基数、测试是否真能覆盖声称的行为。不查语法、类型、include 能否编过（Codex 会编）。
每条发现必须核实过代码：给 文件:行号、触发序列（具体到谁先谁后）、错误后果、最小修法。不确定的不报。按严重度排序（阻断 / 严重 / 一般）。没有问题就说没有。
结果写到任务指定的文件，最终回复只要发现条数与一句话结论。
